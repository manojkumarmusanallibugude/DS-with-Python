# Heap — Custom Implementation as a Class in Python

---

## 1. Introduction

The CEO has been using Python's `heapq` module to manage the company's task priority desk — and it works. But one day the CTO walks in and asks a sharp question:

*"You rely on `heapq` to always give you the most urgent task. But do you actually understand what it does inside? If `heapq` disappeared tomorrow, could you rebuild it from scratch?"*

The CEO pauses. Using a tool is not the same as understanding it.

This is the gap between a **user** and an **engineer**.

`heapq` is a convenience wrapper — it hides the mechanics. A custom Heap class forces you to understand every single decision: how a new task finds its correct position, how extracting the most urgent task reorganises everything below it, and why the whole structure never breaks even after thousands of insertions and deletions.

Before we build, let us be honest about why simpler structures failed this problem — and why even `heapq` is not enough when you need custom behaviour.

**Array / Python List** with manual sorting: every new task insertion costs O(n) to find the right position and shift everything after it. Five hundred tasks? Every hire reshuffles hundreds of entries. Fine for ten tasks, unacceptable for production.

**Stack** is last in, first out. It has no concept of urgency. A routine weekly standup pushed last comes out before a critical outage pushed first. Structurally wrong.

**Queue** is first in, first out. Arrival time is not urgency. The oldest task is not necessarily the most critical one. Structurally wrong.

**Singly Linked List** maintained in sorted order: insertion costs O(n) to find the right position by walking the chain. Extracting the head (most urgent) costs O(1) — but insertion is the bottleneck. For a task desk receiving hundreds of items per minute, O(n) insertion is too slow.

**`heapq` module**: correct and fast, but it is a collection of functions that operate on a plain list. You cannot add custom behaviour — a maximum size limit, automatic task expiry, logging every insertion, or support for custom priority objects — without wrapping it in a class anyway. And when you wrap it, you are building exactly what this chapter teaches.

**The custom Heap class** gives you O(log n) insertion and extraction, guaranteed heap property at every moment, and complete control over behaviour — because you own every line of it.

## 2. What the Custom Class Must Do

Before writing a single line, let us state precisely what the CEO's custom task desk must be able to do:

```
Task Desk Operations
──────────────────────────────────────────────────────
push(item)        Add a new task — place it correctly
pop()             Remove and return the most urgent task
peek()            See the most urgent task without removing it
size()            How many tasks are currently on the desk
is_empty()        Is the desk clear?
display()         Show the entire heap as a tree diagram
```

Every one of these maps to a method in the class. Every method maintains one invariant: **the heap property must hold before and after every operation.**

---

## 3. Key Terminology

| Term | Meaning |
|------|---------|
| **Heap Property** | In a Min-Heap: every parent ≤ both children. In a Max-Heap: every parent ≥ both children. |
| **Complete Binary Tree** | Every level is fully filled left to right — no gaps. Guarantees height = O(log n). |
| **Heapify Up** | After inserting a new element at the end, bubble it upward until the heap property is restored. |
| **Heapify Down** | After removing the root, move the replacement element downward until the heap property is restored. |
| **Parent Index** | For a node at index `i`, its parent is at index `(i - 1) // 2`. |
| **Left Child Index** | For a node at index `i`, its left child is at index `2*i + 1`. |
| **Right Child Index** | For a node at index `i`, its right child is at index `2*i + 2`. |
| **Internal List** | The heap is stored as a flat Python list — the tree shape is implied by index arithmetic. |

---

## 4. The Heap as a Flat List

This is the most important insight in this entire chapter.

A heap is a binary tree — but it is **never stored as a tree with Node objects and pointers**. It is stored as a **flat Python list**, and the tree shape is derived purely from index arithmetic.

Why? Because the heap is a *complete* binary tree — no gaps, always filled left to right. This regularity means every parent-child relationship can be computed mathematically, with no need for explicit pointers.

```
Tree shape:                    List representation:
                                index: 0   1   2   3   4
        [ 1 ]                          [1,  3,  5,  7,  9]
       /     \
    [ 3 ]   [ 5 ]
    /    \
 [ 7 ]  [ 9 ]

Index arithmetic:
  Parent of index 1 (value 3)  → (1-1)//2 = 0  → index 0 (value 1)  ✓
  Parent of index 3 (value 7)  → (3-1)//2 = 1  → index 1 (value 3)  ✓
  Left child of index 1 (3)    → 2*1+1 = 3     → index 3 (value 7)  ✓
  Right child of index 1 (3)   → 2*1+2 = 4     → index 4 (value 9)  ✓
```

This is why the CEO's task desk can be a simple list under the hood. No Node class. No pointers. Just a list and three index formulas.

## 5. The MinHeap Class — Skeleton

```python
class MinHeap:
    def __init__(self):
        self._heap = []              # Internal flat list — the actual storage

    def _parent(self, i):
        return (i - 1) // 2         # Parent of node at index i

    def _left(self, i):
        return 2 * i + 1            # Left child of node at index i

    def _right(self, i):
        return 2 * i + 2            # Right child of node at index i

    def size(self):
        return len(self._heap)

    def is_empty(self):
        return len(self._heap) == 0

    def peek(self):
        if self.is_empty():
            raise IndexError("Task desk is empty — no urgent task to show.")
        return self._heap[0]         # Root is always the minimum
```

Why `_heap` with an underscore? In Python, a single leading underscore signals that this attribute is **internal** — callers should use `push()`, `pop()`, and `peek()` rather than touching the list directly. Direct modification would silently break the heap property.

## 6. Push — Adding a New Task

### 6.1 The Logic

When a new task arrives on the CEO's desk, it cannot simply be appended to the end and forgotten. It must find its correct position — the position where the heap property is satisfied.

The strategy:

1. Append the new element at the **end** of the list (the next available position in the complete binary tree)
2. **Bubble it upward** — compare it with its parent; if it is smaller (higher priority), swap them
3. Repeat until the element is either at the root or its parent is already smaller

This upward movement is called **Heapify Up** or **Sift Up**.

**Analogy:** A new employee joins the company at the lowest level. But if their urgency score is higher than their manager's, they swap positions. They keep swapping upward until they find a manager who genuinely outranks them — or until they reach the CEO position.

### 6.2 Index Arithmetic — Why `(i - 1) // 2`

```
      index 0
     /        \
  index 1    index 2
  /    \      /    \
index3 index4 index5 index6
```

Node at index `3`: parent is at `(3-1)//2 = 1` ✓
Node at index `4`: parent is at `(4-1)//2 = 1` ✓
Node at index `5`: parent is at `(5-1)//2 = 2` ✓
Node at index `6`: parent is at `(6-1)//2 = 2` ✓

Integer division handles both left and right children correctly — no special cases needed.

### 6.3 Code

```python
def push(self, item):
    self._heap.append(item)          # Step 1: Place at the end
    self._heapify_up(len(self._heap) - 1)   # Step 2: Bubble upward

def _heapify_up(self, i):
    while i > 0:                     # Stop when we reach the root
        parent = self._parent(i)
        if self._heap[i] < self._heap[parent]:   # Child is smaller than parent
            self._heap[i], self._heap[parent] = self._heap[parent], self._heap[i]
            i = parent               # Move up and check again
        else:
            break                    # Heap property satisfied — stop
```

## 7. Pop — CEO Completes the Most Urgent Task

### 7.1 The Logic

The CEO finishes the most urgent task (the root). The root slot is now empty. The heap must reorganise so the next most urgent task rises to the top.

Naively moving the second smallest element to the root does not work — you would need to search for the second smallest, which defeats the purpose.

The correct strategy:

1. **Save** the root (the answer to return)
2. **Move the last element** in the list to the root position
3. **Remove** the last element (now duplicated at root)
4. **Bubble the new root downward** — compare it with its children; swap with the smaller child if needed
5. Repeat until the element is either at a leaf or both children are larger

This downward movement is called **Heapify Down** or **Sift Down**.

**Analogy:** The CEO completes the most urgent task and steps down. The last-hired junior employee (last in the list) temporarily takes the CEO chair. Everyone looks at them and says, *"You do not belong here — your urgency score is too low."* They swap with the more urgent of their two direct reports. That process repeats until they settle at the level they actually deserve.

### 7.2 Code

```python
def pop(self):
    if self.is_empty():
        raise IndexError("Task desk is empty — no task to complete.")

    if self.size() == 1:
        return self._heap.pop()      # Only one element — just remove it

    root = self._heap[0]             # Save the most urgent task
    self._heap[0] = self._heap.pop() # Move last element to root
    self._heapify_down(0)            # Restore heap property downward
    return root

def _heapify_down(self, i):
    size = len(self._heap)

    while True:
        smallest = i                 # Assume current node is smallest
        left  = self._left(i)
        right = self._right(i)

        # Check if left child exists and is smaller
        if left < size and self._heap[left] < self._heap[smallest]:
            smallest = left

        # Check if right child exists and is even smaller
        if right < size and self._heap[right] < self._heap[smallest]:
            smallest = right

        if smallest != i:
            # Swap current with the smallest child
            self._heap[i], self._heap[smallest] = self._heap[smallest], self._heap[i]
            i = smallest             # Move down and check again
        else:
            break                    # Heap property satisfied — stop
```

## 8. Display — Visualising the Heap as a Tree

A flat list is hard to read. A good `display` method prints the heap in tree form, level by level — so the CEO can see exactly what their task desk looks like at any moment.

```python
def display(self):
    if self.is_empty():
        print("  (Task desk is empty)")
        return

    print(f"\n  Heap (size={self.size()}):")
    level_start = 0
    level_size  = 1

    while level_start < self.size():
        level_end  = min(level_start + level_size, self.size())
        level_nodes = self._heap[level_start:level_end]
        print("  " + "   ".join(str(node) for node in level_nodes))
        level_start = level_end
        level_size *= 2              # Each level has double the nodes
    print()
```

## 9. The Complete MinHeap Class

```python
class MinHeap:
    """
    Custom Min-Heap implementation.
    The smallest element is always at the root.
    Used as the CEO's task priority desk — most urgent task always on top.
    """

    def __init__(self):
        self._heap = []

    # ── Index Helpers ──────────────────────────────────────────
    def _parent(self, i):
        return (i - 1) // 2

    def _left(self, i):
        return 2 * i + 1

    def _right(self, i):
        return 2 * i + 2

    # ── Core Queries ───────────────────────────────────────────
    def size(self):
        return len(self._heap)

    def is_empty(self):
        return len(self._heap) == 0

    def peek(self):
        if self.is_empty():
            raise IndexError("Task desk is empty.")
        return self._heap[0]

    # ── Internal Heapify Operations ────────────────────────────
    def _heapify_up(self, i):
        while i > 0:
            parent = self._parent(i)
            if self._heap[i] < self._heap[parent]:
                self._heap[i], self._heap[parent] = self._heap[parent], self._heap[i]
                i = parent
            else:
                break

    def _heapify_down(self, i):
        size = len(self._heap)
        while True:
            smallest = i
            left     = self._left(i)
            right    = self._right(i)

            if left < size and self._heap[left] < self._heap[smallest]:
                smallest = left
            if right < size and self._heap[right] < self._heap[smallest]:
                smallest = right

            if smallest != i:
                self._heap[i], self._heap[smallest] = self._heap[smallest], self._heap[i]
                i = smallest
            else:
                break

    # ── Push ───────────────────────────────────────────────────
    def push(self, item):
        self._heap.append(item)
        self._heapify_up(len(self._heap) - 1)

    # ── Pop ────────────────────────────────────────────────────
    def pop(self):
        if self.is_empty():
            raise IndexError("Task desk is empty — nothing to complete.")
        if self.size() == 1:
            return self._heap.pop()
        root             = self._heap[0]
        self._heap[0]    = self._heap.pop()
        self._heapify_down(0)
        return root

    # ── Display ────────────────────────────────────────────────
    def display(self):
        if self.is_empty():
            print("  (Task desk is empty)")
            return
        print(f"\n  Heap (size={self.size()}):")
        level_start = 0
        level_size  = 1
        while level_start < self.size():
            level_end   = min(level_start + level_size, self.size())
            level_nodes = self._heap[level_start:level_end]
            print("  " + "   ".join(str(node) for node in level_nodes))
            level_start = level_end
            level_size *= 2
        print()

    def __repr__(self):
        return f"MinHeap({self._heap})"
```

## 10. The MaxHeap Class

The MaxHeap is identical to the MinHeap in structure — only the comparison direction flips. The largest element sits at the root. Every parent is **greater than or equal to** both its children.

**CEO use case:** salary review desk — highest-paid employee is reviewed first.

```python
class MaxHeap:
    """
    Custom Max-Heap implementation.
    The largest element is always at the root.
    Used as the CEO's salary review desk — highest salary always on top.
    """

    def __init__(self):
        self._heap = []

    def _parent(self, i):
        return (i - 1) // 2

    def _left(self, i):
        return 2 * i + 1

    def _right(self, i):
        return 2 * i + 2

    def size(self):
        return len(self._heap)

    def is_empty(self):
        return len(self._heap) == 0

    def peek(self):
        if self.is_empty():
            raise IndexError("Salary desk is empty.")
        return self._heap[0]

    def _heapify_up(self, i):
        while i > 0:
            parent = self._parent(i)
            if self._heap[i] > self._heap[parent]:   # ← ONLY change from MinHeap
                self._heap[i], self._heap[parent] = self._heap[parent], self._heap[i]
                i = parent
            else:
                break

    def _heapify_down(self, i):
        size = len(self._heap)
        while True:
            largest = i              # ← ONLY change from MinHeap
            left    = self._left(i)
            right   = self._right(i)

            if left < size and self._heap[left] > self._heap[largest]:
                largest = left
            if right < size and self._heap[right] > self._heap[largest]:
                largest = right

            if largest != i:
                self._heap[i], self._heap[largest] = self._heap[largest], self._heap[i]
                i = largest
            else:
                break

    def push(self, item):
        self._heap.append(item)
        self._heapify_up(len(self._heap) - 1)

    def pop(self):
        if self.is_empty():
            raise IndexError("Salary desk is empty — nothing to review.")
        if self.size() == 1:
            return self._heap.pop()
        root          = self._heap[0]
        self._heap[0] = self._heap.pop()
        self._heapify_down(0)
        return root

    def display(self):
        if self.is_empty():
            print("  (Salary desk is empty)")
            return
        print(f"\n  MaxHeap (size={self.size()}):")
        level_start = 0
        level_size  = 1
        while level_start < self.size():
            level_end   = min(level_start + level_size, self.size())
            level_nodes = self._heap[level_start:level_end]
            print("  " + "   ".join(str(node) for node in level_nodes))
            level_start = level_end
            level_size *= 2
        print()

    def __repr__(self):
        return f"MaxHeap({self._heap})"
```

**The only two lines that differ between MinHeap and MaxHeap:**

```
MinHeap _heapify_up:   if self._heap[i] < self._heap[parent]   → bubbles smaller up
MaxHeap _heapify_up:   if self._heap[i] > self._heap[parent]   → bubbles larger up

MinHeap _heapify_down: tracks smallest child                    → swaps with smaller
MaxHeap _heapify_down: tracks largest child                     → swaps with larger
```

## 13. Time and Space Complexity

| Operation | Time | Why |
|-----------|------|-----|
| `push` | O(log n) | Heapify up — at most log n swaps upward |
| `pop` | O(log n) | Heapify down — at most log n swaps downward |
| `peek` | O(1) | Root is always index 0 |
| `size` | O(1) | `len()` on a list |
| `is_empty` | O(1) | `len()` on a list |
| `display` | O(n) | Prints every element once |
| **Space** | O(n) | One list slot per element, no pointers |

The height of a complete binary tree with `n` nodes is always `⌊log₂ n⌋`. That is why every push and pop is bounded by log n swaps — there are at most log n levels to traverse.

## 14. Custom Class vs `heapq` — When to Use Which

| Scenario | Use |
|----------|-----|
| Quick script, no custom logic needed | `heapq` |
| Need a maximum size limit | Custom class |
| Need to log every insertion and pop | Custom class |
| Need to support complex priority objects | Custom class |
| Building a library or API for others to use | Custom class |
| Learning how a heap actually works | **Custom class — always** |
| Competitive programming, speed matters | `heapq` |

The custom class and `heapq` have identical time complexity. The difference is entirely about **control and clarity**. `heapq` functions operate on a naked list — one accidental direct append and the heap property silently breaks. A class encapsulates the list and exposes only the safe methods.

## 15. Common Mistakes

**Mistake 1 — Wrong parent index formula**

```python
# Wrong — off-by-one error
def _parent(self, i):
    return i // 2          # Fails for i=1: gives 0, but (1-1)//2 = 0 is correct by accident
                           # Fails for i=2: gives 1, but correct is (2-1)//2 = 0

# Correct
def _parent(self, i):
    return (i - 1) // 2   # Always correct for 0-indexed heap
```

**Mistake 2 — Heapify down compares with wrong child**

```python
# Wrong — always swaps with left child without checking right
if self._heap[left] < self._heap[i]:
    swap(i, left)

# Correct — always swap with the SMALLER of the two children
smallest = i
if left < size  and self._heap[left]  < self._heap[smallest]: smallest = left
if right < size and self._heap[right] < self._heap[smallest]: smallest = right
if smallest != i: swap(i, smallest)
```

Swapping with the larger child in a Min-Heap would move a bigger value upward — breaking the heap property for the child you did not swap with.

**Mistake 3 — Accessing `_heap` directly from outside the class**

```python
task_desk._heap.append((2, "New task"))   # Silently breaks heap property
task_desk.push((2, "New task"))           # Correct — triggers heapify_up
```

**Mistake 4 — Not handling the single-element pop case**

```python
# Without this check, pop() moves heap[-1] to position 0
# then calls heapify_down — but the list is now empty and it crashes
if self.size() == 1:
    return self._heap.pop()
```

## 17. Summary

| Concept | Meaning |
|---------|---------|
| Flat list storage | Heap stored as a list — no Node objects, no pointers |
| `_parent(i)` | `(i - 1) // 2` — works for any index in a 0-based list |
| `_left(i)` | `2*i + 1` |
| `_right(i)` | `2*i + 2` |
| `_heapify_up` | After push — bubble new element up until heap property holds |
| `_heapify_down` | After pop — sink replacement element down until heap property holds |
| MinHeap comparison | `<` in heapify up, swap with smallest child in heapify down |
| MaxHeap comparison | `>` in heapify up, swap with largest child in heapify down |
| `peek()` | `self._heap[0]` — O(1), never modifies the heap |
| `push()` | Append + heapify up — O(log n) |
| `pop()` | Save root, move last to root, heapify down — O(log n) |
| Leading underscore `_heap` | Internal attribute — do not access directly |

The custom Heap class is not a replacement for `heapq` — it is the explanation of it. Every line of `heapq`'s source code is doing exactly what this class does. Once you have written `_heapify_up` and `_heapify_down` by hand, you will never be confused by a heap problem again.
