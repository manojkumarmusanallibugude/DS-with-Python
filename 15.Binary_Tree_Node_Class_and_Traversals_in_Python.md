# Binary Tree — Node Class and Traversals in Python

---

## 1. Introduction

Picture a company's organisational chart.

At the top sits the **CEO**. Under the CEO are two Vice Presidents — one for Engineering, one for Sales. Under Engineering are two Directors. Under Sales are two more. Every person reports to exactly one boss, but a boss can have multiple people reporting to them.

```
                        [ CEO ]
                       /       \
              [ VP Engg ]     [ VP Sales ]
              /        \       /         \
        [ Dir A ]  [ Dir B ] [ Mgr C ] [ Mgr D ]
```

Now answer this: *Can you represent that company's hierarchy in a simple list?*

You could try — but you'd need a mess of indices, parent pointers, and special cases. A flat list was not designed for hierarchy. A flat list is a road. What you need is a **tree**.

The **Binary Tree** is the simplest form of a tree structure where every node has **at most two children** — a left child and a right child. That "at most two" constraint turns out to be extraordinarily powerful. Almost every efficient searching, sorting, and indexing mechanism in computer science is rooted (pun intended) in a binary tree.

---

## 2. Real-World Applications

In our company, every employee is a **node**. Every reporting line is a **pointer**. The CEO is the **root**. Employees with no reportees are **leaves**.

Now extend that thinking outward:

**Company Directory Search**

The HR system needs to find any employee by name instantly — out of 50,000 employees. It does not scan every record. It uses a **Binary Search Tree** where names are arranged alphabetically: left means the name comes before, right means it comes after. Found in just 16 comparisons.

**Expression Evaluation in a Calculator**

The expression `(3 + 4) × (2 − 1)` can be drawn as a tree:

```
        ×
       / \
      +   −
     / \ / \
    3  4 2  1
```

A compiler or calculator evaluates this tree to compute the answer. This is called an **Expression Tree**, and every calculator, spreadsheet, and compiler uses it internally.

**File Compression (Huffman Coding)**

When you zip a file, the algorithm builds a binary tree where frequent characters get short codes and rare characters get long codes. Your `.zip`, `.mp3`, and `.jpg` files all use trees.

**Decision Making in AI**

Every performance review system that asks yes/no questions — *"Did the employee meet targets? → Yes → Did they lead a project?"* — is a binary tree. Every spam filter, every medical diagnosis AI works the same way.

---

## 3. Key Terminology

Before writing code, you must speak the language. These terms will follow you throughout your career.

```
                        [ CEO ]            ← Root (Level 0)
                       /       \
              [ VP Engg ]     [ VP Sales ] ← Internal Nodes (Level 1)
              /        \
        [ Dir A ]  [ Dir B ]               ← Leaf Nodes (Level 2)
```

| Term | Meaning |
|------|---------|
| **Root** | The topmost node. Every tree has exactly one root. The CEO — reports to nobody. |
| **Parent** | A node that has children below it. VP Engineering is parent of Dir A and Dir B. |
| **Child** | A node directly below a parent. Left child or right child. |
| **Leaf** | A node with NO children. Junior employees with no reportees. |
| **Height** | The number of edges from root to the deepest leaf. |
| **Depth** | The number of edges from root to a specific node. |
| **Subtree** | Any node and all its descendants — itself a valid tree. VP Engineering and all below him is a subtree. |
| **Level** | Root is at Level 0. Its children are Level 1, and so on. |

## 4. The Node Structure

If you have already understood the Node in a Linked List, this will feel familiar. The only difference is that instead of one `next` pointer, a binary tree node has **two** pointers: `left` and `right`.

```
     ┌─────────────────────────────┐
     │        "CEO"                │  ← data  (employee name / designation)
     ├──────────────┬──────────────┤
     │  left ──────►│  right ─────►│  ← pointers to left and right child nodes
     └──────────────┴──────────────┘
           │                │
     [ VP Engg ]       [ VP Sales ]
```

In a linked list, a node says: *"I know who comes after me."*
In a binary tree, a node says: *"I know who reports to me on the left and who reports to me on the right."*

## 5. Implementation

### 5.1 The Node Class

```python
class Node:
    def __init__(self, data):
        self.data = data       # Employee name or designation
        self.left = None       # Left child (default: no reportee)
        self.right = None      # Right child (default: no reportee)

    def __repr__(self):
        return f"Node({self.data})"
```

Why `self.left = None` and `self.right = None`?

Because when a node is first created, it has no reportees yet. `None` means *"no one reporting here."* As you build the org chart, you assign actual Node objects to these pointers.

### 5.2 Creating Individual Nodes

```python
ceo      = Node("CEO")
vp_engg  = Node("VP Engg")
vp_sales = Node("VP Sales")
dir_a    = Node("Dir A")
dir_b    = Node("Dir B")
```

Right now, these are five isolated boxes floating in memory. Each person knows their own designation, but none knows about the others.

### 5.3 Connecting Nodes into an Org Chart

```python
ceo.left      = vp_engg      # CEO's left reportee is VP Engineering
ceo.right     = vp_sales     # CEO's right reportee is VP Sales
vp_engg.left  = dir_a        # VP Engg's left reportee is Director A
vp_engg.right = dir_b        # VP Engg's right reportee is Director B
```

In memory, we have now built this org chart:

```
               [ CEO ]
              /        \
       [ VP Engg ]   [ VP Sales ]
       /         \
  [ Dir A ]   [ Dir B ]
```

`VP Sales`, `Dir A`, and `Dir B` are **leaves** — they have no one reporting to them.
`CEO` and `VP Engg` are **internal nodes**.

### 5.4 The BinaryTree Wrapper Class

Rather than managing the root separately, we wrap the tree in its own class:

```python
class BinaryTree:
    def __init__(self, root_data):
        self.root = Node(root_data)    # Every org chart starts with the CEO
```

Now you can do:

```python
tree = BinaryTree("CEO")
tree.root.left        = Node("VP Engg")
tree.root.right       = Node("VP Sales")
tree.root.left.left   = Node("Dir A")
tree.root.left.right  = Node("Dir B")
```

## 6. Tree Traversals

Here is the central question: *If HR wants to visit every employee in the org chart, in what order do they do it?*

In a list, the answer is obvious — start from the first employee, move to the last. But an org chart has **branching paths**. There is no single "beginning to end."

Computer scientists identified four fundamental strategies, each with a different real-world purpose. The first three are named based on **when you visit the root (CEO)** relative to the rest.

---

### 6.1 Inorder Traversal — Left → Root → Right

**Rule:** First visit the entire left subtree. Then visit the root. Then visit the right subtree.

**The Magical Property:** For a Binary Search Tree of employee names, Inorder traversal always gives you employees in **alphabetical order**. This is why it is called "in-order" — it visits nodes in their natural sorted sequence.

**Analogy:** An auditor visits every employee in the left department first, then meets the department head, then moves to the right department. Every sub-department is audited before its head signs off.

```python
def inorder(node):
    if node is None:
        return
    inorder(node.left)     # 1. Visit entire left subtree first
    print(node.data)       # 2. Visit this node (employee)
    inorder(node.right)    # 3. Visit entire right subtree
```

**Trace on our org chart:**

- Visit `CEO` → go left to `VP Engg` → go left to `Dir A` → `Dir A` has no left → **print Dir A** → `Dir A` has no right
- Back to `VP Engg` → **print VP Engg** → go right to `Dir B` → **print Dir B**
- Back to `CEO` → **print CEO** → go right to `VP Sales` → **print VP Sales**

Output: `Dir A  VP Engg  Dir B  CEO  VP Sales`

---

### 6.2 Preorder Traversal — Root → Left → Right

**Rule:** Visit the root first. Then visit the left subtree. Then visit the right subtree.

**Analogy:** The CEO introduces himself first in the all-hands meeting, then hands over to VP Engineering (who introduces his team), then VP Sales does the same. Every boss speaks before their team does.

**Primary Use:** Copying an org chart, serialising a tree to store it in a file or database, printing a folder structure.

```python
def preorder(node):
    if node is None:
        return
    print(node.data)       # 1. Visit this employee FIRST
    preorder(node.left)    # 2. Then visit their left reportees
    preorder(node.right)   # 3. Then visit their right reportees
```

**Trace on our org chart:**

- Visit root → **print CEO** → go left
- Visit `VP Engg` → **print VP Engg** → go left
- Visit `Dir A` → **print Dir A** → no reportees, go back
- Back to `VP Engg` → go right → **print Dir B** → no reportees, go back
- Back to `CEO` → go right → **print VP Sales**

Output: `CEO  VP Engg  Dir A  Dir B  VP Sales`

Notice: The CEO always comes out first. This makes preorder ideal for **reconstructing** an org chart — you always know who the root is.

---

### 6.3 Postorder Traversal — Left → Right → Root

**Rule:** Visit the left subtree. Then the right subtree. Visit the root last.

**Analogy:** During company-wide performance appraisal, every junior employee is evaluated before their manager. A manager's score is computed only after all their reportees are evaluated. The CEO's appraisal is done last — only after every single employee in the company has been assessed.

**Primary Use:** Deleting an org chart (remove all juniors before the boss), evaluating expression trees, calculating department-wise total salary (sum juniors before reporting manager's total).

```python
def postorder(node):
    if node is None:
        return
    postorder(node.left)    # 1. Evaluate entire left subtree first
    postorder(node.right)   # 2. Evaluate entire right subtree
    print(node.data)        # 3. Visit this employee LAST
```

**Trace on our org chart:**

- Go left all the way → `Dir A` is a leaf → **print Dir A**
- Back to `VP Engg` → go right → `Dir B` is a leaf → **print Dir B**
- Back to `VP Engg` → **print VP Engg**
- Back to `CEO` → go right → `VP Sales` is a leaf → **print VP Sales**
- Back to `CEO` → **print CEO**

Output: `Dir A  Dir B  VP Engg  VP Sales  CEO`

Notice: The CEO always comes out last in postorder.

---

### 6.4 Level Order Traversal — Breadth First

**Rule:** Visit all employees at Level 0 (CEO), then all at Level 1, then Level 2, and so on.

**Analogy:** A company-wide announcement is sent floor by floor. The CEO announces first (Level 0). The announcement then reaches both VPs simultaneously (Level 1). Then all Directors and Managers receive it (Level 2). This wave-like, level-by-level spread is exactly Level Order traversal.

```
Level 0:              [ CEO ]
Level 1:       [ VP Engg ]  [ VP Sales ]
Level 2:   [ Dir A ] [ Dir B ]
```

**Primary Use:** Finding the shortest reporting chain between two employees, org-chart rendering, BFS-based problems.

This traversal requires a **Queue** because you need to process employees in the order they are discovered — first in, first out, just like a queue at the HR desk.

```python
from collections import deque

def level_order(root):
    if root is None:
        return

    queue = deque()
    queue.append(root)           # Start: CEO enters the queue

    while queue:
        node = queue.popleft()   # Call the first person in the queue
        print(node.data)         # Process this employee

        if node.left:            # Enqueue left reportee if exists
            queue.append(node.left)
        if node.right:           # Enqueue right reportee if exists
            queue.append(node.right)
```

**Trace on our org chart:**

- Queue: `[CEO]` → pop `CEO`, print `CEO`, enqueue `VP Engg` and `VP Sales`
- Queue: `[VP Engg, VP Sales]` → pop `VP Engg`, print `VP Engg`, enqueue `Dir A` and `Dir B`
- Queue: `[VP Sales, Dir A, Dir B]` → pop `VP Sales`, print `VP Sales`, no reportees
- Queue: `[Dir A, Dir B]` → pop `Dir A`, print `Dir A`, no reportees
- Queue: `[Dir B]` → pop `Dir B`, print `Dir B`, no reportees

Output: `CEO  VP Engg  VP Sales  Dir A  Dir B`

---

> **`from collections import deque`** imports `deque` from Python's built-in `collections` module. A `deque` (double-ended queue) supports fast **O(1)** appends and pops from both ends, unlike a regular list which is slow at front-removal. It is the right tool for Level Order traversal because we constantly pop from the front and append to the back.

## 7. Why Recursion Works Naturally for Trees

You may have noticed that Inorder, Preorder, and Postorder all use **recursion**. This is not a coincidence.

Consider this: VP Engineering's subtree is itself a valid org chart — it has a root (VP Engg), a left subtree (Dir A), and a right subtree (Dir B). VP Sales is also a valid (single-node) org chart. The CEO's full org chart is simply these smaller org charts connected together.

A tree is a **recursive structure** by definition:

> A binary tree is either empty, or it is a node whose left subtree is a binary tree and whose right subtree is a binary tree.

Every subtree is itself a valid binary tree. So any function that works on the full org chart automatically works on any department within it too. Recursion is not a trick here — it is the most natural expression of a tree algorithm.

**The base case** is always: *if the node is None (no employee here), do nothing and return.*

## 8. Complete Program

```python
from collections import deque


class Node:
    def __init__(self, data):
        self.data  = data
        self.left  = None
        self.right = None

    def __repr__(self):
        return f"Node({self.data})"


class BinaryTree:
    def __init__(self, root_data):
        self.root = Node(root_data)

    # Inorder: Left → Root → Right
    def inorder(self, node=None, _first_call=True):
        if _first_call:
            node = self.root
        if node is None:
            return
        self.inorder(node.left, _first_call=False)
        print(node.data, end="  ")
        self.inorder(node.right, _first_call=False)

    # Preorder: Root → Left → Right
    def preorder(self, node=None, _first_call=True):
        if _first_call:
            node = self.root
        if node is None:
            return
        print(node.data, end="  ")
        self.preorder(node.left, _first_call=False)
        self.preorder(node.right, _first_call=False)

    # Postorder: Left → Right → Root
    def postorder(self, node=None, _first_call=True):
        if _first_call:
            node = self.root
        if node is None:
            return
        self.postorder(node.left, _first_call=False)
        self.postorder(node.right, _first_call=False)
        print(node.data, end="  ")

    # Level Order: Level by Level
    def level_order(self):
        if not self.root:
            return
        queue = deque([self.root])
        while queue:
            node = queue.popleft()
            print(node.data, end="  ")
            if node.left:
                queue.append(node.left)
            if node.right:
                queue.append(node.right)


# Build the Company Org Chart
#
#               [ CEO ]
#              /        \
#       [ VP Engg ]   [ VP Sales ]
#       /         \
#  [ Dir A ]   [ Dir B ]
#
tree = BinaryTree("CEO")
tree.root.left        = Node("VP Engg")
tree.root.right       = Node("VP Sales")
tree.root.left.left   = Node("Dir A")
tree.root.left.right  = Node("Dir B")

print("Inorder   (L→Root→R):", end="  ")
tree.inorder()
print()

print("Preorder  (Root→L→R):", end="  ")
tree.preorder()
print()

print("Postorder (L→R→Root):", end="  ")
tree.postorder()
print()

print("Level Order          :", end="  ")
tree.level_order()
print()
```

**Output:**

```
Inorder   (L→Root→R):   Dir A  VP Engg  Dir B  CEO  VP Sales
Preorder  (Root→L→R):   CEO  VP Engg  Dir A  Dir B  VP Sales
Postorder (L→R→Root):   Dir A  Dir B  VP Engg  VP Sales  CEO
Level Order          :   CEO  VP Engg  VP Sales  Dir A  Dir B
```

## 9. Traversal Comparison

```
               [ CEO ]
              /        \
       [ VP Engg ]   [ VP Sales ]
       /         \
  [ Dir A ]   [ Dir B ]
```

| Traversal | Order | Real-World Meaning in Org Chart |
|-----------|-------|----------------------------------|
| **Inorder** | Left → Root → Right | Audit juniors → head → other juniors |
| **Preorder** | Root → Left → Right | CEO speaks first, then each team |
| **Postorder** | Left → Right → Root | Appraise juniors before their manager |
| **Level Order** | Level by level | Announcement spreads floor by floor |

## 10. Common Mistakes

**Mistake 1 — Assigning to the wrong child**

```python
# Intending to add VP Sales as right child, but writing left by mistake
tree.root.left  = Node("VP Sales")   # Wrong — overwrites VP Engg
tree.root.right = Node("VP Sales")   # Correct
```

**Mistake 2 — Missing the base case in recursion**

```python
def inorder(node):
    # Without this check: AttributeError: 'NoneType' has no attribute 'left'
    # This crashes when you reach Dir A or Dir B who have no reportees
    if node is None:
        return
    inorder(node.left)
    print(node.data)
    inorder(node.right)
```

`if node is None: return` is not optional — it is the termination condition of every tree recursion. Every leaf employee's left and right are None. Without this check, the function crashes the moment it looks for reportees of a leaf.

**Mistake 3 — Confusing Preorder with Level Order**

Preorder visits `CEO, VP Engg, Dir A, Dir B, VP Sales` — it follows one reporting chain all the way down before moving to the next (depth-first).
Level Order visits `CEO, VP Engg, VP Sales, Dir A, Dir B` — it covers everyone at each seniority level before going deeper (breadth-first).

Both start at the CEO, which tricks many beginners into thinking they are the same.

## 12. Summary

| Concept | Meaning |
|---------|---------|
| `self.data` | The employee name or value stored in the node |
| `self.left = None` | No left reportee yet |
| `self.right = None` | No right reportee yet |
| Leaf node | An employee with no reportees — both `left` and `right` are `None` |
| Root | The CEO — topmost node, the entry point of the tree |
| Inorder | L → Root → R; gives alphabetical output for BST |
| Preorder | Root → L → R; CEO/boss always announced first |
| Postorder | L → R → Root; juniors always processed before their boss |
| Level Order | Uses a Queue; processes every level of the hierarchy together |
| Base case | `if node is None: return` — never skip this |

The Binary Tree Node is two pointers and a value. But from that simplicity emerge the most powerful algorithms in computer science — sorting, searching, compressing, routing, scheduling, and reasoning.

Once you can see a tree in a problem, you have gained a new set of eyes.
