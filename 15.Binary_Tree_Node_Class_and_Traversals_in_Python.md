# Binary Tree — Node Class and Traversals in Python

## 1. Introduction

Picture a company's organisational chart.

At the top sits the **CEO**. Under the CEO are two Vice Presidents — one for Engineering, one for Sales. Under Engineering are two Directors. Under Sales are two more. Every person reports to exactly one boss, but a boss can have multiple people reporting to them.

Now answer this: *Can you represent that company's hierarchy in a simple list?*

You could try — but you'd need a mess of indices, parent pointers, and special cases. A flat list was not designed for hierarchy. A flat list is a road. What you need is a **tree**.

The **Binary Tree** is the simplest form of a tree structure where every node has **at most two children** — a left child and a right child. That "at most two" constraint turns out to be extraordinarily powerful. Almost every efficient searching, sorting, and indexing mechanism in computer science is rooted (pun intended) in a binary tree.

---

## 2. Real-World Applications

Before touching a single line of code, let us convince ourselves why this structure matters.

**Phone Contact Search**

When you search a contact name, your phone does not scan every contact from A to Z. It uses a structure called a **Binary Search Tree** that allows it to discard half the remaining names at every step. 1000 contacts? Found in just 10 comparisons.

**Expression Evaluation in a Calculator**

The expression `(3 + 4) × (2 − 1)` can be drawn as a tree:

```
        ×
       / \
      +   −
     / \ / \
    3  4 2  1
```

A compiler or calculator evaluates this tree to compute the answer. This is called an **Expression Tree**, and every calculator, spreadsheet, and compiler uses it internally.

**File Compression (Huffman Coding)**

When you zip a file, the algorithm builds a binary tree where frequent characters get short codes and rare characters get long codes. Your `.zip`, `.mp3`, and `.jpg` files all use trees.

**Decision Making in AI**

Every "20 Questions" game is a binary tree. Every spam filter, every medical diagnosis AI — they are all binary trees where each node asks a yes/no question and branches accordingly.

## 4. The Node Structure

If you have already understood the Node in a Linked List, this will feel familiar. The only difference is that instead of one `next` pointer, a binary tree node has **two** pointers: `left` and `right`.

<img src="https://media.geeksforgeeks.org/wp-content/uploads/20251006150511615111/Binary-Tree-Representation.webp" alt="Binary Tree" width="400"/>

In a linked list, a node says: *"I know who comes after me."*
In a binary tree, a node says: *"I know who is to my left and who is to my right."*

## 5. Implementation

### 5.1 The Node Class

```python
class Node:
    def __init__(self, data):
        self.data = data       # The value stored in this node
        self.left = None       # Pointer to left child (default: no child)
        self.right = None      # Pointer to right child (default: no child)

    def __repr__(self):
        return f"Node({self.data})"
```

Why `self.left = None` and `self.right = None`?

Because when a node is first born, it is a leaf — it has no children yet. `None` means *"no child here."* As you build your tree, you assign actual Node objects to these pointers.

### 5.2 Creating Individual Nodes

```python
root    = Node(1)
node_b  = Node(2)
node_c  = Node(3)
node_d  = Node(4)
node_e  = Node(5)
```

Right now, these are five isolated boxes floating in memory. Each knows its data, but none knows about the others.

### 5.3 Connecting Nodes into a Tree

```python
root.left    = node_b     # 1's left child is 2
root.right   = node_c     # 1's right child is 3
node_b.left  = node_d     # 2's left child is 4
node_b.right = node_e     # 2's right child is 5
```

In memory, we have now built this shape:

```
         [1]          ← root
        /   \
      [2]   [3]
     /   \
   [4]   [5]
```

Node `3`, `4`, and `5` are **leaves** — their `left` and `right` are still `None`.
Node `1` and `2` are **internal nodes**.

### 5.4 The BinaryTree Wrapper Class

Rather than managing the root separately, we wrap the tree in its own class:

```python
class BinaryTree:
    def __init__(self, root_data):
        self.root = Node(root_data)    # Every tree starts with a root
```

Now you can do:

```python
tree = BinaryTree(1)
tree.root.left        = Node(2)
tree.root.right       = Node(3)
tree.root.left.left   = Node(4)
tree.root.left.right  = Node(5)
```

## 6. Tree Traversals

Here is the central question: *If you want to visit every node in a tree, in what order do you do it?*

In a list, the answer is obvious — start from the beginning, move to the end. But a tree has **branching paths**. There is no single "beginning to end."

Computer scientists identified four fundamental strategies, each with a different real-world purpose. The first three are named based on **when you visit the root** relative to its children.

---

### 6.1 Inorder Traversal — Left → Root → Right

**Rule:** First visit the left subtree entirely. Then visit the root. Then visit the right subtree.

**The Magical Property:** For a Binary Search Tree, Inorder traversal always gives you the nodes in **sorted ascending order**. This is why it is called "in-order" — it visits nodes in their natural sorted sequence.

**Analogy:** Imagine reading a book shelf from left to right. You finish the entire left section, then pick up the book in the middle, then read the right section.

```python
def inorder(node):
    if node is None:
        return
    inorder(node.left)     # 1. Recurse into left subtree
    print(node.data)       # 2. Visit this node
    inorder(node.right)    # 3. Recurse into right subtree
```

**Trace on our tree:**

- Visit `1` → go left to `2` → go left to `4` → `4` has no left → **print 4** → `4` has no right
- Back to `2` → **print 2** → go right to `5` → `5` has no left → **print 5**
- Back to `1` → **print 1** → go right to `3` → `3` has no left → **print 3**

Output: `4  2  5  1  3`

---

### 6.2 Preorder Traversal — Root → Left → Right

**Rule:** Visit the root first. Then visit the left subtree. Then visit the right subtree.

**Analogy:** You are a manager inspecting a company. You introduce yourself first (root), then inspect the left department, then the right. You always announce yourself before diving into a branch.

**Primary Use:** Copying a tree, serialising a tree to store it in a file or database, printing a directory structure.

```python
def preorder(node):
    if node is None:
        return
    print(node.data)       # 1. Visit this node FIRST
    preorder(node.left)    # 2. Recurse into left subtree
    preorder(node.right)   # 3. Recurse into right subtree
```

**Trace on our tree:**

- Visit root → **print 1** → go left
- Visit `2` → **print 2** → go left
- Visit `4` → **print 4** → no children, go back
- Back to `2` → go right → Visit `5` → **print 5** → no children, go back
- Back to `1` → go right → Visit `3` → **print 3**

Output: `1  2  4  5  3`

Notice: The root `1` always comes out first. This makes preorder ideal for **reconstructing** a tree.

---

### 6.3 Postorder Traversal — Left → Right → Root

**Rule:** Visit the left subtree. Then the right subtree. Visit the root last.

**Analogy:** Imagine demolishing a building floor by floor. You must clear all rooms before removing the floor itself. Children are processed before the parent — just like deleting files inside a folder before deleting the folder.

**Primary Use:** Deleting a tree, evaluating expression trees, calculating folder sizes.

```python
def postorder(node):
    if node is None:
        return
    postorder(node.left)    # 1. Recurse into left subtree
    postorder(node.right)   # 2. Recurse into right subtree
    print(node.data)        # 3. Visit this node LAST
```

**Trace on our tree:**

- Go left all the way → `4` is a leaf → **print 4**
- Back to `2` → go right → `5` is a leaf → **print 5**
- Back to `2` → **print 2**
- Back to `1` → go right → `3` is a leaf → **print 3**
- Back to `1` → **print 1**

Output: `4  5  2  3  1`

Notice: The root `1` always comes out last in postorder.

---

### 6.4 Level Order Traversal — Breadth First

**Rule:** Visit all nodes at Level 0 (root), then all nodes at Level 1, then Level 2, and so on.

**Analogy:** A fire spreading outward from a single point reaches all places at distance 1 before reaching anything at distance 2. Or think of a WhatsApp forward — you tell your 2 closest friends (Level 1), they each tell their 2 friends (Level 2). Level order traversal is exactly this wave-like expansion.

**Primary Use:** Finding the shortest path, social network friend suggestions ("people you may know"), web crawlers.

This traversal requires a **Queue** because you need to process nodes in the order you discover them.

```python
from collections import deque

def level_order(root):
    if root is None:
        return

    queue = deque()
    queue.append(root)           # Start: put the root in the queue

    while queue:
        node = queue.popleft()   # Take from the front
        print(node.data)         # Visit this node

        if node.left:            # Enqueue left child if it exists
            queue.append(node.left)
        if node.right:           # Enqueue right child if it exists
            queue.append(node.right)
```

**Trace on our tree:**

- Queue: `[1]` → pop `1`, print `1`, enqueue `2` and `3`
- Queue: `[2, 3]` → pop `2`, print `2`, enqueue `4` and `5`
- Queue: `[3, 4, 5]` → pop `3`, print `3`, no children
- Queue: `[4, 5]` → pop `4`, print `4`, no children
- Queue: `[5]` → pop `5`, print `5`, no children

Output: `1  2  3  4  5`

## 7. Why Recursion Works Naturally for Trees

You may have noticed that Inorder, Preorder, and Postorder all use **recursion**. This is not a coincidence.

A tree is a **recursive structure** by definition:

> A binary tree is either empty, or it is a node whose left subtree is a binary tree and whose right subtree is a binary tree.

Every subtree is itself a valid binary tree. So any function that works on a tree automatically works on any of its subtrees too. Recursion is not a trick here — it is the most natural expression of a tree algorithm.

**The base case** is always: *if the node is None, do nothing and return.*

## 8. Complete Program

```python
from collections import deque


class Node:
    def __init__(self, data):
        self.data  = data
        self.left  = None
        self.right = None

    def __repr__(self):
        return f"Node({self.data})"


class BinaryTree:
    def __init__(self, root_data):
        self.root = Node(root_data)

    # Inorder: Left → Root → Right
    def inorder(self, node=None, _first_call=True):
        if _first_call:
            node = self.root
        if node is None:
            return
        self.inorder(node.left, _first_call=False)
        print(node.data, end="  ")
        self.inorder(node.right, _first_call=False)

    # Preorder: Root → Left → Right
    def preorder(self, node=None, _first_call=True):
        if _first_call:
            node = self.root
        if node is None:
            return
        print(node.data, end="  ")
        self.preorder(node.left, _first_call=False)
        self.preorder(node.right, _first_call=False)

    # Postorder: Left → Right → Root
    def postorder(self, node=None, _first_call=True):
        if _first_call:
            node = self.root
        if node is None:
            return
        self.postorder(node.left, _first_call=False)
        self.postorder(node.right, _first_call=False)
        print(node.data, end="  ")

    # Level Order: Level by Level
    def level_order(self):
        if not self.root:
            return
        queue = deque([self.root])
        while queue:
            node = queue.popleft()
            print(node.data, end="  ")
            if node.left:
                queue.append(node.left)
            if node.right:
                queue.append(node.right)


# Build the Tree
#
#          [1]
#         /   \
#       [2]   [3]
#      /   \
#    [4]   [5]
#
tree = BinaryTree(1)
tree.root.left        = Node(2)
tree.root.right       = Node(3)
tree.root.left.left   = Node(4)
tree.root.left.right  = Node(5)

print("Inorder   (L→Root→R):", end="  ")
tree.inorder()
print()

print("Preorder  (Root→L→R):", end="  ")
tree.preorder()
print()

print("Postorder (L→R→Root):", end="  ")
tree.postorder()
print()

print("Level Order          :", end="  ")
tree.level_order()
print()
```

**Output:**

```
Inorder   (L→Root→R):   4  2  5  1  3
Preorder  (Root→L→R):   1  2  4  5  3
Postorder (L→R→Root):   4  5  2  3  1
Level Order          :   1  2  3  4  5
```

## 9. Traversal Comparison

```
          [1]
         /   \
       [2]   [3]
      /   \
    [4]   [5]
```

| Traversal | Order | Output | Best Used For |
|-----------|-------|--------|---------------|
| **Inorder** | Left → Root → Right | `4 2 5 1 3` | Sorted output from BST |
| **Preorder** | Root → Left → Right | `1 2 4 5 3` | Copying / serialising a tree |
| **Postorder** | Left → Right → Root | `4 5 2 3 1` | Deleting a tree, evaluating expressions |
| **Level Order** | Level by level | `1 2 3 4 5` | Shortest path, BFS problems |

## 10. Common Mistakes

**Mistake 1 — Assigning to the wrong child**

```python
# Intending to add a right child, but writing left by mistake
tree.root.left  = Node(3)    # Wrong — overwrites the existing left child
tree.root.right = Node(3)    # Correct
```

**Mistake 2 — Missing the base case in recursion**

```python
def inorder(node):
    # Without this check: AttributeError: 'NoneType' has no attribute 'left'
    if node is None:
        return
    inorder(node.left)
    print(node.data)
    inorder(node.right)
```

`if node is None: return` is not optional — it is the termination condition of every tree recursion.

**Mistake 3 — Confusing Preorder with Level Order**

Preorder visits `1, 2, 4, 5, 3` — it dives deep down the left branch first (depth-first).
Level Order visits `1, 2, 3, 4, 5` — it sweeps across each level (breadth-first).

They both start at the root, which tricks many beginners into thinking they are the same.

## 11. What Comes Next

The Binary Tree is the foundation for an entire family of advanced structures:

```
Binary Tree
 │
 ├──► Binary Search Tree (BST)
 │      └── Every left child < parent < every right child
 │          Searching becomes O(log n) instead of O(n)
 │
 ├──► AVL Tree / Red-Black Tree
 │      └── Self-balancing BSTs used in databases (Java TreeMap,
 │          C++ std::map, Linux process scheduler)
 │
 ├──► Heap (Min-Heap / Max-Heap)
 │      └── Priority queues; used in Dijkstra's algorithm,
 │          OS schedulers, A* pathfinding
 │
 ├──► Trie (Prefix Tree)
 │      └── Autocomplete in search bars, spell checkers,
 │          IP routing tables
 │
 └──► Segment Tree / Fenwick Tree
        └── Range queries in competitive programming,
            used in game engines and financial systems
```

## 12. Summary

| Concept | Meaning |
|---------|---------|
| `self.data` | The value stored in the node |
| `self.left = None` | No left child yet |
| `self.right = None` | No right child yet |
| Leaf node | A node where both `left` and `right` are `None` |
| Root | The topmost node; the entry point of the tree |
| Inorder | L → Root → R; gives sorted output for BST |
| Preorder | Root → L → R; used for copying and serialising |
| Postorder | L → R → Root; used for deletion and expression evaluation |
| Level Order | Uses a Queue; visits nodes level by level |
| Base case | `if node is None: return` — never skip this |

The Binary Tree Node is two pointers and a value. But from that simplicity emerge the most powerful algorithms in computer science — sorting, searching, compressing, routing, scheduling, and reasoning.

Once you can see a tree in a problem, you have gained a new set of eyes.
