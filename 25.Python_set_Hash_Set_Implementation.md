# Python `set` — Hash Set Implementation

---

## 1. Introduction

Picture a college hostel's attendance register.

Every morning the warden checks: *"Is this student present?"* The register has 1,000 names. A slow warden scans from page 1 to page 1,000 for every single check. A smart warden uses a **locker system** — each student is assigned a locker number based on their roll number. To check if a student is present, you go directly to their locker. One step. Done.

```
Roll 1023  →  locker 23  →  ✓ Present
Roll 1087  →  locker 87  →  ✗ Absent
Roll 1045  →  locker 45  →  ✓ Present
```

Now answer this: *Can you do that instant lookup with a regular Python list?*

You cannot — not efficiently. A list checks every element one by one. What you need is a structure that maps any value to its storage location in **O(1)** — constant time, regardless of size. That structure is a **Hash Set**.

Python's built-in `set` is a Hash Set under the hood. Understanding how it works transforms how you think about membership testing, deduplication, and set mathematics — three operations that appear in almost every real program.

---

## 2. Real-World Applications

In our hostel analogy, every student is a **value**, the locker number is a **hash**, and the locker system is the **hash table** that powers the set.

Now extend that thinking outward:

**Deduplication in Data Pipelines**

A payment system receives 10 million transaction IDs per day. Some are retries — duplicates that must be discarded. Scanning a list for duplicates takes O(n²). A Hash Set discards duplicates in a single O(n) pass. Every ETL pipeline, every event-deduplication system uses this.

**Spell Checkers**

A spell checker loads all 200,000 valid English words into a Hash Set. For every word you type, it asks: *"Is this word in the set?"* — answered in O(1). Checking a million words against a list would take hours. With a Hash Set it takes milliseconds.

**Network Security — Blacklist Filtering**

A firewall keeps a set of blocked IP addresses. When a packet arrives, the firewall checks the source IP against the set in one step. Loading 5 million blocked IPs into a list and searching linearly would be catastrophically slow. A Hash Set makes it instant.

**Social Networks — Mutual Friends**

*"Which friends do Alice and Bob have in common?"* Alice's friend set ∩ Bob's friend set — a single set intersection operation. Python's `set` makes a problem that sounds complex completely trivial.

## 3. Key Terminology

Before writing code, you must speak the language. These terms will appear throughout your career.

```
Value:  "Alice"
         │
         ▼
Hash Function:  hash("Alice") = 4568291736...
         │
         ▼
Index:   4568291736 % table_size  =  7
         │
         ▼
Bucket:  [ slot 7 ] ← "Alice" stored here
```

| Term | Meaning |
|------|---------|
| **Hash Function** | A formula that converts any value into an integer (the hash). Fast and deterministic. |
| **Hash Code** | The integer produced by the hash function for a given value. |
| **Bucket / Slot** | One cell in the internal array where values are stored. |
| **Collision** | Two different values produce the same bucket index. Must be handled. |
| **Load Factor** | Ratio of stored elements to total buckets. Triggers resizing when too high. |
| **Rehashing** | Expanding the internal array and redistributing all elements when load factor is exceeded. |
| **Membership Test** | Asking: *"Is this value in the set?"* — the primary operation. |
| **Unordered** | Hash Sets make no guarantee about the order elements are stored or iterated. |

## 4. How Hashing Works

The central idea is deceptively simple.

To **store** a value: run it through a hash function → get an index → place the value at that index in an array.

To **look up** a value: run it through the same hash function → get the same index → check if the value is there.

```
Internal Array (size = 8):

Index:   0     1     2     3     4     5     6     7
       [   ] [   ] [   ] ["Bob"][   ] [   ] [   ] ["Alice"]
                            ▲                         ▲
                   hash("Bob") % 8 = 3       hash("Alice") % 8 = 7
```

**Why O(1)?**

Because the index is *computed*, not *searched*. You never scan the array. You jump directly to the right slot. Doesn't matter if the set has 10 elements or 10 million.

**What is a Collision?**

Two values can produce the same index:

```
hash("Alice") % 8 = 7
hash("Eve")   % 8 = 7   ← Collision! Same bucket.
```

Python resolves this with **open addressing** — it probes nearby slots until it finds an empty one. The details are hidden from you, but understanding that collisions exist explains why Hash Sets occasionally resize themselves.

## 5. Python's Built-in `set`

Python's `set` is a fully implemented Hash Set. No imports needed.

### 5.1 Creating a Set

```python
# Empty set — must use set(), NOT {} (that creates a dict)
employees = set()

# Set from a literal
departments = {"Engineering", "Sales", "HR", "Finance"}

# Set from a list (deduplication happens automatically)
raw_ids = [101, 202, 101, 303, 202, 404]
unique_ids = set(raw_ids)
print(unique_ids)   # {101, 202, 303, 404}  — duplicates removed
```

Why `set()` for empty and not `{}`?

Because `{}` was already claimed by Python dictionaries. An empty `set` must be written as `set()`. This is a common beginner mistake that causes silent bugs.

### 5.2 Core Operations

```python
employees = {"Alice", "Bob", "Charlie"}

# Add a single element — O(1)
employees.add("Diana")
print(employees)    # {"Alice", "Bob", "Charlie", "Diana"}

# Add a duplicate — silently ignored, no error
employees.add("Alice")
print(len(employees))   # Still 4 — Alice is not added twice

# Membership test — O(1)   ← The killer feature
print("Bob" in employees)       # True
print("Mallory" in employees)   # False

# Remove — O(1); raises KeyError if not found
employees.remove("Charlie")

# Discard — O(1); silently does nothing if not found (safer)
employees.discard("Nobody")     # No error

# Pop — removes and returns an arbitrary element
whoever = employees.pop()
print(whoever)      # Some element — order is not guaranteed

# Size
print(len(employees))   # O(1)

# Clear all elements
employees.clear()
```

### 5.3 Set Mathematics

This is where `set` becomes extraordinary. Operations that would take you dozens of lines with lists become single symbols.

```python
alice_friends = {"Bob", "Carol", "Dave", "Eve"}
bob_friends   = {"Alice", "Carol", "Frank", "Dave"}

# Union — everyone either person knows
all_people = alice_friends | bob_friends
# {"Bob", "Carol", "Dave", "Eve", "Alice", "Frank"}

# Intersection — mutual friends
mutual = alice_friends & bob_friends
# {"Carol", "Dave"}

# Difference — Alice's friends who are NOT Bob's friends
only_alice = alice_friends - bob_friends
# {"Bob", "Eve"}

# Symmetric Difference — friends of exactly one person, not both
exclusive = alice_friends ^ bob_friends
# {"Bob", "Eve", "Alice", "Frank"}
```

**Subset and Superset Checks:**

```python
admins  = {"Alice", "Bob"}
all_staff = {"Alice", "Bob", "Carol", "Dave"}

print(admins.issubset(all_staff))       # True — all admins are staff
print(all_staff.issuperset(admins))     # True — staff includes all admins
print(admins.isdisjoint({"Carol"}))     # True — no overlap
```

## 6. Implementing a Hash Set from Scratch

Python's `set` hides all the internals. Building one from scratch reveals exactly how it works.

We will build a `HashSet` class that supports `add`, `contains`, `remove`, and `__len__`, using **chaining** (each bucket holds a list) to resolve collisions.

```
Internal Array (self._buckets):

Index 0:  []
Index 1:  []
Index 2:  ["Alice"]           ← hash("Alice") % 8 = 2
Index 3:  ["Bob", "Rob"]      ← Collision! Both land at index 3
Index 4:  []
Index 5:  ["Carol"]
Index 6:  []
Index 7:  []
```

### 6.1 The HashSet Class

```python
class HashSet:
    """
    A Hash Set implementation using separate chaining for collision resolution.
    Supports O(1) average-case add, remove, and membership test.
    """

    INITIAL_CAPACITY = 8        # Starting number of buckets
    LOAD_FACTOR_LIMIT = 0.75    # Resize when 75% full

    def __init__(self):
        self._capacity = HashSet.INITIAL_CAPACITY
        self._buckets  = [[] for _ in range(self._capacity)]  # Array of empty lists
        self._size     = 0      # Number of elements stored

    def __repr__(self):
        items = [item for bucket in self._buckets for item in bucket]
        return f"HashSet({items})"

    def __len__(self):
        return self._size
```

Why a list of lists?

Each `bucket` at index `i` is a small Python list. If two values hash to the same index, they both go into that list. This is called **separate chaining**. Each chain stays short (average length = load factor), keeping lookup fast.

### 6.2 The `_get_index` Helper

```python
    def _get_index(self, value):
        """Compute the bucket index for a given value."""
        return hash(value) % self._capacity
```

Python's built-in `hash()` handles strings, integers, tuples — any **hashable** type. We just mod it by capacity to fit within our array.

### 6.3 The `add` Method

```python
    def add(self, value):
        """Add value to the set. Ignored if already present. O(1) average."""
        index  = self._get_index(value)
        bucket = self._buckets[index]

        if value not in bucket:     # Avoid duplicates — sets store each value once
            bucket.append(value)
            self._size += 1

            # Resize if load factor exceeded
            if self._size / self._capacity > HashSet.LOAD_FACTOR_LIMIT:
                self._rehash()
```

Two things to notice:

First, `value not in bucket` scans the chain at that bucket. Because we resize when load factor hits 0.75, chains stay short — average length is less than 1. So this scan is effectively O(1).

Second, after adding, we check the load factor. If more than 75% of buckets are in use, we rehash — doubling capacity and redistributing everything.

### 6.4 The `contains` Method

```python
    def contains(self, value):
        """Return True if value is in the set. O(1) average."""
        index  = self._get_index(value)
        bucket = self._buckets[index]
        return value in bucket
```

We compute the index in one step, then check only the (usually tiny) chain at that index. This is the O(1) magic.

### 6.5 The `remove` Method

```python
    def remove(self, value):
        """Remove value from the set. Raises KeyError if not found."""
        index  = self._get_index(value)
        bucket = self._buckets[index]

        if value not in bucket:
            raise KeyError(f"{value!r} not in HashSet")

        bucket.remove(value)
        self._size -= 1
```

### 6.6 The `_rehash` Method

```python
    def _rehash(self):
        """Double capacity and redistribute all elements."""
        old_buckets       = self._buckets
        self._capacity   *= 2
        self._buckets     = [[] for _ in range(self._capacity)]
        self._size        = 0   # Will be re-counted during re-insertion

        for bucket in old_buckets:
            for value in bucket:
                self.add(value)     # Re-insert using new capacity
```

Why does rehashing exist?

As the set fills up, chains grow longer. A 75%-full table with 8 buckets storing 6 items has chains averaging 0.75 in length — still O(1). But if we kept adding without resizing, eventually every value lands in a long chain and lookup degrades to O(n). Rehashing resets the load factor back to ~37.5% after doubling.

## 7. Complete Implementation

```python
class HashSet:
    """
    Hash Set using separate chaining.
    O(1) average-case: add, remove, contains.
    O(n) worst-case (all values hash to the same bucket).
    """

    INITIAL_CAPACITY = 8
    LOAD_FACTOR_LIMIT = 0.75

    def __init__(self):
        self._capacity = HashSet.INITIAL_CAPACITY
        self._buckets  = [[] for _ in range(self._capacity)]
        self._size     = 0

    # ── Core Interface ────────────────────────────────────────────────────────

    def add(self, value):
        index  = self._get_index(value)
        bucket = self._buckets[index]
        if value not in bucket:
            bucket.append(value)
            self._size += 1
            if self._size / self._capacity > HashSet.LOAD_FACTOR_LIMIT:
                self._rehash()

    def remove(self, value):
        index  = self._get_index(value)
        bucket = self._buckets[index]
        if value not in bucket:
            raise KeyError(f"{value!r} not in HashSet")
        bucket.remove(value)
        self._size -= 1

    def contains(self, value):
        index  = self._get_index(value)
        return value in self._buckets[index]

    def discard(self, value):
        """Remove without raising KeyError if absent."""
        try:
            self.remove(value)
        except KeyError:
            pass

    # ── Set Mathematics ───────────────────────────────────────────────────────

    def union(self, other):
        result = HashSet()
        for bucket in self._buckets:
            for v in bucket:
                result.add(v)
        for bucket in other._buckets:
            for v in bucket:
                result.add(v)
        return result

    def intersection(self, other):
        result = HashSet()
        for bucket in self._buckets:
            for v in bucket:
                if other.contains(v):
                    result.add(v)
        return result

    def difference(self, other):
        result = HashSet()
        for bucket in self._buckets:
            for v in bucket:
                if not other.contains(v):
                    result.add(v)
        return result

    # ── Dunder Methods ────────────────────────────────────────────────────────

    def __len__(self):
        return self._size

    def __contains__(self, value):
        return self.contains(value)

    def __repr__(self):
        items = [item for bucket in self._buckets for item in bucket]
        return f"HashSet({items})"

    # ── Internal Helpers ──────────────────────────────────────────────────────

    def _get_index(self, value):
        return hash(value) % self._capacity

    def _rehash(self):
        old_buckets     = self._buckets
        self._capacity *= 2
        self._buckets   = [[] for _ in range(self._capacity)]
        self._size      = 0
        for bucket in old_buckets:
            for value in bucket:
                self.add(value)


# ── Demo: Hostel Attendance System ────────────────────────────────────────────

present = HashSet()

# Students arrive
for student in ["Alice", "Bob", "Carol", "Dave", "Eve"]:
    present.add(student)

print("Attendance set:", present)                   # Order not guaranteed
print("Total present :", len(present))              # 5
print("Is Bob present?", "Bob" in present)          # True
print("Is Mallory present?", "Mallory" in present)  # False

# Bob leaves
present.discard("Bob")
print("After Bob leaves:", len(present))            # 4

# Duplicate — silently ignored
present.add("Alice")
print("After duplicate add:", len(present))         # Still 4

# Set operations
morning_batch = HashSet()
for s in ["Alice", "Carol", "Frank"]:
    morning_batch.add(s)

afternoon_batch = present   # Alice, Carol, Dave, Eve

both_batches   = morning_batch.union(afternoon_batch)
common         = morning_batch.intersection(afternoon_batch)
only_morning   = morning_batch.difference(afternoon_batch)

print("Union        :", both_batches)
print("Intersection :", common)
print("Only morning :", only_morning)
```

**Output:**

```
Attendance set: HashSet(['Alice', 'Bob', 'Carol', 'Dave', 'Eve'])
Total present : 5
Is Bob present? True
Is Mallory present? False
After Bob leaves: 4
After duplicate add: 4
Union        : HashSet(['Alice', 'Carol', 'Frank', 'Dave', 'Eve'])
Intersection : HashSet(['Alice', 'Carol'])
Only morning : HashSet(['Frank'])
```

## 8. Why Recursion Doesn't Apply Here — and What Does

Unlike Binary Trees, Hash Sets are **not recursive structures**. They are flat arrays of buckets. The interesting internal mechanism is not recursion — it is the **hash function** and the **rehashing cycle**.

The mental model:

> A Hash Set is an array where the *address* of every element is computed from the element itself.

This is what makes it O(1). Recursion solves *"how do I visit a structure that branches?"* Hashing solves *"how do I find something without searching?"* — an entirely different class of problem.

## 9. `set` vs `list` vs `dict` — When to Use Which

| Operation | `list` | `set` | `dict` |
|-----------|--------|-------|--------|
| Membership test (`in`) | O(n) — scans all | **O(1)** — hash lookup | **O(1)** — hash lookup |
| Add element | O(1) append | **O(1)** add | O(1) insert |
| Remove by value | O(n) — must scan | **O(1)** discard | O(1) by key |
| Duplicates allowed | Yes | **No** — auto-deduplicated | Keys: No, Values: Yes |
| Ordered | Yes (insertion order) | **No** | Yes (insertion order, Python 3.7+) |
| Key → Value mapping | No | No | **Yes** |
| Set math (union, intersect) | Manual loops | **Built-in** | No |

**Rule of thumb:**

Use `set` when you care about *membership* and *uniqueness*, not about order or key-value pairs. If your question is *"is X in this collection?"* and you're asking it repeatedly, `set` is your answer.

## 10. Common Mistakes

**Mistake 1 — Using `{}` for an empty set**

```python
# This creates a dict, not a set
empty = {}
print(type(empty))   # <class 'dict'>

# Correct
empty = set()
print(type(empty))   # <class 'set'>
```

**Mistake 2 — Trying to hash an unhashable type**

```python
# Lists are mutable — they cannot be hashed
bad_set = {[1, 2, 3]}   # TypeError: unhashable type: 'list'

# Use a tuple instead — tuples are immutable and hashable
good_set = {(1, 2, 3)}  # Works perfectly
```

Why does this matter? The hash function needs the value to *never change* after it is stored. If a value could change, it would need a different slot — but the set would not know to move it. Mutability breaks hashing.

**Mistake 3 — Assuming set order is consistent**

```python
names = {"Zara", "Alice", "Bob"}
for name in names:
    print(name)
# Output order is NOT guaranteed — do not rely on it
```

If you need a sorted output: `sorted(names)` — but that returns a list, not a set.

**Mistake 4 — Using `remove` when `discard` is safer**

```python
employees = {"Alice", "Bob"}

employees.remove("Charlie")    # KeyError — Charlie doesn't exist
employees.discard("Charlie")   # No error — safe to call even if absent
```

Use `remove` when absence is an error. Use `discard` when absence is acceptable.

**Mistake 5 — Modifying a set while iterating over it**

```python
s = {1, 2, 3, 4, 5}
for x in s:
    if x % 2 == 0:
        s.remove(x)   # RuntimeError: Set changed size during iteration

# Correct: build a new set or collect removals first
s = {x for x in s if x % 2 != 0}
```

## 11. Time and Space Complexity

| Operation | Average Case | Worst Case |
|-----------|-------------|------------|
| `add(v)` | O(1) | O(n) — all values collide |
| `remove(v)` | O(1) | O(n) |
| `v in s` | **O(1)** | O(n) |
| `len(s)` | O(1) | O(1) |
| Union `\|` | O(m + n) | O(m + n) |
| Intersection `&` | O(min(m, n)) | O(m · n) |
| Difference `-` | O(len(s1)) | O(len(s1)) |
| Rehash | O(n) — amortised O(1) per add | O(n) |

**Space:** O(n) — one slot (or chain entry) per unique element stored.

The O(n) worst case for lookup exists when a maliciously chosen set of values all hash to the same bucket. In practice, with Python's hash randomisation (enabled by default since Python 3.3), this is not a real-world concern.

## 13. Summary

| Concept | Meaning |
|---------|---------|
| Hash Function | Converts a value into an integer index in O(1) |
| Bucket | One slot in the internal array; holds a chain of values |
| Collision | Two values produce the same index; resolved by chaining or probing |
| Load Factor | Elements ÷ Capacity; triggers rehashing when too high (typically 0.75) |
| `add(v)` | Hashes v, places it in its bucket — O(1) average |
| `v in s` | Hashes v, checks only its bucket — O(1) average |
| `remove(v)` | Hashes v, removes from its bucket — O(1) average |
| `discard(v)` | Same as remove but no KeyError if absent |
| `\|` `&` `-` `^` | Union, Intersection, Difference, Symmetric Difference |
| Unordered | Sets do not preserve insertion order — never rely on it |
| Unhashable | Lists, dicts, and other sets cannot be stored in a set — use tuples |
| `{}` trap | `{}` creates a dict; always use `set()` for an empty set |

A Hash Set is one bucket of data and one mathematical formula. But from that simplicity emerges the most powerful membership-testing structure in computer science — deduplication, filtering, social graph queries, network security, and spell checking all collapse to a single O(1) lookup.

Once you understand hashing, you understand how Python makes `in` instant.
