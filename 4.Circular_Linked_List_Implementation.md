# Circular Linked List – Implementation in Python
### *Because sometimes, the end is just the beginning again*

---

## The Setup — A Problem Worth Solving

Picture this.

You are building a **multiplayer board game** — Ludo, Monopoly, anything with turns. After Player 4 goes, it's Player 1's turn again. Forever. Until someone wins.

With a Python list, you'd write this:

```python
current = (current + 1) % len(players)   # manual wraparound every single step
```

It works. But the structure doesn't know it's circular — *you* enforce it, every time, with arithmetic. Add or remove a player mid-game, and your index math quietly breaks.

What if the wraparound was **built into the data structure itself**?

That is a **Circular Linked List**.

---

## What Exactly Is a Circular Linked List?

A Circular Linked List is a chain of nodes where the **last node points back to the first** — completing the circle. There is no `None` at the end.

```
         ┌─────────────────────────────────────────┐
         │                                         │
         ▼                                         │
      [Alice] ──► [Bob] ──► [Carol] ──► [Dave] ────┘
         ↑
        head  (tail.next)
```

- No `None` at the end — the chain wraps
- You track **`tail`** (not head) — because `tail.next` gives you the head for free
- **Singly** means each node knows only the next — it's a one-way circle

---

## Why Not Just Use a Singly Linked List?

| Operation | Singly Linked List | Circular Linked List |
|---|---|---|
| Traverse and wrap around | ❌ Manual `%` math | ✅ Built into the structure |
| Insert at end | ❌ O(n) without tail | ✅ O(1) with tail pointer |
| Access head from tail | ❌ Walk entire list | ✅ `tail.next` is always head |
| Model looping systems | ❌ `None` breaks the loop | ✅ Loop is the structure |

The cost: traversal needs a smarter stop condition — no `None` to hit. The gain: cyclic systems become natural, not forced.

---

## The Real-World Example: CPU Round-Robin Scheduling

Your OS runs dozens of processes on one CPU. Each process gets a time slice, then the next runs. After the last, it loops back to the first.

```
    [Chrome] ──► [Spotify] ──► [VS Code] ──► [Terminal] ──► (back to Chrome)
         ↑
    (CPU is here)
```

No index math. No `%`. The structure enforces the loop. The same pattern appears in:

- **Multiplayer games** — cycling through players each round
- **Image carousels** — wrapping from last slide back to first
- **Network token ring** — nodes taking turns to transmit data
- **Traffic light controllers** — Red → Yellow → Green → Red forever

## Building the Foundation

```python
class Node:
    def __init__(self, data):
        self.data = data
        self.next = None

class CircularLinkedList:
    def __init__(self):
        self.tail = None   # tail.next is always the head
```

**Why track `tail` instead of `head`?**
`self.tail` → last node. `self.tail.next` → first node (head). Both ends in O(1), for free. Tracking only `head` would cost O(n) to reach the tail every append.

---

## Act 1 — Traversal

No `None` exists in a circular list. If you follow `.next` blindly, you loop forever. The stop condition is: **return to where you started**.

```python
def traverse(self):
    if not self.tail:
        return
    current = self.tail.next      # start at head
    while True:
        print(current.data, end=" ──► ")
        current = current.next
        if current == self.tail.next:   # back to head — full circle done
            break
```

Trace with `Alice → Bob → Carol → Dave`:

| Step | current | Back to head? |
|------|---------|---------------|
| 1 | Alice | No |
| 2 | Bob | No |
| 3 | Carol | No |
| 4 | Dave | No |
| 5 | Alice | Yes → break |

**Output:** `Alice ──► Bob ──► Carol ──► Dave ──►`

## Act 2 — Insertion

### Scene 1 — Append (Insert at End)

```python
def append(self, data):
    new_node = Node(data)
    if not self.tail:                  # empty list — node points to itself
        new_node.next = new_node
        self.tail = new_node
        return
    new_node.next = self.tail.next     # new node → head (save head first!)
    self.tail.next = new_node          # old tail → new node
    self.tail = new_node               # new node is now tail
```

```
Before: Alice ──► Bob ──► (back to Alice)

Insert Eve:
  Eve.next  = tail.next  →  Eve points to Alice
  tail.next = Eve        →  Bob points to Eve
  tail      = Eve

After: Alice ──► Bob ──► Eve ──► (back to Alice)
```

**Why `new_node.next = self.tail.next` before `self.tail.next = new_node`?**
`tail.next` is your only reference to the head. Overwrite it first and the head is lost forever.

**Time Complexity: O(1)**

---

### Scene 2 — Prepend (Insert at Front)

```python
def prepend(self, data):
    new_node = Node(data)
    if not self.tail:
        new_node.next = new_node
        self.tail = new_node
        return
    new_node.next = self.tail.next     # new node → old head
    self.tail.next = new_node          # tail now points to new node (new head)
    # tail unchanged — last node is still the last
```

```
Before: Alice ──► Bob ──► (back to Alice),  tail = Bob

Insert Zara at front:
  Zara.next  = Bob.next  →  Zara points to Alice
  Bob.next   = Zara      →  Zara is new head

After: Zara ──► Alice ──► Bob ──► (back to Zara)
```

**Time Complexity: O(1)**

## Act 3 — Deletion

### Scene 1 — Delete Head

```python
def delete_head(self):
    if not self.tail:
        return
    if self.tail.next == self.tail:    # only one node
        self.tail = None
        return
    self.tail.next = self.tail.next.next   # tail skips over head → points to node 2
```

```
Before: Alice ──► Bob ──► Carol ──► (back to Alice),  tail = Carol

Carol.next = Alice.next  →  Carol.next = Bob

After: Bob ──► Carol ──► (back to Bob)
```

**Time Complexity: O(1)**

---

### Scene 2 — Delete by Value

```python
def delete_by_value(self, value):
    if not self.tail:
        return
    if self.tail.next.data == value:   # deleting the head — special case
        self.delete_head()
        return
    prev, current = self.tail, self.tail.next
    while current != self.tail.next or prev == self.tail:
        if current.data == value:
            prev.next = current.next
            if current == self.tail:
                self.tail = prev
            return
        prev, current = current, current.next
        if current == self.tail.next:
            break
```

**Why handle the head separately?** To delete any node you need its predecessor. The predecessor of the head is `tail` — a boundary case the main loop doesn't reach cleanly. Isolating it keeps the logic readable.

**Time Complexity: O(n)**

## The Full Story — Watch It Run

```python
game = CircularLinkedList()

game.append("Alice")
game.append("Bob")
game.append("Carol")
game.append("Dave")
game.traverse()
# Alice ──► Bob ──► Carol ──► Dave ──►

game.prepend("Zara")
game.traverse()
# Zara ──► Alice ──► Bob ──► Carol ──► Dave ──►

game.delete_by_value("Bob")
game.traverse()
# Zara ──► Alice ──► Carol ──► Dave ──►

game.delete_head()
game.traverse()
# Alice ──► Carol ──► Dave ──►
```

## The Josephus Problem — Where CLL Gets Serious

`n` people stand in a circle. Count around and every `k`-th person is eliminated. Last one standing wins.

```
k=2, n=5:
[1]──►[2]──►[3]──►[4]──►[5]──►(back to 1)

Eliminate 2 → [1]──►[3]──►[4]──►[5]──►(back to 1)
Eliminate 4 → [1]──►[3]──►[5]──►(back to 1)
Eliminate 1 → [3]──►[5]──►(back to 3)
Eliminate 5 → [3] alone → Winner!
```

```python
def josephus(n, k):
    cll = CircularLinkedList()
    for i in range(1, n + 1):
        cll.append(i)
    current = cll.tail.next
    while cll.tail != cll.tail.next:
        for _ in range(k - 1):
            current = current.next
        next_node = current.next
        cll.delete_by_value(current.data)
        current = next_node
    print(f"Winner: {cll.tail.data}")

josephus(5, 2)   # Winner: 3
```

With an array you'd fight `% n` math at every step. Here, the circle handles the wrap — deletion is a pointer update, not a shift. This maps directly to **distributed leader election** in computer networks.

## Common Mistakes to Avoid

**1. Using `None` as your traversal stop**
```python
# Wrong — loops forever
while current is not None:
    current = current.next
```
```python
# Correct — stop when you lap the head
if current == self.tail.next: break
```

**2. Forgetting self-reference on the first node**
```python
# Wrong — circle broken from the start
self.tail = new_node          # new_node.next is still None!
```
```python
# Correct
new_node.next = new_node      # single node points to itself
self.tail = new_node
```

**3. Overwriting `tail.next` before saving head**
```python
# Wrong — head is lost
self.tail.next = new_node          # tail.next WAS the head — now gone
new_node.next = self.tail.next     # now points to itself!
```
```python
# Correct — forward pointer first
new_node.next = self.tail.next     # save head
self.tail.next = new_node
```

## Time Complexity

| Operation | Complexity | Why |
|---|---|---|
| Append | O(1) | `tail` is direct access |
| Prepend | O(1) | `tail.next` is head |
| Delete head | O(1) | One pointer update |
| Delete by value | O(n) | Must search the circle |
| Traversal | O(n) | Visit every node once |

**Golden insight:** Track `tail`, not `head`. You get both ends for O(1) — the one design decision that makes the whole structure efficient.

## Mental Model

```
         ┌──────────────────────────────────────┐
         │                                      │
      [Alice] ──► [Bob] ──► [Carol] ──► [Dave] ─┘
         ↑                               ↑
     tail.next                         tail

  tail is None          → list is empty
  tail.next == tail     → exactly one node
  tail.next             → always the head
```

---

## Summary

| Concept | The Why |
|---|---|
| `tail.next` | Head access in O(1) — no walking |
| No `None` at end | The circle never terminates — loop is the structure |
| Single node self-loop | The circular invariant must hold at every state |
| Stop at `tail.next` | Your only valid traversal sentinel |
| Josephus / Round-Robin | CLL's two most important real-world uses |

The Circular Linked List is one pointer change away from a Singly Linked List — yet it fundamentally changes what you can model. When a system loops, repeats, or cycles, a Circular Linked List is not just a good fit. It is the natural shape of the problem.
