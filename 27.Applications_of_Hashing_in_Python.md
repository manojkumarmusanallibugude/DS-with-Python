## 1. Introduction

Picture a massive government archive building — ten floors, ten million files.

A clerk receives a request: *"Find the tax return for Ravi Kumar, filed in 2023."*

**Clerk A — Linear Search:**
Starts at shelf 1, row 1, file 1. Reads every label. After hours of searching, finds the file on floor 7. Tomorrow, a different request. Back to shelf 1, row 1, file 1.

**Clerk B — Hash-Indexed Archive:**
Takes the citizen's ID number, runs it through a formula, gets a locker number. Walks directly to locker 4821. Opens it. File is there. Done in thirty seconds — every single time, for any of ten million files.

```
Input:  "Ravi Kumar" + 2023
         │
         ▼
Formula: (name_code × year) % total_lockers  =  4821
         │
         ▼
Locker 4821  →  📁 Tax Return 2023  →  Retrieved in O(1)
```

Clerk B's formula is a **hash function**. The locker system is a **hash table**.

This is the core idea: instead of *searching* for data, you *compute* where it lives. One formula. One step. No scanning. It doesn't matter whether the archive has one hundred files or one hundred billion — the time to find any file is the same.

This single idea powers more software than any other technique in computer science:

- Python's `dict` and `set` — instant key lookup
- Every password you've ever created — stored as a hash, never as plain text
- Git — every commit, file, and tree identified by its hash
- Google's search index — billions of URLs mapped to results
- Blockchain — every block linked to the previous by its hash
- TLS/HTTPS — every certificate signed with a cryptographic hash
- Database indexes — billions of rows, any row in one lookup
- CDN caching — any URL maps to its cached response globally

In this chapter, you will learn hashing not as a single data structure but as a **universal technique** with seven distinct application domains — each one solving a different category of problem, each one using the same core insight.

## 2. The Seven Application Domains of Hashing

Before diving into code, understand the landscape. Hashing solves seven fundamentally different categories of problems in Python:

```
HASHING APPLICATIONS
═══════════════════════════════════════════════════════════════════

  1. FAST LOOKUP & DEDUPLICATION
     dict, set — replace O(n) scans with O(1) hash jumps
     "Is this value present? / What is the value for this key?"

  2. FREQUENCY COUNTING
     Counter, defaultdict(int) — count anything in one pass
     "How many times does each element appear?"

  3. PASSWORD SECURITY
     hashlib.pbkdf2_hmac, bcrypt — one-way, salted, slow
     "Store proof of a password without storing the password"

  4. FILE INTEGRITY & FINGERPRINTING
     hashlib.sha256 — detect corruption or tampering
     "Is this file identical to what was published?"

  5. CACHING & MEMOISATION
     lru_cache, dict cache — skip recomputation
     "Have I computed this before? Return the stored result"

  6. ALGORITHMIC PROBLEM SOLVING
     Two-sum, prefix-hash, sliding window, anagram grouping
     "Reduce O(n²) problems to O(n) using hash maps"

  7. DISTRIBUTED SYSTEMS
     Consistent hashing — distribute load across servers
     "Which server is responsible for this key?"

═══════════════════════════════════════════════════════════════════
```

Each domain uses a different hash function, a different data structure, and has different performance and security requirements. Understanding which domain your problem belongs to is the first and most important step.

## 3. Key Terminology

```
ANY INPUT (any size)              HASH FUNCTION              FIXED OUTPUT
────────────────────              ─────────────              ────────────
"hello"              ──────────►  SHA-256()     ──────────►  2cf24dba5fb0a30e26...
"hellp"              ──────────►  SHA-256()     ──────────►  9b71d224bd62f37850...
[entire 4GB movie]   ──────────►  SHA-256()     ──────────►  b94f6f125c79e2...

          ▲                                               ▲
One character change                        Completely different output
= AVALANCHE EFFECT                          (same 256-bit length always)
```

| Term | Meaning | Example |
|------|---------|---------|
| **Hash Function** | Formula that converts any input into a fixed-size value | `hash()`, `sha256()` |
| **Hash Value / Digest** | The output — also called fingerprint, checksum, or digest | `"2cf24dba..."` |
| **Collision** | Two different inputs produce the same hash | `hash(x) == hash(y)` but `x != y` |
| **Avalanche Effect** | One-bit change → ~50% of output bits change | `"hello"` vs `"hellp"` → completely different SHA-256 |
| **Deterministic** | Same input → same output, always, everywhere | `sha256("abc")` is identical on every machine |
| **One-Way / Preimage Resistant** | Cannot reverse a hash to recover original input | Given `sha256(password)`, cannot find `password` |
| **Collision Resistance** | Computationally infeasible to find two inputs with same hash | Core security property of SHA-256 |
| **Salt** | Random bytes added to a password before hashing | Defeats precomputed rainbow tables |
| **Hash Table** | Array where index = `hash(key) % capacity` | Foundation of `dict` and `set` |
| **Load Factor** | `elements / buckets` — triggers resize when too high | Python resizes `dict` at ~66% |
| **PYTHONHASHSEED** | Per-process random seed for Python's `hash()` | Changes every run by default |
| **Non-Cryptographic Hash** | Fast; for hash tables only — no security guarantees | Python's `hash()` |
| **Cryptographic Hash** | Slow; one-way, collision-resistant, avalanche effect | `hashlib.sha256()` |

## 4. Python's Built-in `hash()` — The Engine of `dict` and `set`

Python's `hash()` is fast, non-cryptographic, and built for one purpose: computing bucket indices inside `dict` and `set`. Understanding it deeply explains every behaviour of these two structures.

### 4.1 How `hash()` Feeds into a Hash Table

```
Step 1: Compute hash
        key = "Alice"
        h   = hash("Alice")  →  4568291736854325912

Step 2: Map to bucket index
        index = h % capacity
        index = 4568291736854325912 % 8  =  0

Step 3: Store at index 0
        buckets[0] = ("Alice", 95000)

Step 4: Lookup — same key, same computation, same index, O(1)
        hash("Alice") % 8  =  0  →  buckets[0]  →  95000
```

### 4.2 Basic Behaviour

```python
# Integers: Python's hash of an int is the int itself (mod large prime for big ints)
print(hash(0))           # 0
print(hash(42))          # 42
print(hash(-1))          # -2  ← -1 is reserved internally, mapped to -2
print(hash(10**18))      # Large: computed via modular arithmetic

# Strings: fast polynomial rolling hash, randomised per process
print(hash("hello"))     # e.g.  7013366597264323348  (changes each run)
print(hash("Hello"))     # e.g. -8428029956198347394  (one capital → very different)
print(hash("hello "))    # e.g.  3745538199813721073  (one space → very different)

# Numeric equality → hash equality (always)
print(hash(1) == hash(1.0) == hash(True))  # True — because 1 == 1.0 == True
print(1 == 1.0 == True)                    # True — same value

# Tuples: hash is derived from all elements
print(hash((1, 2, 3)))   # Consistent within a process run
print(hash((1, 2, 4)))   # Completely different — one element changed

# None and bool
print(hash(None))        # Some fixed large integer (platform-specific)
print(hash(True))        # 1
print(hash(False))       # 0
```

### 4.3 Hash Randomisation — PYTHONHASHSEED

```python
# Run 1:  python script.py
print(hash("user_id"))   # 3847291056234781234

# Run 2:  python script.py
print(hash("user_id"))   # -5624109834721098345  ← Completely different!

# Why? Python randomises the hash seed at startup since Python 3.3
# This defeats "Hash DoS" attacks — where attackers craft inputs that
# all map to the same bucket, turning O(1) dict into O(n) catastrophe
```

```
HASH DoS ATTACK (without randomisation):
  Attacker crafts 10,000 strings that all hash to bucket 0
  Your web server receives these as HTTP POST parameters
  dict.__setitem__ for each one scans the entire chain at bucket 0
  O(10,000²) = 100,000,000 operations per request
  Server becomes unresponsive. Denial of Service achieved.

WITH PYTHONHASHSEED randomisation:
  The same 10,000 strings hash to random different buckets
  Attack fails — attacker cannot predict bucket layout
```

```python
import os

# Fix the seed for reproducible testing (NEVER in production security)
# Run as: PYTHONHASHSEED=42 python script.py
seed = os.environ.get("PYTHONHASHSEED", "random")
```

### 4.4 What Is and Is Not Hashable

```python
# ✓ HASHABLE — immutable, fixed content
hash(42)               # int
hash(3.14)             # float
hash("text")           # str
hash(True)             # bool
hash(None)             # NoneType
hash((1, "a", 3.0))   # tuple — only if ALL elements are hashable
hash(frozenset({1, 2, 3}))  # frozenset — immutable version of set

# ✗ NOT HASHABLE — mutable, content can change after creation
hash([1, 2, 3])        # TypeError: unhashable type: 'list'
hash({"a": 1})         # TypeError: unhashable type: 'dict'
hash({1, 2, 3})        # TypeError: unhashable type: 'set'
hash((1, [2, 3]))      # TypeError — tuple containing a list is not hashable
```

**Why does mutability prevent hashing?**

```
Scenario:
  key = [1, 2, 3]
  hash([1, 2, 3]) % 8 = 5   →   stored at bucket 5

  Later: key.append(4)       →   key is now [1, 2, 3, 4]
  hash([1, 2, 3, 4]) % 8 = 2  →   correct bucket is now 2

  But the dict still thinks it's at bucket 5.
  The key is LOST — unreachable without scanning all buckets.
  The hash table is silently corrupted.

Solution: forbid mutable keys. Enforced by the Python runtime.
```

### 4.5 Custom `__hash__` and `__eq__`

```python
class Student:
    """
    A student identified uniquely by roll number.
    Two Student objects with the same roll number are considered equal
    even if their names differ — useful for lookup-by-ID patterns.
    """
    def __init__(self, roll_no, name, gpa):
        self.roll_no = roll_no
        self.name    = name
        self.gpa     = gpa

    def __hash__(self):
        # Hash is based ONLY on the immutable identifier
        return hash(self.roll_no)

    def __eq__(self, other):
        # Equality is based ONLY on roll number
        return isinstance(other, Student) and self.roll_no == other.roll_no

    def __repr__(self):
        return f"Student({self.roll_no}, {self.name!r}, GPA={self.gpa})"


s1 = Student(101, "Arjun Sharma",  8.9)
s2 = Student(101, "Arjun S.",      8.9)   # Same roll — name typo corrected
s3 = Student(102, "Meena Pillai",  9.2)

# s1 and s2 are equal (same roll_no)
print(s1 == s2)                    # True
print(hash(s1) == hash(s2))        # True

# Set: s2 is a duplicate of s1 — only one kept
class_roll = {s1, s2, s3}
print(len(class_roll))             # 2 — not 3

# Dict: s2 finds s1's entry
marks = {s1: {"Math": 95, "Science": 88}}
print(marks[s2]["Math"])           # 95 — s2 looks up s1's record

# CRITICAL RULE:
# If a == b  →  hash(a) MUST equal hash(b)
# If hash(a) == hash(b)  →  a and b CAN be unequal (that's a collision)
# If you define __eq__, you MUST define __hash__ too
# Python sets __hash__ = None if you define __eq__ without __hash__
```

## 5. Application 1 — Fast Lookup and Deduplication

The most direct and universal application. Replace every O(n) list scan with an O(1) hash lookup.

### 5.1 The Speed Gap — Measured

```python
import time
import random

N = 1_000_000
data   = list(range(N))
data_s = set(data)

# Pick a target near the end — worst case for list
target = N - 1

# Measure list lookup: O(n)
start     = time.perf_counter()
for _ in range(1000):
    _ = target in data
list_ms   = (time.perf_counter() - start) * 1000

# Measure set lookup: O(1)
start     = time.perf_counter()
for _ in range(1000):
    _ = target in data_s
set_ms    = (time.perf_counter() - start) * 1000

print(f"List (1M elements) : {list_ms:8.2f} ms for 1000 lookups")
print(f"Set  (1M elements) : {set_ms:8.4f} ms for 1000 lookups")
print(f"Set is {list_ms / set_ms:,.0f}x faster")
# Typical output: Set is 50,000x faster
```

### 5.2 Deduplication — Four Patterns

```python
# PATTERN 1: Basic deduplication — order not preserved
data    = [3, 1, 4, 1, 5, 9, 2, 6, 5, 3, 5, 8, 9]
unique  = list(set(data))
print(unique)   # Order unpredictable — [1, 2, 3, 4, 5, 6, 8, 9] in any order

# PATTERN 2: Deduplication — insertion order preserved (Python 3.7+)
unique_ordered = list(dict.fromkeys(data))
print(unique_ordered)   # [3, 1, 4, 5, 9, 2, 6, 8] — first occurrences in order

# PATTERN 3: Deduplication of objects by a field
from collections import defaultdict

transactions = [
    {"id": "T001", "amount": 500, "user": "Alice"},
    {"id": "T002", "amount": 300, "user": "Bob"},
    {"id": "T001", "amount": 500, "user": "Alice"},   # Duplicate
    {"id": "T003", "amount": 700, "user": "Carol"},
    {"id": "T002", "amount": 300, "user": "Bob"},     # Duplicate
]

seen        = set()
unique_txns = []
for txn in transactions:
    if txn["id"] not in seen:         # O(1) set lookup
        seen.add(txn["id"])
        unique_txns.append(txn)

print(f"Before: {len(transactions)}, After: {len(unique_txns)}")
# Before: 5, After: 3

# PATTERN 4: Stream deduplication — real-time, memory-bounded
def dedup_stream(stream, seen=None):
    """Yield only first occurrence of each item in a stream."""
    if seen is None:
        seen = set()
    for item in stream:
        if item not in seen:
            seen.add(item)
            yield item

events = ["login", "click", "login", "purchase", "click", "logout"]
print(list(dedup_stream(events)))
# ["login", "click", "purchase", "logout"]
```

### 5.3 Set Operations — Relational Problems in One Line

```python
# Problem: Given user activity logs from two days,
# find new users, churned users, and retained users

day1_users = {"Alice", "Bob", "Carol", "Diana", "Eve"}
day2_users = {"Bob", "Diana", "Eve", "Frank", "Grace"}

new_users     = day2_users - day1_users          # Joined today
churned       = day1_users - day2_users          # Left after day 1
retained      = day1_users & day2_users          # Present both days
ever_visited  = day1_users | day2_users          # Any day
exclusive     = day1_users ^ day2_users          # Exactly one day

print(f"Ever visited  : {ever_visited}")   # All 7
print(f"Exclusive     : {exclusive}")      # {Alice, Carol, Frank, Grace}

# Retention rate
```

## 6. Application 2 — Frequency Counting

### 6.1 The Progression: From Loop to Counter

```python
# STAGE 1 — naive loop with guard (what beginners write)
text  = "the quick brown fox jumps over the lazy dog the fox"
words = text.split()

freq = {}
for word in words:
    if word not in freq:
        freq[word] = 0
    freq[word] += 1

# STAGE 2 — .get() default (intermediate)
freq = {}
for word in words:
    freq[word] = freq.get(word, 0) + 1

# STAGE 3 — defaultdict (clean)
from collections import defaultdict
freq = defaultdict(int)
for word in words:
    freq[word] += 1

# STAGE 4 — Counter (professional, one line)
from collections import Counter
freq = Counter(words)

print(freq)
# Counter({"the": 3, "fox": 2, "quick": 1, "brown": 1, ...})
print(freq.most_common(3))
# [("the", 3), ("fox", 2), ("quick", 1)]
```

All four produce identical results. Use Stage 4 in production. Use Stage 1 when teaching.

### 6.2 Inverted Index — The Heart of Every Search Engine

```python
from collections import defaultdict

# Corpus of documents
docs = {
    "doc_1": "python is a high level programming language",
    "doc_2": "python is used for machine learning and data science",
    "doc_3": "machine learning requires linear algebra and statistics",
    "doc_4": "data science uses python statistics and visualisation",
    "doc_5": "java and c++ are also high level programming languages",
}

# Build inverted index: word → set of docs containing that word
index = defaultdict(set)
for doc_id, content in docs.items():
    for word in content.lower().split():
        index[word].add(doc_id)

def search(query):
    """
    Multi-keyword AND search.
    Returns docs containing ALL query terms.
    Each term lookup is O(1). Intersection is O(min doc set size).
    """
    terms   = query.lower().split()
    results = None
    for term in terms:
        hits = index.get(term, set())
        results = hits if results is None else results & hits
    return results or set()

print(search("python"))                      # {doc_1, doc_2, doc_4}
print(search("python machine learning"))     # {doc_2}
print(search("statistics python"))           # {doc_2, doc_4}
print(search("java python"))                 # set() — no doc has both
```

### 6.3 Character Frequency — Anagram and Encoding Problems

```python
from collections import Counter

# Anagram check — O(n + m) where n, m are string lengths
def is_anagram(s1, s2):
    return Counter(s1.lower().replace(" ", "")) == Counter(s2.lower().replace(" ", ""))

print(is_anagram("listen", "silent"))           # True
print(is_anagram("Astronomer", "Moon starer"))  # True — spaces removed
print(is_anagram("hello", "world"))             # False

# Find all anagram groups in a word list
from collections import defaultdict

def group_anagrams(words):
    """
    Group words that are anagrams of each other.
    Key insight: sort the characters — anagrams produce identical sorted strings.
    O(n · k log k) where k = max word length.
    """
    groups = defaultdict(list)
    for word in words:
        key = tuple(sorted(word))   # "eat" → ("a","e","t")
        groups[key].append(word)
    return [g for g in groups.values() if len(g) > 1]

words = ["eat", "tea", "tan", "ate", "nat", "bat", "listen", "silent", "enlist"]
for group in group_anagrams(words):
    print(group)
# ["eat", "tea", "ate"]
# ["tan", "nat"]
# ["listen", "silent", "enlist"]
```

## 7. Application 3 — Password Security

This is where hashing leaves data structures entirely and enters cryptography. The requirements are opposite: you want hashing to be **as slow as possible** without breaking usability.

### 7.1 The Three Levels of Password Storage (Worst to Best)

```
LEVEL 1 — Plain Text (catastrophic)
───────────────────────────────────
Database row: alice | password123
Breach impact: Every password exposed instantly.
Used by: Nobody who knows better.

LEVEL 2 — Unsalted Hash (bad)
──────────────────────────────
Database row: alice | 5f4dcc3b5aa765...  (md5("password123"))
Breach impact: Attacker downloads precomputed rainbow table.
               Looks up "5f4dcc3b5aa765..." → "password123". Instant.
Used by: Legacy systems from the 1990s.

LEVEL 3 — Salted, Slow Hash (correct)
──────────────────────────────────────
Database row: alice | $2b$12$randomsalt...hashedvalue...  (bcrypt)
Breach impact: Each password needs individual brute-forcing.
               At 100k iterations: 0.1 seconds per guess.
               10 billion guesses per second GPU → 100k guesses/sec.
               "password123" would take ~8 hours. "xK9!mP2@qR#" → centuries.
Used by: Every responsible system.
```

### 7.2 SHA-256 for Non-Password Hashing

```python
import hashlib

def sha256(text):
    return hashlib.sha256(text.encode("utf-8")).hexdigest()

# Properties
print(sha256("hello"))   # 2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73...
print(sha256("hello"))   # Identical — deterministic
print(sha256("hellp"))   # 9b71d224bd62f3785d96d46ad3ea3d73319bfbc2890caadae2...
                         # ↑ One character different → completely different hash

# Fixed size regardless of input length
print(len(sha256("a")))                    # 64 hex chars = 256 bits
print(len(sha256("a" * 1_000_000)))       # Still 64 hex chars

# Avalanche effect — measure bit difference
def bit_difference(h1, h2):
    """Count differing characters between two hex digests."""
    return sum(c1 != c2 for c1, c2 in zip(h1, h2))

h1 = sha256("hello")
h2 = sha256("hellp")
print(f"Chars different: {bit_difference(h1, h2)} / {len(h1)}")
# Typically 58-62 out of 64 — ~93% of characters differ
```

### 7.3 Proper Password Hashing with PBKDF2

```python
import hashlib
import os
import hmac

def hash_password(password: str) -> bytes:
    """
    Securely hash a password using PBKDF2-HMAC-SHA256.

    What each component does:
    - salt (32 bytes): unique per user, defeats rainbow tables
    - pbkdf2_hmac: Password-Based Key Derivation Function 2
    - sha256: underlying hash algorithm
    - iterations=200_000: 200k rounds — deliberately slow
    """
    salt       = os.urandom(32)          # Cryptographically random — never reuse
    key        = hashlib.pbkdf2_hmac(
        hash_name  = "sha256",
        password   = password.encode("utf-8"),
        salt       = salt,
        iterations = 200_000             # NIST 2023 recommendation
    )
    return salt + key                    # Prepend salt so we can verify later


def verify_password(password: str, stored: bytes) -> bool:
    """
    Verify a password against its stored hash.
    Uses hmac.compare_digest — constant-time comparison prevents timing attacks.
    """
    salt       = stored[:32]
    stored_key = stored[32:]
    candidate  = hashlib.pbkdf2_hmac(
        hash_name  = "sha256",
        password   = password.encode("utf-8"),
        salt       = salt,
        iterations = 200_000
    )
    return hmac.compare_digest(candidate, stored_key)


# Registration
stored_alice = hash_password("MyS3cur3P@ss!")
stored_bob   = hash_password("MyS3cur3P@ss!")    # Same password

# Login verification
print(verify_password("MyS3cur3P@ss!", stored_alice))  # True
print(verify_password("wrongpassword",  stored_alice))  # False
print(verify_password("MyS3cur3P@ss!", stored_bob))    # True

# Critical: same password → DIFFERENT stored values (different salts)
print(stored_alice[:32] == stored_bob[:32])   # False — different salts
print(stored_alice == stored_bob)             # False — different stored values
print("Two users, same password: different stored hashes — ✓ Correct")
```

### 7.4 Why `hmac.compare_digest` Instead of `==`

```python
import hmac
import time

real_hash = "5f4dcc3b5aa765d61d8327deb882cf99"

# TIMING ATTACK: Python's == short-circuits
# "5f4dcc..." vs "aaaaaaaa..." → mismatch at position 0, exits immediately (fast)
# "5f4dcc..." vs "5f4dcc..." → matches all 32 chars, exits at the end (slow)
# An attacker measures response times to guess the hash one character at a time

def insecure_verify(user_input, real):
    return user_input == real          # Returns after first mismatch — LEAKS TIMING

def secure_verify(user_input, real):
    return hmac.compare_digest(        # Always takes same time regardless of match
        user_input.encode(),
        real.encode()
    )

# Demonstrate: insecure verify returns faster on early mismatch
attempts = ["aaaaaaaa" * 4, "5f4dcc3b" + "a" * 24, real_hash]
for attempt in attempts:
    start   = time.perf_counter_ns()
    result  = insecure_verify(attempt, real_hash)
    elapsed = time.perf_counter_ns() - start
    print(f"  {'Match' if result else 'No match':8} | {elapsed:4}ns | {attempt[:16]}...")
# Timing differences (even small) can be exploited statistically by an attacker
```

## 8. Application 4 — File Integrity and Fingerprinting

A hash is a **fingerprint**. Identical files → identical hash. Any change, even one byte → completely different hash. This property makes hashing the universal tool for detecting corruption, verifying downloads, and deduplicating storage.

### 8.1 Verifying a Downloaded File

```python
import hashlib

def sha256_file(filepath: str) -> str:
    """
    Compute SHA-256 of a file.
    Reads in 64KB chunks — works efficiently on files of any size
    without loading the entire file into memory.
    """
    h = hashlib.sha256()
    with open(filepath, "rb") as f:
        while True:
            chunk = f.read(65536)   # 64 KB per read
            if not chunk:
                break
            h.update(chunk)
    return h.hexdigest()


def verify_download(filepath: str, expected_hash: str) -> bool:
    """Verify a downloaded file against its published SHA-256."""
    actual = sha256_file(filepath)
    if actual.lower() == expected_hash.lower():
        print(f"  ✓  File verified: {filepath}")
        return True
    else:
        print(f"  ✗  CORRUPTION DETECTED: {filepath}")
        print(f"     Expected : {expected_hash}")
        print(f"     Got      : {actual}")
        return False


# Usage: publisher posts expected hash alongside download link
# expected = "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"
# verify_download("/tmp/ubuntu-24.04.iso", expected)
```

### 8.2 Directory Snapshot — Detecting Any File Change

```python
def find_duplicate_files(directory: str) -> dict:
    """

            print(f"  {p}  ({size:,} bytes)")
        print(f"  Wasted: {wasted:,} bytes")
```

## 9. Application 5 — Caching and Memoisation

Caching stores the result of an expensive computation so it is never repeated for the same input. The cache key is always the function's arguments — hashed internally by Python's dict.

### 9.1 The Memoisation Pattern — Manual

```python
# WITHOUT memoisation: exponential time O(2ⁿ)
# fib(50) makes ~2²⁵ ≈ 33 million recursive calls
def fib_slow(n):
    if n <= 1:
        return n
    return fib_slow(n - 1) + fib_slow(n - 2)
# fib_slow(40) takes ~30 seconds. fib_slow(100) never finishes.

# WITH memoisation: linear time O(n), each subproblem computed once
_memo = {}

def fib(n):
    if n in _memo:                         # O(1) hash lookup
        return _memo[n]
    if n <= 1:
        return n
    result   = fib(n - 1) + fib(n - 2)
    _memo[n] = result                      # O(1) hash insert
    return result

print(fib(100))    # 354224848179261915075 — computed in microseconds
print(fib(1000))   # Enormous number — still instant
```

### 9.3 HTTP Response Cache with TTL

```python
import time
import hashlib
from functools import wraps

def timed_cache(ttl_seconds: int):
    """
    Decorator: cache function results for `ttl_seconds` seconds.
    After TTL expires, the result is recomputed.
    Cache key = SHA-256 of the function arguments (for stability across runs).
    """
    cache = {}

    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            # Build a stable cache key from arguments
            key_str = str(args) + str(sorted(kwargs.items()))
            key     = hashlib.sha256(key_str.encode()).hexdigest()

            now = time.time()
            if key in cache:
                result, expires_at = cache[key]
                if now < expires_at:
                    print(f"  [CACHE HIT]  {func.__name__}{args}")
                    return result
                else:
                    print(f"  [EXPIRED]    {func.__name__}{args}")

            print(f"  [COMPUTING]  {func.__name__}{args}")
            result       = func(*args, **kwargs)
            cache[key]   = (result, now + ttl_seconds)
            return result

        wrapper.cache_clear = lambda: cache.clear()
        return wrapper
    return decorator


@timed_cache(ttl_seconds=5)
def fetch_exchange_rate(currency_pair: str) -> float:
    """Simulate expensive API call."""
    time.sleep(0.3)
    rates = {"USD/INR": 83.5, "EUR/INR": 91.2, "GBP/INR": 106.8}
    return rates.get(currency_pair, 0.0)


# First calls: computed
print(fetch_exchange_rate("USD/INR"))   # 0.3s — COMPUTING
print(fetch_exchange_rate("USD/INR"))   # Instant — CACHE HIT
print(fetch_exchange_rate("EUR/INR"))   # 0.3s — COMPUTING
print(fetch_exchange_rate("EUR/INR"))   # Instant — CACHE HIT

# After TTL:
time.sleep(6)
print(fetch_exchange_rate("USD/INR"))   # 0.3s — EXPIRED, recomputed
```

## 10. Application 6 — Algorithmic Problem Solving

The most powerful algorithmic use of hashing: converting problems that appear to require O(n²) or O(n log n) into O(n) solutions using hash maps.

### 10.1 The Core Pattern — "Complement Lookup"

```
Naive approach: For every element, scan all remaining elements.
                O(n²) — nested loops.

Hash map approach: For every element, compute what you need,
                   check if it was seen earlier in O(1).
                   O(n) — one pass.

The template:
    seen = {}
    for i, element in enumerate(data):
        what_i_need = f(element, target)
        if what_i_need in seen:
            return answer using seen[what_i_need] and i
        seen[element] = i
```

### 10.2 Two-Sum and Its Family

```python
# ── TWO SUM ─────────────────────────────────────────────────────────────────
def two_sum(nums: list, target: int) -> list:
    """Find indices of two numbers that sum to target. O(n)."""
    seen = {}   # {value: index}
    for i, num in enumerate(nums):
        complement = target - num
        if complement in seen:
            return [seen[complement], i]
        seen[num] = i
    return []

print("Two-Sum:")
print(two_sum([2, 7, 11, 15], 9))    # [0, 1]  — 2+7=9
print(two_sum([3, 2, 4],      6))    # [1, 2]  — 2+4=6


# ── THREE SUM COUNT ──────────────────────────────────────────────────────────
def count_three_sum_zero(nums: list) -> int:
    """Count triplets that sum to zero. O(n²) with hash set."""
    from collections import Counter
    freq   = Counter(nums)
    unique = sorted(set(nums))
    count  = 0
    for i in range(len(unique)):
        for j in range(i + 1, len(unique)):
            a, b = unique[i], unique[j]
            c = -(a + b)
            if c > b and c in freq:
                count += 1
            elif c == b and freq[b] >= 2:
                count += 1
    return count


# ── FOUR SUM COUNT ───────────────────────────────────────────────────────────
def four_sum_count(a, b, c, d) -> int:
    """
    Count tuples (i,j,k,l) where a[i]+b[j]+c[k]+d[l] = 0.
    Key: precompute all a+b sums, then check for -(c+d) in O(1).
    O(n²) instead of O(n⁴).
    """
    from collections import Counter
    ab_sums = Counter(x + y for x in a for y in b)
    return sum(ab_sums[-(x + y)] for x in c for y in d)
```

### 10.3 Prefix Sum + Hash — Subarray Problems

```python
# ── SUBARRAY SUM EQUALS K ────────────────────────────────────────────────────
def subarray_sum_k(nums: list, k: int) -> int:
    """
    Count subarrays whose sum equals k.

    Key insight: prefix[j] - prefix[i] = k
                 ↔ prefix[i] = prefix[j] - k

    For each j, check how many earlier prefix sums equal (current_sum - k).
    O(n) with hash map — vs O(n²) naive double loop.
    """
    from collections import defaultdict
    prefix_count = defaultdict(int)
    prefix_count[0] = 1   # Empty prefix sum of 0 seen once (before any element)

    current_sum = 0
    result      = 0

    for num in nums:
        current_sum += num
        # How many earlier positions have prefix_sum = current_sum - k?
        result      += prefix_count[current_sum - k]   # O(1) lookup
        prefix_count[current_sum] += 1

    return result

print("\nSubarray Sum = k:")
print(subarray_sum_k([1, 1, 1], 2))         # 2  — [1,1] appears twice
print(subarray_sum_k([1, 2, 3], 3))         # 2  — [1,2] and [3]
print(subarray_sum_k([3,-1,2,1,-3,4], 3))   # 4


# ── LONGEST SUBARRAY WITH SUM = 0 ────────────────────────────────────────────
def longest_zero_sum_subarray(nums: list) -> int:
    """
    Find length of longest subarray with sum = 0.
    If prefix[i] == prefix[j], the subarray (i+1..j) has sum 0.
    Store first occurrence of each prefix sum.
    O(n).
    """
    first_seen  = {0: -1}   # prefix_sum → earliest index
    prefix      = 0
    best        = 0

    for i, num in enumerate(nums):
        prefix += num
        if prefix in first_seen:
            best = max(best, i - first_seen[prefix])
        else:
            first_seen[prefix] = i   # Only store FIRST occurrence

    return best

print("\nLongest Zero-Sum Subarray:")
print(longest_zero_sum_subarray([3, -4, 1, -1, 0, 5, -5]))   # 6
print(longest_zero_sum_subarray([1, 2, -2, 3]))               # 2


# ── EQUAL ZEROS AND ONES ─────────────────────────────────────────────────────
def longest_equal_01(binary: list) -> int:
    """
    Longest subarray with equal 0s and 1s.
    Transform: 0 → -1, 1 → 1. Find longest subarray with sum = 0.
    O(n).
    """
    transformed = [1 if b == 1 else -1 for b in binary]
    return longest_zero_sum_subarray(transformed)

print("\nLongest Equal 0s and 1s:")
print(longest_equal_01([0, 1, 0, 0, 1, 1, 0]))   # 6
```

### 10.4 Sliding Window with Hash — Fixed and Variable Size

```python
from collections import defaultdict, Counter

# ── LONGEST SUBSTRING WITHOUT REPEATING CHARACTERS ───────────────────────────
def length_of_longest_unique_substring(s: str) -> int:
    """
    Sliding window + hash map tracking last seen index of each character.
    O(n).
    """
    last_seen = {}
    start     = 0
    best      = 0

    for end, char in enumerate(s):
        if char in last_seen and last_seen[char] >= start:
            start = last_seen[char] + 1   # Shrink window past the duplicate
        last_seen[char] = end
        best = max(best, end - start + 1)

    return best

print("\nLongest Unique Substring:")
print(length_of_longest_unique_substring("abcabcbb"))  # 3 — "abc"
print(length_of_longest_unique_substring("pwwkew"))    # 3 — "wke"
print(length_of_longest_unique_substring("aab"))       # 2 — "ab"


# ── MINIMUM WINDOW SUBSTRING ─────────────────────────────────────────────────
def min_window_substring(s: str, t: str) -> str:
    """
    Find shortest window in s containing all characters of t.
    Sliding window + two Counters. O(|s| + |t|).
    """
    need    = Counter(t)
    window  = defaultdict(int)
    have    = 0
    total   = len(need)
    best    = ""
    left    = 0

    for right, char in enumerate(s):
        window[char] += 1
        if char in need and window[char] == need[char]:
            have += 1

        while have == total:
            # Current window [left..right] contains all of t
            window_str = s[left:right + 1]
            if not best or len(window_str) < len(best):
                best = window_str
            # Shrink from left
            left_char = s[left]
            window[left_char] -= 1
            if left_char in need and window[left_char] < need[left_char]:
                have -= 1
            left += 1

    return best

print("\nMinimum Window Substring:")
print(min_window_substring("ADOBECODEBANC", "ABC"))   # "BANC"
print(min_window_substring("a", "a"))                  # "a"
print(min_window_substring("aa", "aa"))                # "aa"
```

## 11. Application 7 — Consistent Hashing in Distributed Systems

When data must be distributed across multiple servers, naive `hash(key) % num_servers` fails catastrophically when servers are added or removed. Consistent hashing solves this.

### 11.1 The Problem with Naive Hashing

```
Naive:  server_index = hash(key) % num_servers

3 servers:
  "user_1001" → hash % 3 = 2 → Server-C
  "user_2042" → hash % 3 = 0 → Server-A
  "product_5" → hash % 3 = 1 → Server-B

Add a 4th server:
  "user_1001" → hash % 4 = 3 → Server-D  ← MOVED
  "user_2042" → hash % 4 = 2 → Server-C  ← MOVED
  "product_5" → hash % 4 = 0 → Server-A  ← MOVED

Result: ~75% of all keys remapped.
        Every CDN cache entry invalidated.
        All traffic hits origin servers simultaneously.
        Cascading failure.
```

### 11.2 Consistent Hashing — Ring-Based Solution

```python
import hashlib
from bisect import bisect_right, insort

class ConsistentHashRing:
    """
    Distributes keys across servers on a virtual ring (0 to 2^32).

    Algorithm:
    1. Place each server at REPLICAS positions on the ring (virtual nodes)
    2. To find a key's server: hash the key, walk clockwise to nearest server
    3. Adding a server: only keys between new server and its predecessor move
    4. Removing a server: only that server's keys move (to its successor)

    Net effect: adding/removing 1 server remaps only 1/n of all keys.
    """

    REPLICAS = 150   # Virtual nodes per physical server

    def __init__(self):
        self._ring        = []     # Sorted list of hash positions
        self._node_map    = {}     # hash_position → server_name
        self._servers     = set()

    def _hash(self, key: str) -> int:
        """Consistent hash: same output on every machine and every run."""
        return int(hashlib.md5(key.encode()).hexdigest(), 16)

    def add_server(self, server: str):
        """Add a server with REPLICAS virtual nodes."""
        self._servers.add(server)
        for i in range(self.REPLICAS):
            vnode_key = f"{server}#vnode{i}"
            h         = self._hash(vnode_key)
            insort(self._ring, h)
            self._node_map[h] = server
        print(f"  ✚  {server} joined  ({self.REPLICAS} virtual nodes, "
              f"{len(self._servers)} servers total)")

    def remove_server(self, server: str):
        """Remove a server and all its virtual nodes."""
        self._servers.discard(server)
        for i in range(self.REPLICAS):
            vnode_key = f"{server}#vnode{i}"
            h         = self._hash(vnode_key)
            if h in self._node_map:
                self._ring.remove(h)
                del self._node_map[h]
        print(f"  ✖  {server} removed  ({len(self._servers)} servers remaining)")

    def get_server(self, key: str) -> str:
        """Find the server responsible for this key. O(log n)."""
        if not self._ring:
            raise RuntimeError("No servers in ring")
        h   = self._hash(key)
        idx = bisect_right(self._ring, h) % len(self._ring)
        return self._node_map[self._ring[idx]]

    def distribution_report(self, keys: list) -> dict:
        """Show how keys are distributed across servers."""
        from collections import Counter
        return Counter(self.get_server(k) for k in keys)


# ── Demo ─────────────────────────────────────────────────────────────────────
```

## 12. Cryptographic vs Non-Cryptographic Hashing — The Full Picture

This is the most critical conceptual distinction in all of hashing. Using the wrong type causes either catastrophic security failures or severe performance problems.

```
┌─────────────────────────────────┬─────────────────────────────────────────┐
│   NON-CRYPTOGRAPHIC             │   CRYPTOGRAPHIC                         │
│   Python's built-in hash()      │   hashlib: sha256, sha3, pbkdf2         │
├─────────────────────────────────┼─────────────────────────────────────────┤
│ Purpose: Hash table indexing    │ Purpose: Security, integrity, identity  │
│ Speed:   Nanoseconds            │ Speed:   Microseconds to milliseconds   │
│ Security: None                  │ Security: One-way, collision-resistant  │
│ Avalanche: Approximate          │ Avalanche: Guaranteed (~50% bit change) │
│ Seed:    Randomised per process │ Seed:     Deterministic — universal     │
│ Output:  Platform integer       │ Output:   Fixed-size digest (256 bits)  │
│ Reversible: Yes (in principle)  │ Reversible: No — computationally infeas │
└─────────────────────────────────┴─────────────────────────────────────────┘
```

```python

```

**Decision Table — Which Hash to Use:**

| Scenario | Use | Why |
|----------|-----|-----|
| `dict` / `set` key | `hash()` built-in | Speed — nanoseconds, automatic |
| Deduplication | `set()` / `dict.fromkeys()` | `hash()` used internally |
| Cache key (in-process) | `hash(args)` or tuple | Fast; randomisation doesn't matter |
| Cache key (cross-process / on-disk) | `hashlib.sha256()` | Must be stable across runs |
| Password storage | `hashlib.pbkdf2_hmac()` | Slow + salt — essential |
| File integrity check | `hashlib.sha256()` | Deterministic, collision-resistant |
| Digital signature | `hashlib.sha256()` | Industry standard |
| URL deduplication at scale | `hashlib.md5()` *(for speed, not security)* | Fast, non-secret, stable |
| API request signing | `hmac.new(secret, data, sha256)` | Keyed hash — authentication |

```python
def two_sum(nums, target):
    seen = {}
    for i, n in enumerate(nums):
        if target - n in seen:
            return [seen[target - n], i]
        seen[n] = i
    return []

def subarray_sum_k(nums, k):
    prefix_count = defaultdict(int)
    prefix_count[0] = 1
    total = result = 0
    for num in nums:
        total  += num
        result += prefix_count[total - k]
        prefix_count[total] += 1
    return result

def group_anagrams(words):
    groups = defaultdict(list)
    for w in words:
        groups[tuple(sorted(w))].append(w)
    return [g for g in groups.values() if len(g) > 1]

# 7. CONSISTENT HASHING
# ══════════════════════════════════════════════════════════════════════════════

class MiniRing:
    REPLICAS = 100
    def __init__(self):
        self._ring, self._map, self._servers = [], {}, set()
    def _h(self, k):
        return int(hashlib.md5(k.encode()).hexdigest(), 16)
    def add(self, s):
        self._servers.add(s)
        for i in range(self.REPLICAS):
            h = self._h(f"{s}#{i}")
            insort(self._ring, h)
            self._map[h] = s
    def remove(self, s):
        self._servers.discard(s)
        for i in range(self.REPLICAS):
            h = self._h(f"{s}#{i}")
            self._ring.remove(h)
            del self._map[h]
    def get(self, k):
        idx = bisect_right(self._ring, self._h(k)) % len(self._ring)
        return self._map[self._ring[idx]]

def demo_consistent_hashing():
    print("\n── 7. Consistent Hashing ──")

    keys = [f"key_{i}" for i in range(1000)]
    ring = MiniRing()
    for s in ["server-A", "server-B", "server-C"]:
        ring.add(s)

    before = {k: ring.get(k) for k in keys}
    dist   = Counter(before.values())
    print(f"  Distribution (3 servers): {dict(dist)}")

    after  = {k: ring.get(k) for k in keys}
    moved  = sum(1 for k in keys if before[k] != after[k])

    print(f"  Expected ~25%  (1 of 4 servers) — actual: {moved/10:.1f}%")
```

## 14. Common Mistakes

**Mistake 1 — Using `hash()` for security**

```python
# ✗ WRONG — Python's hash() is not cryptographic
stored = hash("mypassword")
# • Reversible with effort
# • No salt — two users with same password get same hash
# • Changes between Python versions and runs

# ✓ CORRECT — use PBKDF2, bcrypt, or argon2
import hashlib, os, hmac
salt   = os.urandom(32)
stored = hashlib.pbkdf2_hmac("sha256", b"mypassword", salt, 200_000)
```

**Mistake 2 — Comparing security hashes with `==` (timing attack)**

```python
# ✗ WRONG — short-circuit comparison leaks timing information
if computed == stored:
    grant_access()

# ✓ CORRECT — constant-time comparison regardless of where mismatch occurs
import hmac
if hmac.compare_digest(computed, stored):
    grant_access()
```

**Mistake 3 — Storing `hash()` output persistently**

```python
# ✗ WRONG — hash() is randomised per-process; useless across runs
cache_key = hash("https://api.example.com/data")
with open("cache_index.json", "w") as f:
    json.dump({str(cache_key): "data"}, f)
# Next run: hash() returns a different value — cache is unreachable

# ✓ CORRECT — use hashlib for stable, cross-process keys
cache_key = hashlib.sha256("https://api.example.com/data".encode()).hexdigest()
```

**Mistake 4 — Using MD5 or SHA-1 for security**

```python
# ✗ WRONG — both are cryptographically broken (collisions found)
h = hashlib.md5(data).hexdigest()    # Broken since 2004
h = hashlib.sha1(data).hexdigest()   # Broken since 2017

# ✓ CORRECT — minimum SHA-256 for any security purpose
h = hashlib.sha256(data).hexdigest()
h = hashlib.sha3_256(data).hexdigest()   # SHA-3: alternative family, also safe
```

**Mistake 5 — Hashing mutable objects with custom `__hash__`**

```python
# ✗ WRONG — __hash__ based on mutable attribute
class Config:
    def __init__(self, name):
        self.name = name
    def __hash__(self):
        return hash(self.name)    # Danger!
    def __eq__(self, other):
        return self.name == other.name

c = Config("prod")
s = {c}
c.name = "staging"          # Mutated after insertion!
print(c in s)               # False — hash changed, object "lost" in set

# ✓ CORRECT — hash only immutable attributes, or freeze the object
class Config:
    def __init__(self, name):
        self._name = name    # "Private" — conventionally not mutated
    @property
    def name(self):
        return self._name
    def __hash__(self):
        return hash(self._name)
    def __eq__(self, other):
        return self._name == other._name
```

**Mistake 6 — Not handling hash collisions in custom hash tables**

```python
# ✗ WRONG — assuming no two keys hash to the same index
class BadHashMap:
    def __init__(self):
        self.buckets = [None] * 8
    def put(self, key, value):
        idx = hash(key) % 8
        self.buckets[idx] = (key, value)   # OVERWRITES on collision!

m = BadHashMap()
m.put("Alice", 95000)
m.put("Charlie", 88000)   # hash("Charlie") % 8 might equal hash("Alice") % 8
                           # If so, Alice's record is silently lost.
# ✓ CORRECT — use chaining (list of pairs) or open addressing at each bucket
```

## 15. Time and Space Complexity

| Operation / Application | Time | Space | Notes |
|------------------------|------|-------|-------|
| `hash(x)` — string of length k | O(k) | O(1) | Each char contributes to hash |
| `hash(x)` — int / float / bool | O(1) | O(1) | Constant-time formula |
| `dict[key]` / `key in set` | O(1) avg, O(n) worst | O(n) | Worst = all keys collide |
| Deduplication with `set` | O(n) | O(n) | One pass, n hash insertions |
| `Counter(iterable)` | O(n) | O(k) | k = unique elements |
| `Counter.most_common(m)` | O(k log m) | O(k) | Uses `heapq.nlargest` |
| Two-sum (hash map) | O(n) | O(n) | vs O(n²) nested loops |
| Subarray sum = k (prefix hash) | O(n) | O(n) | One pass, prefix map |
| Longest unique substring | O(n) | O(min(n, σ)) | σ = alphabet size |
| Group anagrams (n words, len k) | O(n·k log k) | O(n·k) | Sort each word as key |
| `sha256(data of size n)` | O(n) | O(1) | Streaming — constant space |
| PBKDF2 (iter=200k, pw length k) | O(iter·k) | O(1) | Deliberately slow |
| `lru_cache` hit | O(1) | O(maxsize) | Miss = original function cost |
| Consistent hash ring lookup | O(log(r·s)) | O(r·s) | r = replicas, s = servers |
| Add server to consistent ring | O(r log(r·s)) | O(r) | r virtual nodes inserted |
| Inverted index build (n docs) | O(total words) | O(vocabulary) | One pass per document |
| Inverted index AND search | O(k + result) | O(1) | k = number of query terms |

## 17. Summary

| Concept | One-Line Answer |
|---------|----------------|
| `hash(x)` | Non-cryptographic, nanosecond-speed, randomised per process. For `dict`/`set` only. |
| `hashlib.sha256(x)` | Cryptographic, deterministic, collision-resistant. For security and integrity. |
| Avalanche effect | One bit changed → ~50% of output bits change. Makes SHA-256 a fingerprint. |
| Deterministic | Same input → same hash, on every machine, every run (SHA-256 only — not `hash()`). |
| One-way function | You can compute `sha256(password)` but cannot recover `password` from it. |
| Collision | Two different inputs → same hash. Unavoidable; managed by chaining or probing. |
| Collision resistance | For SHA-256: finding two inputs with the same hash requires 2¹²⁸ operations. |
| Salt | `os.urandom(32)` bytes added before hashing a password. Defeats rainbow tables. |
| `hmac.compare_digest` | Constant-time comparison. Prevents timing attacks on hash verification. |
| `PYTHONHASHSEED` | Python randomises `hash()` seed per process. Prevents Hash DoS attacks. |
| Deduplication | `set(items)` — O(n) one pass. The most universal hashing application. |
| Inverted index | `defaultdict(set)`: word → {doc_ids}. Foundation of every search engine. |
| Two-sum pattern | `seen = {}`. For each element: look up complement in O(1). O(n) total. |
| Prefix sum + hash | `prefix_count[0]=1; if prefix-k in map: count+=map[prefix-k]`. Subarray sums in O(n). |
| Memoisation | `@cache`: hash the arguments, store the return value, skip recomputation. |
| Consistent hashing | Virtual ring. Adding one server remaps ~1/n of keys. No cascading invalidation. |
| Non-crypto vs crypto | Use `hash()` for speed inside one process. Use `hashlib` for persistence or security. |
| MD5 / SHA-1 | Cryptographically broken — collisions found. Never use for security. |
| PBKDF2 iterations | Deliberate slowness. 200k iterations → 0.1s per attempt → throttles brute-force. |

Hashing is not one data structure. It is a universal technique that appears at every level of computing — from the nanosecond `dict` lookup that powers every Python variable name to the SHA-256 that secures every HTTPS connection on the internet. It is the reason you can search a billion records in one step, store passwords nobody can steal, trust that a file arrived uncorrupted, and scale a web service across a thousand servers without any of them talking to each other.

Once you see the hash function behind the curtain, you see it everywhere.
