# Queue — List and `collections.deque` Implementations

---

## What a Queue Is

A queue enforces a simple rule: **the first element to arrive is the first to leave**.

This is FIFO — First In, First Out. Elements join at the back (enqueue) and leave from the front (dequeue). No element can skip ahead. No element can be removed from the middle.

```
Enqueue →  [ 10 | 20 | 30 | 40 ]  → Dequeue
               ▲                       ▲
              rear                    front
```

The analogy to a real-world queue is exact. A customer who joins a line first is served first. Anyone who arrives later waits behind everyone already present.

This is in direct contrast to a stack, where the most recently added element is the first to leave. A queue is the patient counterpart to the stack's impatience.

---

## Two Approaches in Python

Python offers two natural ways to implement a queue:

1. **Using `list`** — simple, familiar, but carries a significant hidden cost on one operation.
2. **Using `collections.deque`** — purpose-built for exactly this workload, with O(1) operations at both ends.

Understanding why `list` falls short — and why `deque` solves it — is the real lesson of this topic.

---

## Approach 1 — Queue Using a Python `list`

### The Naive Implementation

The first instinct is to reach for a list: append to the right for enqueue, remove from the left for dequeue.

```python
class QueueUsingList:
    def __init__(self):
        self._data = []

    def enqueue(self, item):
        """Add an item to the rear. O(1) amortised."""
        self._data.append(item)

    def dequeue(self):
        """Remove and return the front item. O(n) — the problem."""
        if self.is_empty():
            raise IndexError("dequeue from an empty queue")
        return self._data.pop(0)

    def front(self):
        """Return the front item without removing it. O(1)."""
        if self.is_empty():
            raise IndexError("front of an empty queue")
        return self._data[0]

    def is_empty(self):
        return len(self._data) == 0

    def __len__(self):
        return len(self._data)

    def __repr__(self):
        return "Queue(front → rear): " + repr(self._data)
```

### The Hidden Cost: Why `pop(0)` Is O(n)

Python lists are backed by a contiguous array. Every element sits at a fixed memory address, and that address is computed from the element's index.

When you call `pop(0)`:
1. The value at index 0 is returned.
2. Every remaining element must shift one position to the left.
3. Element at index 1 moves to index 0, index 2 moves to index 1, and so on.

```
Before pop(0) on [10, 20, 30, 40]:

Index:   0    1    2    3
       ┌────┬────┬────┬────┐
       │ 10 │ 20 │ 30 │ 40 │
       └────┴────┴────┴────┘
         ▲
       Remove this

After — every element shifts left:

Index:   0    1    2
       ┌────┬────┬────┐
       │ 20 │ 30 │ 40 │
       └────┴────┴────┘
```

With n elements in the queue, every dequeue shifts n − 1 elements. That is **O(n) per dequeue** — a cost that grows with queue size.

For a queue of 1,000,000 items, a single dequeue moves 999,999 values in memory. This is not an edge case; it happens on every removal.

### When the List Queue Is Acceptable

The list queue is fine when:
- The queue is **small** (a few hundred elements at most).
- Dequeue operations are **infrequent** relative to enqueues.
- You want the simplest possible code for a quick script.

For any performance-sensitive workload, move to `deque`.

## Approach 2 — Queue Using `collections.deque`

### What `deque` Is

`collections.deque` (pronounced *deck*) stands for **double-ended queue**. It is implemented as a **doubly linked list of fixed-size blocks** — not a single contiguous array.

Because of this structure:
- Appending to the right: **O(1)**
- Removing from the left: **O(1)**
- No shifting. Ever.

This is precisely what a queue needs.

```python
from collections import deque

class Queue:
    def __init__(self):
        self._data = deque()

    def enqueue(self, item):
        """Add an item to the rear. O(1)."""
        self._data.append(item)

    def dequeue(self):
        """Remove and return the front item. O(1)."""
        if self.is_empty():
            raise IndexError("dequeue from an empty queue")
        return self._data.popleft()

    def front(self):
        """Return the front item without removing it. O(1)."""
        if self.is_empty():
            raise IndexError("front of an empty queue")
        return self._data[0]

    def rear(self):
        """Return the rear item without removing it. O(1)."""
        if self.is_empty():
            raise IndexError("rear of an empty queue")
        return self._data[-1]

    def is_empty(self):
        """Return True if the queue has no elements. O(1)."""
        return len(self._data) == 0

    def __len__(self):
        """Return the number of elements. O(1)."""
        return len(self._data)

    def __repr__(self):
        """Display the queue from front to rear. O(n)."""
        return "Queue(front → rear): " + repr(list(self._data))
```

### How `popleft()` Achieves O(1)

In a `deque`, elements are not stored in one flat array. They live in a chain of fixed-size blocks. The structure maintains two pointers:

```
   left_block_ptr                   right_block_ptr
        │                                 │
        ▼                                 ▼
   ┌─────────────┐   ┌─────────────┐   ┌─────────────┐
   │ 10 │ 20 │ 30│──►│ 40 │ 50 │ 60│──►│ 70 │ 80 │   │
   └─────────────┘   └─────────────┘   └─────────────┘
     ▲
   front index within this block
```

`popleft()` advances the front index within the left block. When the block is exhausted, it is released and the pointer moves to the next block. **No element is shifted.** The cost is constant regardless of queue length.

`append()` fills space in the rightmost block. When that block is full, a new block is allocated. Again, **no copying of existing elements**.

## Walkthrough

```python
q = Queue()
print(q.is_empty())    # True

q.enqueue(10)
q.enqueue(20)
q.enqueue(30)

print(q)               # Queue(front → rear): [10, 20, 30]
print(len(q))          # 3
print(q.front())       # 10  — front is unchanged
print(q.rear())        # 30  — rear is unchanged

print(q.dequeue())     # 10  — first in, first out
print(q.dequeue())     # 20
print(q)               # Queue(front → rear): [30]
print(len(q))          # 1

q.enqueue(40)
q.enqueue(50)
print(q)               # Queue(front → rear): [30, 40, 50]

print(q.dequeue())     # 30

try:
    empty_q = Queue()
    empty_q.dequeue()  # Raises IndexError
except IndexError as e:
    print(e)           # dequeue from an empty queue
```

## Practical Patterns

### Pattern 1 — Breadth-First Search (BFS)

BFS explores a graph level by level. The queue ensures that nodes are visited in the order they were discovered — the defining property of BFS. A stack would give DFS instead; the data structure dictates the traversal.

```python
from collections import deque

def bfs(graph, start):
    """Level-order traversal of a graph using a queue."""
    q = Queue()
    visited = set()

    q.enqueue(start)
    visited.add(start)

    order = []
    while not q.is_empty():
        vertex = q.dequeue()
        order.append(vertex)
        for neighbour in graph[vertex]:
            if neighbour not in visited:
                visited.add(neighbour)
                q.enqueue(neighbour)

    return order


graph = {
    "A": ["B", "C"],
    "B": ["A", "D", "E"],
    "C": ["A", "F"],
    "D": ["B"],
    "E": ["B"],
    "F": ["C"],
}

print(bfs(graph, "A"))    # ['A', 'B', 'C', 'D', 'E', 'F']
```

Every node is enqueued when first seen and dequeued when it is time to process it. The queue holds the frontier — all nodes discovered but not yet expanded.

### Pattern 2 — Printer Spooler Simulation

A printer accepts jobs in the order they arrive and prints them in that order. This is exactly FIFO.

```python
class PrinterSpooler:
    def __init__(self, printer_name):
        self.name = printer_name
        self._queue = Queue()
        self._printed = []

    def submit(self, job):
        """Submit a print job to the spooler."""
        self._queue.enqueue(job)
        print(f"[{self.name}] Queued: '{job}'")

    def process_next(self):
        """Print the next job in line."""
        if self._queue.is_empty():
            print(f"[{self.name}] No jobs pending.")
            return
        job = self._queue.dequeue()
        self._printed.append(job)
        print(f"[{self.name}] Printing: '{job}'")

    def process_all(self):
        """Print every queued job in order."""
        while not self._queue.is_empty():
            self.process_next()

    def status(self):
        print(f"[{self.name}] Jobs pending: {len(self._queue)}")


spooler = PrinterSpooler("HP-LaserJet")
spooler.submit("Report_Q3.pdf")
spooler.submit("Invoice_0042.pdf")
spooler.submit("Slides_Final.pdf")
spooler.status()          # Jobs pending: 3

spooler.process_all()
# Printing: 'Report_Q3.pdf'
# Printing: 'Invoice_0042.pdf'
# Printing: 'Slides_Final.pdf'
```

### Pattern 3 — Level-Order Binary Tree Traversal

BFS on a tree visits nodes level by level from root to leaves. The queue holds each level's children, ready to be processed in the order they appear left to right.

```python
class TreeNode:
    def __init__(self, val):
        self.val = val
        self.left = None
        self.right = None


def level_order(root):
    """Return nodes level by level as a list of lists."""
    if root is None:
        return []

    q = Queue()
    q.enqueue(root)
    result = []

    while not q.is_empty():
        level_size = len(q)
        level = []

        for _ in range(level_size):
            node = q.dequeue()
            level.append(node.val)
            if node.left:
                q.enqueue(node.left)
            if node.right:
                q.enqueue(node.right)

        result.append(level)

    return result


#        1
#       / \
#      2   3
#     / \   \
#    4   5   6

root = TreeNode(1)
root.left = TreeNode(2)
root.right = TreeNode(3)
root.left.left = TreeNode(4)
root.left.right = TreeNode(5)
root.right.right = TreeNode(6)

print(level_order(root))
# [[1], [2, 3], [4, 5, 6]]
```

The trick of capturing `level_size = len(q)` before the inner loop is key. It tells you exactly how many nodes belong to the current level, so you can process them without mixing in the children just added.

### Pattern 4 — Sliding Window Maximum

Given a list and window size k, find the maximum value in every window of size k as it slides across the list. A `deque` tracking candidate indices solves this in O(n) — far better than the O(nk) brute-force approach.

```python
from collections import deque

def sliding_window_max(nums, k):
    """
    Return the maximum in each sliding window of size k.
    Uses a deque of indices, maintaining decreasing order of values.
    Time: O(n).  Space: O(k).
    """
    result = []
    dq = deque()    # Stores indices; values in nums are decreasing from front to rear

    for i, val in enumerate(nums):
        # Remove indices outside the window
        while dq and dq[0] < i - k + 1:
            dq.popleft()

        # Remove indices whose values are smaller than the current value —
        # they can never be the maximum while the current element is in the window
        while dq and nums[dq[-1]] < val:
            dq.pop()

        dq.append(i)

        # The window is fully formed once i >= k - 1
        if i >= k - 1:
            result.append(nums[dq[0]])    # Front always holds the max index

    return result


nums = [3, 1, 5, 2, 7, 4, 6, 8]
print(sliding_window_max(nums, k=3))
# [5, 5, 7, 7, 7, 8]
#
# Window [3,1,5] → 5
# Window [1,5,2] → 5
# Window [5,2,7] → 7
# Window [2,7,4] → 7
# Window [7,4,6] → 7
# Window [4,6,8] → 8
```

This pattern uses `deque` directly rather than the `Queue` wrapper because it needs O(1) access to **both ends** simultaneously — appending to the right and discarding from either end depending on the condition.

### Pattern 5 — Task Scheduling with Priority Rotation

A round-robin scheduler assigns CPU time to tasks in a cyclic order. Each task gets a fixed time slice; if it finishes, it is removed. If it needs more time, it is re-enqueued at the rear.

```python
def round_robin_scheduler(tasks, time_slice):
    """
    Simulate round-robin CPU scheduling.
    tasks: list of (name, burst_time) tuples
    time_slice: maximum CPU units per turn
    """
    q = Queue()
    for name, burst in tasks:
        q.enqueue([name, burst])

    time_elapsed = 0

    print(f"{'Time':>6}  {'Task':<12}  {'Remaining'}")
    print("-" * 35)

    while not q.is_empty():
        name, remaining = q.dequeue()
        run_for = min(remaining, time_slice)
        time_elapsed += run_for
        remaining -= run_for

        if remaining > 0:
            q.enqueue([name, remaining])    # Task not finished — back to the rear
            status = f"{remaining} units left"
        else:
            status = "DONE"

        print(f"{time_elapsed:>6}  {name:<12}  {status}")


tasks = [
    ("Process-A", 10),
    ("Process-B", 4),
    ("Process-C", 7),
]

round_robin_scheduler(tasks, time_slice=3)
```

```
  Time  Task          Remaining
-----------------------------------
     3  Process-A     7 units left
     7  Process-B     1 units left
    10  Process-C     4 units left
    13  Process-A     4 units left
    14  Process-B     DONE
    17  Process-C     1 units left
    20  Process-A     1 units left
    21  Process-C     DONE
    22  Process-A     DONE
```

The queue's FIFO ordering guarantees that every process gets its turn in rotation. No process starves while another monopolises the CPU.

## Bounded Queue with `maxlen`

`deque` accepts an optional `maxlen` parameter. When the deque is full and a new item is appended, the **oldest item is automatically discarded** from the opposite end. This creates a fixed-size sliding buffer with no extra bookkeeping.

```python
from collections import deque

class BoundedQueue:
    """A queue that holds at most `capacity` items.
    When full, the oldest item is automatically evicted on enqueue.
    """
    def __init__(self, capacity):
        self._data = deque(maxlen=capacity)
        self.capacity = capacity

    def enqueue(self, item):
        if len(self._data) == self.capacity:
            print(f"  [Evicted: {self._data[0]}]")
        self._data.append(item)

    def dequeue(self):
        if not self._data:
            raise IndexError("dequeue from an empty queue")
        return self._data.popleft()

    def __repr__(self):
        return f"BoundedQueue(cap={self.capacity}): {list(self._data)}"


log_buffer = BoundedQueue(capacity=4)

for event in ["login", "click", "scroll", "purchase", "logout", "search"]:
    log_buffer.enqueue(event)
    print(log_buffer)
```

```
BoundedQueue(cap=4): ['login']
BoundedQueue(cap=4): ['login', 'click']
BoundedQueue(cap=4): ['login', 'click', 'scroll']
BoundedQueue(cap=4): ['login', 'click', 'scroll', 'purchase']
  [Evicted: login]
BoundedQueue(cap=4): ['click', 'scroll', 'purchase', 'logout']
  [Evicted: click]
BoundedQueue(cap=4): ['scroll', 'purchase', 'logout', 'search']
```

Real applications: recent-file lists, rolling log windows, audio/video streaming buffers, sensor data pipelines.

## `list` vs `deque` — The Performance Comparison

| Operation | `list` | `deque` |
|---|---|---|
| `enqueue` (add to rear) | O(1) amortised | O(1) always |
| `dequeue` (remove from front) | **O(n)** — entire array shifts | **O(1)** — pointer advances |
| `front` (peek front) | O(1) | O(1) |
| `rear` (peek rear) | O(1) | O(1) |
| `len()` | O(1) | O(1) |
| Index access (middle element) | O(1) | O(n) |
| Memory layout | Contiguous array — cache-friendly | Linked blocks — less cache-friendly |
| Max capacity | Unbounded (up to memory) | Unbounded, or fixed via `maxlen` |

The single difference that matters in practice: **dequeue is O(n) for `list`, O(1) for `deque`**. Everything else is comparable.

## Common Mistakes

### Mistake 1 — Using `pop(0)` on a List in a Loop

```python
# Wrong — O(n) per iteration → O(n²) total
queue = [1, 2, 3, 4, 5]
while queue:
    item = queue.pop(0)    # Shifts every remaining element
    process(item)
```

For a 10,000-element queue, this performs roughly 50,000,000 element-shift operations. Replace with `deque` and `popleft()` for O(n) total.

```python
# Correct
from collections import deque
queue = deque([1, 2, 3, 4, 5])
while queue:
    item = queue.popleft()    # O(1) every time
    process(item)
```

---

### Mistake 2 — Confusing `append` and `appendleft` Direction

```python
from collections import deque
dq = deque()
dq.append(1)         # Adds to the RIGHT  → [1]
dq.append(2)         # Adds to the RIGHT  → [1, 2]
dq.appendleft(0)     # Adds to the LEFT   → [0, 1, 2]

# For a queue: enqueue = append (right), dequeue = popleft (left)
# Mixing appendleft into an enqueue path corrupts the FIFO order
```

Always enqueue with `append` and dequeue with `popleft` to maintain FIFO.

---

### Mistake 3 — Dequeuing from an Empty Queue

```python
q = Queue()
q.enqueue(42)
print(q.dequeue())    # 42
print(q.dequeue())    # IndexError — queue is empty
```

Always guard dequeue calls:

```python
if not q.is_empty():
    value = q.dequeue()
```

Or handle the exception explicitly:

```python
try:
    value = q.dequeue()
except IndexError:
    value = None
```

---

### Mistake 4 — Using `deque` as a Stack (Wrong End Consistency)

```python
dq = deque()
dq.append(1)      # enqueue to right
dq.append(2)
dq.pop()          # ← Wrong for a queue! This pops from the RIGHT (LIFO, not FIFO)
```

A `deque` can model either a stack or a queue, but not both at once. Pick one discipline and be consistent: **for a queue, always `append` + `popleft`.**

---

### Mistake 5 — Iterating While Dequeuing

```python
q = Queue()
for i in range(5):
    q.enqueue(i)

# Wrong — modifying the queue while iterating its internal deque
for item in q._data:    # Do not do this
    q.dequeue()
```

Either drain the queue with a `while not q.is_empty()` loop, or convert to a list first if you need non-destructive iteration:

```python
# Non-destructive iteration — snapshot first
snapshot = list(q._data)
for item in snapshot:
    print(item)
```

## Complete Implementation

```python
from collections import deque


class Queue:
    def __init__(self):
        self._data = deque()

    def enqueue(self, item):
        """Add item to the rear. O(1)."""
        self._data.append(item)

    def dequeue(self):
        """Remove and return the front item. Raises IndexError if empty. O(1)."""
        if self.is_empty():
            raise IndexError("dequeue from an empty queue")
        return self._data.popleft()

    def front(self):
        """Return the front item without removing it. Raises IndexError if empty. O(1)."""
        if self.is_empty():
            raise IndexError("front of an empty queue")
        return self._data[0]

    def rear(self):
        """Return the rear item without removing it. Raises IndexError if empty. O(1)."""
        if self.is_empty():
            raise IndexError("rear of an empty queue")
        return self._data[-1]

    def is_empty(self):
        """Return True if the queue has no elements. O(1)."""
        return len(self._data) == 0

    def __len__(self):
        """Return the number of elements. O(1)."""
        return len(self._data)

    def __repr__(self):
        """Display the queue from front to rear. O(n)."""
        return "Queue(front → rear): " + repr(list(self._data))
```

## Full Reference

```python
# Instantiation
q = Queue()

# Core operations — all O(1)
q.enqueue(x)      # Add x to the rear
q.dequeue()       # Remove and return the front element
                  # Raises IndexError if empty
q.front()         # Read front element without removing
                  # Raises IndexError if empty
q.rear()          # Read rear element without removing
                  # Raises IndexError if empty
q.is_empty()      # True if the queue has no elements
len(q)            # Number of elements currently in the queue

# Display — O(n)
print(q)          # Queue(front → rear): [front, ..., rear]

# Direct deque usage for performance-critical or two-ended access
from collections import deque
dq = deque()
dq.append(x)          # Enqueue to right  — O(1)
dq.popleft()          # Dequeue from left — O(1)
dq.appendleft(x)      # Add to left       — O(1)  (use for deque, not plain queue)
dq.pop()              # Remove from right — O(1)  (use for deque, not plain queue)
dq.maxlen             # None if unbounded; integer if bounded
deque(iterable, maxlen=k)    # Bounded deque; auto-evicts oldest on overflow
```

## Where This Pattern Appears

**Operating System Scheduling**

The CPU scheduler in every modern OS maintains a run queue. Processes are enqueued when they become ready to run and dequeued when the CPU is available. Round-robin scheduling, as shown in Pattern 5 above, is the textbook policy: fair, starvation-free, and implemented with nothing more than a queue and a clock.

**Network Packet Routing**

Routers buffer incoming packets in queues when a link is congested. Packets are forwarded in the order they arrived. Quality-of-service systems implement multiple queues with different priorities, but each priority level is still a FIFO queue internally.

**Web Server Request Handling**

Incoming HTTP requests are placed in a queue. Worker threads pull from the front. When traffic spikes, the queue absorbs the burst. When workers are fast, the queue drains. The queue decouples the arrival rate from the processing rate.

**BFS in Pathfinding**

Every shortest-path algorithm on an unweighted graph — whether finding the fewest hops across a social network, the minimum number of moves in a puzzle, or the closest hospital in a map — uses BFS. BFS requires a queue. The path found by BFS is guaranteed to be the shortest because nodes are visited in non-decreasing order of distance from the source.

**Producer–Consumer Pipelines**

Data pipelines connect producers (components that generate data) to consumers (components that process it) through a shared queue. The queue is the contract: producers write to the rear, consumers read from the front. Neither side needs to know the other's speed. Python's `queue.Queue` in the standard library is thread-safe version of exactly this structure.

## Summary

| Concept | What It Means |
|---|---|
| FIFO | First In, First Out — the defining rule of a queue |
| `enqueue` | Add to the rear — O(1) with `deque.append` |
| `dequeue` | Remove from the front — O(1) with `deque.popleft`, O(n) with `list.pop(0)` |
| `front` | Read the front element without removing — O(1) |
| `rear` | Read the rear element without removing — O(1) |
| `list` pitfall | `pop(0)` shifts every remaining element — avoid for queues |
| `deque` advantage | O(1) at both ends by design — the right tool for queues |
| `maxlen` | Bounded deque; auto-evicts oldest element when capacity is exceeded |
| BFS connection | A queue is what makes BFS visit nodes level by level |

Use a `list` when the queue is small and convenience matters. Use `collections.deque` whenever dequeue operations appear in any loop, or when the queue may hold more than a few hundred elements. The cost difference between `pop(0)` and `popleft()` is invisible at small scales and catastrophic at large ones.
