# Doubly Linked List – Implementation in Python

---

## The Setup — A Problem Worth Solving

Picture this.

You are listening to music on Spotify. You're three songs deep into a playlist when you realise — that second song was perfect. You want to go back.

With a **Singly Linked List**, you can't. Once you move forward, the past is gone. To get back to that song, you'd have to start the playlist over from the very beginning and walk forward to it again.

That's not how music players work. That's not how browsers work. That's not how text editors work.

All of them let you go **back and forward** with equal ease.

The reason? A **Doubly Linked List**.

---

## What Exactly Is a Doubly Linked List?

A Doubly Linked List is a **chain of nodes** where:
- Each node holds **data**
- Each node holds a **pointer to the next node**
- Each node *also* holds a **pointer to the previous node**
- The first node's `prev` points to **None** — there's nothing before it
- The last node's `next` points to **None** — there's nothing after it
- You always know where the chain **starts** — called the **head**
- You always know where the chain **ends** — called the **tail**

```
         HEAD                                 TAIL
          ↓                                    ↓
None ← [Song A] ⟺ [Song B] ⟺ [Song C] ⟺ [Song D] → None
```

**Doubly** means each node looks in **both directions** — it knows its left neighbour and its right neighbour. It's a two-way street.

This one extra pointer — `prev` — is all that separates a doubly linked list from a singly linked list. But that one pointer changes everything.

---

## Why Not Just Use a Singly Linked List?

You just learned Singly Linked Lists. They're already better than arrays for insertions and deletions. Why go further?

Here's the problem.

In a Singly Linked List, if you are **at node C** and need to delete it, you have no idea who came before it. You have to walk all the way from `head` to find node B — the one *before* C — so you can redirect its pointer. That's **O(n)** just to find the predecessor.

In a Doubly Linked List, node C already knows node B. Node C has a `prev` pointer. Deletion is **O(1)** — no walking required.

| Operation | Singly Linked List | Doubly Linked List |
|---|---|---|
| Insert at beginning | ✅ O(1) | ✅ O(1) |
| Insert at end | ❌ O(n) without tail | ✅ O(1) with tail |
| Delete a node (if you have it) | ❌ O(n) — must find predecessor | ✅ O(1) — `prev` pointer |
| Traverse forward | ✅ O(n) | ✅ O(n) |
| Traverse backward | ❌ Impossible | ✅ O(n) |

The Doubly Linked List pays a small price — one extra pointer per node, a little more memory — and in return gets **bidirectional travel** and **O(1) deletion** at any known node.

---

## The Real-World Example: Your Browser History

Right now, as you read this, your browser is maintaining a Doubly Linked List.

Every tab you've opened has a history. Every page you've visited is a node. Each page knows the page before it and the page after it.

```
None ← [google.com] ⟺ [youtube.com] ⟺ [stackoverflow.com] ⟺ [github.com] → None
                                               ↑
                                          (you are here)
```

- Press **← Back**: `current = current.prev` → move to `youtube.com`
- Press **→ Forward**: `current = current.next` → move back to `stackoverflow.com`
- Type a new URL and navigate: create a **new node**, attach it after current, **discard everything after it** (that's why forward history disappears when you navigate away mid-session)

No arrays. No index searching. Just pointer updates. Instant.

The same pattern appears in:

- **Music players** — previous track / next track buttons
- **Text editors** — Undo/Redo history (each state is a node, Ctrl+Z moves `prev`, Ctrl+Y moves `next`)
- **Photo apps** — left swipe / right swipe through your camera roll
- **LRU Cache** — the most famous interview question in software engineering, built on a DLL
- **Operating system process schedulers** — processes waiting for CPU time stored in a doubly linked queue

## Building the Foundation

First, the **Node** — but this time with three fields instead of two:

```python
class Node:
    def __init__(self, data):
        self.data = data    # The value this node carries
        self.prev = None    # Pointer to the previous node
        self.next = None    # Pointer to the next node
```

Visualised as a box:

```
        ┌──────┬──────────┬──────┐
  None ←│ prev │   data   │ next │→ None
        └──────┴──────────┴──────┘
```

**Why `self.prev = None` at creation?**
A freshly created node is alone. It has no neighbours yet — neither ahead nor behind. Both pointers start as `None` until we explicitly connect the node to a chain.

Now the List itself:

```python
class DoublyLinkedList:
    def __init__(self):
        self.head = None   # Entry point into the list
        self.tail = None   # Exit point — also lets us append in O(1)
```

**Why track both `head` and `tail`?**
`head` lets you enter from the front. `tail` lets you enter from the back — and critically, it lets you **append** a new node in O(1) without walking the entire list to find the end. Without `tail`, every append costs O(n). With it, appending is instant.

---

## Act 1 — Traversal (Walking Both Ways)

Unlike a Singly Linked List, you can walk this chain in **two directions**. Both start from opposite ends.

### Forward — from Head to Tail

```python
def traverse_forward(self):
    current = self.head          # Start at the beginning

    while current is not None:   # Keep going until the chain ends
        print(current.data, end=" ⟶ ")
        current = current.next   # Move forward

    print("None")
```

### Backward — from Tail to Head

```python
def traverse_backward(self):
    current = self.tail          # Start at the END this time

    while current is not None:
        print(current.data, end=" ⟶ ")
        current = current.prev   # Move BACKWARD

    print("None")
```

Let's trace both with a list: `Song A ⟺ Song B ⟺ Song C`

**Forward:** `Song A ⟶ Song B ⟶ Song C ⟶ None`

**Backward:** `Song C ⟶ Song B ⟶ Song A ⟶ None`

The ability to go backwards is the entire point. You couldn't do this with a Singly Linked List.

---

## Act 2 — Insertion

There are **three places** you can insert a new node:
1. At the **beginning** (before the head)
2. At the **end** (after the tail)
3. **After a specific node** (in the middle)

Each one requires careful pointer management. In a Doubly Linked List, every insert touches **four pointers** — two on the new node, two on its neighbours. Miss one, and your backward traversal silently breaks.

---

### Scene 1 — Insert at the End (Append)

A new song is added to the playlist. It goes at the back.

**The logic:**
1. Create a new node
2. Make the new node's `prev` point to the current tail
3. Make the current tail's `next` point to the new node
4. Update `self.tail` to the new node

```python
def append(self, data):
    new_node = Node(data)

    if self.tail is None:          # List is empty — first node ever
        self.head = new_node
        self.tail = new_node
        return

    new_node.prev = self.tail      # New node looks BACK at old tail
    self.tail.next = new_node      # Old tail looks FORWARD to new node
    self.tail = new_node           # Update tail to new node
```

Let's watch this step by step. List before: `[A] ⟺ [B]`, inserting `[C]`:

```
Step 1: Create new_node(C)
        [C | prev=None | next=None]

Step 2: new_node.prev = self.tail
        [C | prev=──► B | next=None]

Step 3: self.tail.next = new_node
        [A] ⟺ [B | next=──► C]

Step 4: self.tail = new_node
        HEAD=[A], TAIL=[C]

Result: None ← [A] ⟺ [B] ⟺ [C] → None
```

**Why steps 2 and 3 before step 4?**
If you update `self.tail` first, you lose the reference to the old last node — and can't set `old_tail.next = new_node` anymore. Always connect the nodes *before* updating the list's tail pointer.

**Time Complexity: O(1)** — No walking. The `tail` pointer takes you straight there.

---

### Scene 2 — Insert at the Beginning (Prepend)

A new song is pinned to the top of the playlist.

**The logic:**
1. Create a new node
2. Make the new node's `next` point to the current head
3. Make the current head's `prev` point to the new node
4. Update `self.head` to the new node

```python
def prepend(self, data):
    new_node = Node(data)

    if self.head is None:          # List is empty
        self.head = new_node
        self.tail = new_node
        return

    new_node.next = self.head      # New node looks FORWARD to old head
    self.head.prev = new_node      # Old head looks BACK at new node
    self.head = new_node           # Update head to new node
```

```
Before: None ← [A] ⟺ [B] ⟺ [C] → None

Insert [Z] at beginning:

Step 2: new_node(Z).next = self.head  →  Z points forward to A
Step 3: self.head.prev = new_node     →  A points backward to Z
Step 4: self.head = new_node          →  Z is the new head

After: None ← [Z] ⟺ [A] ⟺ [B] ⟺ [C] → None
```

**Time Complexity: O(1)** — Just update the head. No matter how long the list, this is always instant.

This is where a Doubly Linked List destroys a Python array. Inserting at the beginning of a Python `list` forces every element to shift one position — O(n). Here, two pointer updates. Done.

---

### Scene 3 — Insert After a Specific Node

A new song is inserted right after your current favourite.

Say the list is `[A] ⟺ [B] ⟺ [D]` and you want to insert `[C]` after `[B]`:

```python
def insert_after(self, target_node, data):
    new_node = Node(data)

    new_node.prev = target_node           # New node looks back at B
    new_node.next = target_node.next      # New node looks forward to D

    if target_node.next is not None:      # If D exists
        target_node.next.prev = new_node  # D looks back at new node

    target_node.next = new_node           # B looks forward to new node

    if target_node == self.tail:          # If we inserted after the tail
        self.tail = new_node              # New node becomes the new tail
```

```
Before: None ← [A] ⟺ [B] ⟺ [D] → None

After: None ← [A] ⟺ [B] ⟺ [C] ⟺ [D] → None
```

**The critical rule:** Always set the **new node's pointers first**, before redirecting the existing nodes. The moment you change `B.next`, you lose access to `D` unless `new_node.next` already points to it.

**Time Complexity: O(1)** — If you already hold the node reference, insertion is instant. This is the DLL's killer feature.

## Act 3 — Deletion

Deletion in a Doubly Linked List is where the `prev` pointer earns its place.

In a Singly Linked List, to delete node C you had to find B first (its predecessor) — which meant walking from `head`. Here, node C already knows B. Deletion is **O(1)** if you hold the node.

---

### Scene 1 — Delete a Specific Node

This is the most powerful deletion — O(1) with a node reference.

**The logic:** Make the node's neighbours point to each other, skipping over the node being deleted.

```python
def delete_node(self, node):
    # Reconnect the left neighbour
    if node.prev is not None:
        node.prev.next = node.next    # Left neighbour points forward past this node
    else:
        self.head = node.next         # Deleting the head — move head forward

    # Reconnect the right neighbour
    if node.next is not None:
        node.next.prev = node.prev    # Right neighbour points backward past this node
    else:
        self.tail = node.prev         # Deleting the tail — move tail backward

    # node is now completely disconnected
    # Python's garbage collector will reclaim it
```

Let's watch `[C]` being removed from `[A] ⟺ [B] ⟺ [C] ⟺ [D]`:

```
node = C
node.prev = B,  node.next = D

Step 1: B.next = D          (B now skips over C, points directly to D)
Step 2: D.prev = B          (D now skips back over C, points directly to B)

C is now orphaned. Nothing points to it. Nobody it points to cares.

Result: None ← [A] ⟺ [B] ⟺ [D] → None
```

Think of it like removing a link from a chain bracelet. You reconnect the two links on either side. The old link simply falls away.

**Time Complexity: O(1)** — No walking. The `prev` and `next` pointers carry all the information needed.

---

### Scene 2 — Delete by Value

If you don't have the node reference, you need to find the node first.

```python
def delete_by_value(self, value):
    if self.head is None:
        print("List is empty")
        return

    current = self.head
    while current is not None:
        if current.data == value:
            self.delete_node(current)   # Reuse our O(1) delete
            return
        current = current.next

    print(f"Value {value} not found")
```

**Why is this cleaner than in a Singly Linked List?**

In a Singly Linked List, you checked `current.next.data` — always staying one step *behind* the target, because you needed its predecessor. In a Doubly Linked List, you walk directly to the matching node and call `delete_node(current)`. Since `current.prev` is already stored inside the node, you don't need to track a separate `previous` variable at all.

**Time Complexity: O(n)** for the search, **O(1)** for the deletion itself.

---

### Scene 3 — Delete at Beginning and End

These are the simplest cases — just call `delete_node` with the right target:

```python
def delete_at_beginning(self):
    if self.head is None:
        print("List is empty")
        return
    self.delete_node(self.head)    # self.head already in hand — O(1)

def delete_at_end(self):
    if self.tail is None:
        print("List is empty")
        return
    self.delete_node(self.tail)    # self.tail already in hand — O(1)
```

Both are **O(1)** — no walking at all.

In a Singly Linked List, deleting the last node required walking to the second-to-last node — O(n). The `tail` pointer and the `prev` pointer together make this problem disappear entirely.

## Putting It All Together — The Complete Class

```python
class Node:
    def __init__(self, data):
        self.data = data
        self.prev = None
        self.next = None

    def __repr__(self):
        return f"Node({self.data})"


class DoublyLinkedList:
    def __init__(self):
        self.head = None
        self.tail = None

    # ── Traversal ───────────────────────────────────────────────
    def traverse_forward(self):
        current = self.head
        while current is not None:
            print(current.data, end=" ⟶ ")
            current = current.next
        print("None")

    def traverse_backward(self):
        current = self.tail
        while current is not None:
            print(current.data, end=" ⟶ ")
            current = current.prev
        print("None")

    # ── Insertion ───────────────────────────────────────────────
    def append(self, data):
        new_node = Node(data)
        if self.tail is None:
            self.head = self.tail = new_node
            return
        new_node.prev = self.tail
        self.tail.next = new_node
        self.tail = new_node

    def prepend(self, data):
        new_node = Node(data)
        if self.head is None:
            self.head = self.tail = new_node
            return
        new_node.next = self.head
        self.head.prev = new_node
        self.head = new_node

    def insert_after(self, target_node, data):
        new_node = Node(data)
        new_node.prev = target_node
        new_node.next = target_node.next
        if target_node.next is not None:
            target_node.next.prev = new_node
        target_node.next = new_node
        if target_node == self.tail:
            self.tail = new_node

    # ── Deletion ────────────────────────────────────────────────
    def delete_node(self, node):
        if node.prev is not None:
            node.prev.next = node.next
        else:
            self.head = node.next

        if node.next is not None:
            node.next.prev = node.prev
        else:
            self.tail = node.prev

    def delete_by_value(self, value):
        current = self.head
        while current is not None:
            if current.data == value:
                self.delete_node(current)
                return
            current = current.next
        print(f"Value {value} not found")

    def delete_at_beginning(self):
        if self.head:
            self.delete_node(self.head)

    def delete_at_end(self):
        if self.tail:
            self.delete_node(self.tail)
```

## The LRU Cache — Where DLL Gets Serious

The **Least Recently Used (LRU) Cache** is the most celebrated real-world application of a Doubly Linked List.

The problem it solves: your computer's RAM is limited. When a program needs to cache data — recently accessed files, database query results, rendered web pages — it can't keep everything. It needs a strategy for deciding *what to throw away* when the cache is full.

The strategy: **evict whatever was accessed least recently**.

The structure: a **HashMap** + **Doubly Linked List**, working together.

```
Most Recently Used                    Least Recently Used
       ↓                                      ↓
[github.com] ⟺ [stackoverflow.com] ⟺ [youtube.com] ⟺ [google.com]
```

- **Access a page?** Move its node to the front — O(1), because `prev` and `next` let you splice it out and reinsert at the head instantly.
- **Cache is full?** Remove the tail — O(1), because you have the `tail` pointer.
- **New page?** Insert at the front via `prepend` — O(1).

Every single one of these operations is O(1). That's why this matters. Without a Doubly Linked List, there's no efficient way to "move a node to the front" — because you need to fix both the left and right neighbours, which requires `prev`.

This is exactly how Python's `functools.lru_cache` decorator works under the hood. Every time you decorate a function with `@lru_cache`, Python builds one of these.

## Common Mistakes That Will Break Your Code

### Mistake 1 — Forgetting to Update Both `prev` and `next`

```python
# Wrong — only half the work done
new_node.next = self.head     # ✅ new_node points forward to old head
# self.head.prev = new_node   # ❌ forgot this — head doesn't know who came before it

# Backward traversal is now broken. Silently. Good luck debugging.
```

Every insertion in a DLL touches **four pointers**. Write all four. Every time.

---

### Mistake 2 — Updating the List Pointer Too Early

```python
# Wrong order — you just lost the old tail
self.tail = new_node           # ❌ tail updated too early
new_node.prev = self.tail      # self.tail IS new_node now — it points to itself!
```

```python
# Correct order — connect the node FIRST, update the list pointer LAST
new_node.prev = self.tail      # ✅ new node connects to old tail
self.tail.next = new_node      # ✅ old tail connects to new node
self.tail = new_node           # ✅ NOW update the tail
```

The rule: **connect before you update**. The moment you overwrite `self.head` or `self.tail`, you lose what it was pointing to.

---

### Mistake 3 — Not Handling the Empty List Case

A Doubly Linked List has two sentinel pointers — `head` and `tail`. When the list is empty, both must be `None`. When you insert into an empty list, both must be set to the new node. Forget either one, and operations will fail in ways that are hard to trace.

```python
# Always check for this:
if self.head is None:
    self.head = new_node
    self.tail = new_node   # Don't forget tail!
    return
```

## Time Complexity — The Full Picture

| Operation | Time Complexity | Why |
|---|---|---|
| Append (insert at end) | **O(1)** | `tail` pointer — no walking |
| Prepend (insert at front) | **O(1)** | `head` pointer — no walking |
| Insert after known node | **O(1)** | `prev` and `next` handle it immediately |
| Delete known node | **O(1)** | `prev` and `next` — no walking needed |
| Delete at beginning | **O(1)** | `head` pointer |
| Delete at end | **O(1)** | `tail` pointer |
| Delete by value | **O(n)** | Must walk to find it first |
| Traverse forward | **O(n)** | Visit every node |
| Traverse backward | **O(n)** | Visit every node in reverse |
| Access by index | **O(n)** | No direct jump — must walk |

**The golden insight:**
Everything is O(1) **if you have the node**. The only time you pay O(n) is when you have to *search*. Hold onto your node references, and a Doubly Linked List is blindingly fast.

## The Mental Model to Carry Forward

```
         HEAD                                   TAIL
          ↓                                      ↓
  None ← [A] ⟺ [B] ⟺ [C] ⟺ [D] → None

Rules:
  head.prev  is always None
  tail.next  is always None

  Every node knows its left neighbour  (prev)
  Every node knows its right neighbour (next)

Insertion:  Set the new node's pointers FIRST. Update head/tail LAST.
Deletion:   Reconnect neighbours to each other. Update head/tail if at the edges.
```

## What Comes After the Doubly Linked List?

The DLL is a building block, not a destination. Here is where it leads:

```
Doubly Linked List
 │
 ├──► Circular Doubly Linked List   (tail.next = head, head.prev = tail)
 │
 ├──► Deque (Double-Ended Queue)    (Python's collections.deque IS a DLL internally)
 │
 ├──► LRU Cache                     (DLL + HashMap — used in browsers, OS, databases)
 │
 ├──► Text Editor Buffer            (the "piece table" structure used in VS Code is a DLL variant)
 │
 └──► Skip List                     (a probabilistic structure built on layered linked lists)
```

Every one of these is, at its core, just **nodes pointing to other nodes in both directions**.

## Summary

| Concept | What It Means |
|---|---|
| `self.prev` | Look backward — know who came before |
| `self.next` | Look forward — know who comes after |
| `self.head` | Entry point into the list |
| `self.tail` | Exit point — also makes `append` O(1) |
| Why DLL over SLL | O(1) deletion at any known node; backward traversal |
| Why DLL over array | O(1) insert/delete at front and back; no shifting |
| Browser history | Each page is a node; Back = `prev`, Forward = `next` |
| LRU Cache | DLL + HashMap = O(1) access, O(1) eviction |

The Doubly Linked List is the first data structure where you feel genuine elegance. Every pointer has a reason. Every operation has a clear logic. The `prev` pointer isn't just an extra variable — it's the key that unlocks O(1) deletion, backward traversal, and some of the most important algorithms in computer science.

Once you understand *why* each pointer exists, the entire structure clicks into place — and every advanced topic that builds on it becomes obvious rather than mysterious.
