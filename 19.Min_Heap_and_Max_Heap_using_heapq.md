# Min-Heap and Max-Heap — Priority Queues using `heapq` in Python

---

## 1. Introduction

The company has a crisis.

Five urgent tasks have landed on the CEO's desk simultaneously:

- Fix a **critical server outage** affecting all customers
- Respond to a **board member's email**
- Review a **junior developer's pull request**
- Attend a **routine weekly standup**
- Sign off on a **salary increment form**

The CEO cannot work on all five at once. But picking randomly is reckless. The correct approach is to always work on the **most urgent task first** — and the moment that is done, move to the next most urgent.

The naive approach: keep all tasks in a list, scan the entire list every time to find the highest priority one. Five tasks? Manageable. Five hundred tasks? The CEO wastes more time searching for the next task than actually doing the work.

Before accepting this as inevitable, let us be honest and try every data structure you already know.

**Array / Python List** stores all tasks in a flat sequence. To always get the most urgent, you scan every element each time — O(n) per extraction. Inserting a new urgent task does not automatically place it at the front. You would need to re-sort the entire list after every single insertion.

**Stack** gives you the most recently added task — not the most urgent one. If a critical outage arrives after a routine standup was pushed, the standup comes out first. A stack has no concept of priority at all.

**Queue** gives you the task that waited the longest — first in, first out. Again, no concept of urgency. A routine form submitted yesterday comes out before a critical outage reported just now.

**Singly Linked List** lets you maintain a sorted order, but inserting a new task in the correct priority position requires scanning from the head every time — O(n) insertion. And extracting the top priority still requires traversal unless you maintain a dedicated head pointer.

**Binary Search Tree** can maintain sorted order and gives O(log n) insertion and minimum extraction — but it requires careful balancing. An unbalanced BST degrades to O(n). It also carries the overhead of two child pointers and no guarantee of shape.

**The common failure:** none of these structures are purpose-built for the single operation that matters most here — *"always give me the most urgent item, and let me insert new items efficiently."*

This is exactly the gap the **Heap** was designed to fill.

A **Heap** is a specialised binary tree where the most important element is always sitting at the top — like the most urgent task always on top of the CEO's desk — and every insertion or extraction takes at most **O(log n)** time, guaranteed.

---

## 2. Real-World Applications

The CEO's task priority desk is not just an analogy — it is exactly how operating systems, networks, and databases work internally.

**Operating System Process Scheduler**

The OS has hundreds of processes competing for CPU time. It uses a Min-Heap of process priorities — the most critical process (lowest priority number) always runs next. Every time a process finishes, the heap extracts the minimum and the next most critical process begins.

**Hospital Emergency Room**

Patients do not wait in the order they arrive. A cardiac arrest patient jumps the queue over a sprained ankle. The ER uses a priority queue (Min-Heap on severity score) — severity 1 always treated before severity 5, regardless of arrival time.

**Dijkstra's Shortest Path Algorithm**

GPS navigation finds the shortest route between two locations. At each step it asks: *"which unvisited city has the shortest known distance so far?"* This is a Min-Heap extraction — and it happens thousands of times per route calculation.

**Task Scheduling in Companies**

Project management tools like Jira and Asana rank tasks by priority. The build pipeline always runs the highest-priority ticket first. Under the hood: a heap.

**Python's `heapq` Module**

Python ships with a built-in heap module. You do not need to implement a heap from scratch. `heapq` gives you a Min-Heap on any Python list — ready to use in one import.

## 3. Key Terminology

| Term | Meaning in CEO Priority Context |
|------|--------------------------------|
| **Heap** | A complete binary tree satisfying the heap property at every node |
| **Min-Heap** | Parent's priority number ≤ children's priority numbers — lowest number = highest urgency at the top |
| **Max-Heap** | Parent's priority number ≥ children's priority numbers — highest number = highest urgency at the top |
| **Heap Property** | The rule that must hold at every node — parent is always ≤ (Min) or ≥ (Max) its children |
| **Complete Binary Tree** | Every level is fully filled except possibly the last, which fills left to right |
| **Root** | The top of the heap — always the minimum (Min-Heap) or maximum (Max-Heap) element |
| **Heapify** | The process of rearranging elements to restore the heap property after insertion or extraction |
| **`heappush`** | Insert a new task — O(log n) |
| **`heappop`** | Extract the most urgent task — O(log n) |

## 4. The Two Types of Heap

### 4.1 Min-Heap — Lowest Number Has Highest Priority

In a Min-Heap, the **smallest value always sits at the root**. Every parent is smaller than or equal to both its children.

Think of it as the CEO's urgency desk where tasks are numbered by urgency level — **1 is most urgent, 10 is least urgent**. The task numbered `1` always stays on top.

```
Urgency levels: 1=Critical, 3=High, 5=Medium, 7=Low, 9=Routine

                        [ 1 ]             ← Most urgent (root)
                       /     \
                    [ 3 ]   [ 5 ]
                   /    \
                [ 7 ]  [ 9 ]

Heap Property check:
  1 ≤ 3 ✓    1 ≤ 5 ✓
  3 ≤ 7 ✓    3 ≤ 9 ✓
```

Every parent is smaller than its children. The minimum is always at the root — instantly accessible.

### 4.2 Max-Heap — Highest Number Has Highest Priority

In a Max-Heap, the **largest value always sits at the root**. Every parent is greater than or equal to both its children.

Think of it as the CEO's salary review desk — employees are ranked by salary (in thousands). The **highest earner** is reviewed first.

```
Salaries (in thousands): 95, 80, 70, 60, 50

                        [ 95 ]            ← Highest salary (root)
                       /      \
                   [ 80 ]    [ 70 ]
                   /    \
               [ 60 ]  [ 50 ]

Heap Property check:
  95 ≥ 80 ✓    95 ≥ 70 ✓
  80 ≥ 60 ✓    80 ≥ 50 ✓
```

Every parent is larger than its children. The maximum is always at the root.

## 5. The Complete Binary Tree Property

A heap is not just any binary tree. It must be a **complete binary tree** — every level is fully filled from left to right, with no gaps.

```
VALID Heap (complete):           INVALID Heap (not complete):
        [ 1 ]                            [ 1 ]
       /     \                          /     \
    [ 3 ]   [ 5 ]                    [ 3 ]   [ 5 ]
    /   \                                \
 [ 7 ] [ 9 ]                            [ 9 ]
                                   ↑ Gap on the left — violates completeness
```

Why does this matter? The complete binary tree property guarantees that a heap of `n` elements always has height **⌊log₂ n⌋**. That height bound is what makes every operation O(log n) — always, without the risk of skewing that plagues BSTs.

## 6. How `heapq` Works in Python

Python's `heapq` module implements a **Min-Heap** on a regular Python list. The list itself is the heap — `heapq` maintains the heap property by rearranging elements on every push and pop.

```python
import heapq

heap = []                    # Start with an empty list — this IS the heap
heapq.heappush(heap, value)  # Insert a value, heap property maintained
heapq.heappop(heap)          # Remove and return the smallest value
heap[0]                      # Peek at the smallest without removing
heapq.heapify(list)          # Convert any list into a heap in-place — O(n)
```

**Important:** `heapq` always gives you a **Min-Heap**. For a Max-Heap, you negate the values on insert and negate again on extraction (covered in Section 9).

## 7. Min-Heap — CEO Task Priority Desk

### 7.1 The Setup

The CEO assigns each task an urgency number. Lower number = more urgent.

```
Task                          Urgency
─────────────────────────────────────
Critical server outage           1
Board member email               3
Sprint planning meeting          5
Pull request review              7
Salary increment form            9
```

### 7.2 Building the Min-Heap Step by Step

```python
import heapq

# Each entry: (urgency_number, task_name)
task_desk = []

heapq.heappush(task_desk, (5, "Sprint planning meeting"))
heapq.heappush(task_desk, (1, "Critical server outage"))
heapq.heappush(task_desk, (9, "Salary increment form"))
heapq.heappush(task_desk, (3, "Board member email"))
heapq.heappush(task_desk, (7, "Pull request review"))
```

Watch the heap reshape itself after each push:

```
Push (5, Sprint planning):
        [ 5 ]

Push (1, Server outage):
        [ 5 ]
        /
     [ 1 ]
  → 1 < 5, swap upward (heapify up)
        [ 1 ]
        /
     [ 5 ]

Push (9, Salary form):
        [ 1 ]
       /     \
    [ 5 ]   [ 9 ]
  → 9 > 1, no swap needed ✓

Push (3, Board email):
        [ 1 ]
       /     \
    [ 5 ]   [ 9 ]
    /
 [ 3 ]
  → 3 < 5, swap upward
        [ 1 ]
       /     \
    [ 3 ]   [ 9 ]
    /
 [ 5 ]
  → 3 > 1, stop ✓

Push (7, PR review):
        [ 1 ]
       /     \
    [ 3 ]   [ 9 ]
    /   \
 [ 5 ] [ 7 ]
  → 7 > 3, no swap needed ✓

Final Min-Heap:
                    [ 1 - Server Outage ]        ← Most urgent, always on top
                   /                    \
     [ 3 - Board Email ]       [ 9 - Salary Form ]
      /            \
[ 5 - Sprint ]  [ 7 - PR Review ]
```

### 7.3 CEO Works Through Tasks — Extracting the Most Urgent

```python
print("CEO's Task Order (Most Urgent First):\n")

while task_desk:
    urgency, task = heapq.heappop(task_desk)
    print(f"  [{urgency}] {task}")
```

**Output:**

```
CEO's Task Order (Most Urgent First):

  [1] Critical server outage
  [3] Board member email
  [5] Sprint planning meeting
  [7] Pull request review
  [9] Salary increment form
```

No matter the order tasks were pushed, the CEO always works on the most urgent one next. The heap guarantees this every single time.

### 7.4 What Happens Inside `heappop`

When the root (most urgent task) is extracted, the heap must reorganise itself to place the next most urgent task at the top. This is called **heapify down**.

```
Pop [ 1 - Server Outage ]:

Step 1: Move the last element (7 - PR Review) to the root temporarily
        [ 7 ]
       /     \
    [ 3 ]   [ 9 ]
    /
 [ 5 ]

Step 2: Heapify down — swap 7 with its smallest child (3)
        [ 3 ]
       /     \
    [ 7 ]   [ 9 ]
    /
 [ 5 ]

Step 3: 7 > 5, swap again
        [ 3 ]
       /     \
    [ 5 ]   [ 9 ]
    /
 [ 7 ]

Step 4: 7 has no children — heap property restored ✓
Next most urgent: Board member email (3) is now at the root
```

### 7.5 Numerical Example — Pure Numbers

```python
import heapq

numbers = [40, 10, 30, 50, 20]
heap = []

for n in numbers:
    heapq.heappush(heap, n)

print("Heap list (internal):", heap)
# Output: [10, 20, 30, 50, 40]
# The list is NOT fully sorted — but heap[0] is always the minimum

print("\nExtracting in sorted order:")
while heap:
    print(heapq.heappop(heap), end="  ")
# Output: 10  20  30  40  50
```

**Key insight:** The heap list `[10, 20, 30, 50, 40]` is not sorted — but `heap[0]` is always `10` (the minimum). The internal arrangement satisfies only the heap property, not full sorted order. Yet popping repeatedly produces sorted output — this is the basis of **Heap Sort**.

## 8. `heapify` — Instant Heap from Existing List

Instead of pushing one by one, `heapify` converts an entire existing list into a heap in **O(n)** time — faster than pushing n elements one by one (which costs O(n log n)).

```python
import heapq

# CEO receives a batch of pending tasks all at once
pending_tasks = [
    (7, "Pull request review"),
    (1, "Critical server outage"),
    (5, "Sprint planning meeting"),
    (9, "Salary increment form"),
    (3, "Board member email"),
]

heapq.heapify(pending_tasks)       # Convert list to heap in-place — O(n)

print("Most urgent task right now:", pending_tasks[0])
# Output: (1, 'Critical server outage')
```

**Numerical example:**

```python
numbers = [64, 25, 12, 22, 11]
heapq.heapify(numbers)
print(numbers)          # [11, 22, 12, 64, 25]
print(numbers[0])       # 11 — always the minimum, instantly accessible
```

## 9. Max-Heap — Highest Salary Review First

Python's `heapq` only supports Min-Heap natively. To get a **Max-Heap**, negate every value on insertion and negate again on extraction. The Min-Heap of negatives behaves exactly like a Max-Heap of positives.

### 9.1 CEO's Salary Review — Highest Earner First

The CEO reviews employees starting from the highest salary.

```
Employee      Salary (₹ thousands)
─────────────────────────────────
Alice              95
Bob                80
Charlie            70
Diana              60
Eve                50
```

```python
import heapq

salary_review = []

employees = [
    ("Alice",   95),
    ("Bob",     80),
    ("Charlie", 70),
    ("Diana",   60),
    ("Eve",     50),
]

# Negate salary to simulate Max-Heap
for name, salary in employees:
    heapq.heappush(salary_review, (-salary, name))

print("CEO's Salary Review Order (Highest First):\n")
while salary_review:
    neg_salary, name = heapq.heappop(salary_review)
    print(f"  ₹{-neg_salary}k — {name}")
```

**Output:**

```
CEO's Salary Review Order (Highest First):

  ₹95k — Alice
  ₹80k — Bob
  ₹70k — Charlie
  ₹60k — Diana
  ₹50k — Eve
```

### 9.2 Numerical Max-Heap Example

```python
import heapq

numbers = [40, 10, 30, 50, 20]
max_heap = []

for n in numbers:
    heapq.heappush(max_heap, -n)      # Push negated values

print("Max-Heap internal:", [-x for x in max_heap])
# Output: [50, 40, 30, 10, 20]   ← heap[0] is 50 (maximum)

print("\nExtracting largest first:")
while max_heap:
    print(-heapq.heappop(max_heap), end="  ")
# Output: 50  40  30  20  10
```

## 10. Peeking at the Top Without Removing

Sometimes the CEO wants to see what the most urgent task is — without actually starting it yet.

```python
import heapq

task_desk = []
heapq.heappush(task_desk, (1, "Critical server outage"))
heapq.heappush(task_desk, (3, "Board member email"))
heapq.heappush(task_desk, (5, "Sprint planning meeting"))

# Peek — O(1), does NOT remove the element
most_urgent = task_desk[0]
print("Most urgent right now:", most_urgent)
# Output: (1, 'Critical server outage')

print("Heap unchanged — size still:", len(task_desk))   # 3
```

`heap[0]` is always the minimum in a Min-Heap and costs O(1) — no extraction, no reorganisation, no side effects.

## 11. Adding a New Urgent Task Mid-Session

The CEO is working through tasks when a **new critical issue** arrives. The heap absorbs it instantly and places it at the top if it is the most urgent.

```python
import heapq

task_desk = []
heapq.heappush(task_desk, (3, "Board member email"))
heapq.heappush(task_desk, (5, "Sprint planning meeting"))
heapq.heappush(task_desk, (7, "Pull request review"))

print("Before new task — top:", task_desk[0])
# Output: (3, 'Board member email')

# New critical task arrives mid-session
heapq.heappush(task_desk, (1, "CRITICAL: Production database down"))

print("After new task  — top:", task_desk[0])
# Output: (1, 'CRITICAL: Production database down')
```

The heap reshuffled in O(log n) time and the new critical task is now at the top. A sorted list would have needed O(n) to find the insertion point and shift everything after it.

## 12. `nlargest` and `nsmallest` — Without Destroying the Heap

HR wants to see the **top 3 most urgent tasks** without processing them. Or the **3 least urgent** tasks for deferral planning.

```python
import heapq

task_desk = [
    (1, "Critical server outage"),
    (3, "Board member email"),
    (5, "Sprint planning meeting"),
    (7, "Pull request review"),
    (9, "Salary increment form"),
]
heapq.heapify(task_desk)

# Top 3 most urgent (smallest urgency numbers)
top3 = heapq.nsmallest(3, task_desk)
print("Top 3 urgent tasks:")
for urgency, task in top3:
    print(f"  [{urgency}] {task}")

# 3 least urgent (largest urgency numbers)
bottom3 = heapq.nlargest(3, task_desk)
print("\n3 least urgent tasks:")
for urgency, task in bottom3:
    print(f"  [{urgency}] {task}")
```

**Output:**

```
Top 3 urgent tasks:
  [1] Critical server outage
  [3] Board member email
  [5] Sprint planning meeting

3 least urgent tasks:
  [9] Salary increment form
  [7] Pull request review
  [5] Sprint planning meeting
```

The heap is **not modified** — `nsmallest` and `nlargest` read without extracting.

**Numerical example:**

```python
numbers = [40, 10, 30, 50, 20, 60, 15]
print(heapq.nsmallest(3, numbers))   # [10, 15, 20]
print(heapq.nlargest(3, numbers))    # [60, 50, 40]
```

## 13. Why Other Structures Failed — And Why Heap Wins

| Structure | Insert | Get Most Urgent | Verdict |
|-----------|--------|-----------------|---------|
| Unsorted List | O(1) | O(n) scan every time | Too slow to find urgent task |
| Sorted List | O(n) shift | O(1) | Too slow to add new tasks |
| Stack | O(1) | Not possible — LIFO | Wrong structure entirely |
| Queue | O(1) | Not possible — FIFO | Wrong structure entirely |
| BST (balanced) | O(log n) | O(log n) | Works, but no shape guarantee |
| **Min-Heap** | **O(log n)** | **O(log n)** | **Purpose-built. Always balanced. Always correct.** |

The heap wins because it makes **one deliberate trade-off**: it does not maintain full sorted order (like a sorted list), but it guarantees that the minimum (or maximum) is always at the root. That partial order is all you need for a priority queue — and it costs far less to maintain than full sorted order.

## 14. Complete Program

```python
import heapq


# ── Min-Heap: CEO Task Priority Desk ──────────────────────────

print("=" * 50)
print("  MIN-HEAP — CEO Task Priority Desk")
print("=" * 50)

task_desk = []

tasks = [
    (5, "Sprint planning meeting"),
    (1, "Critical server outage"),
    (9, "Salary increment form"),
    (3, "Board member email"),
    (7, "Pull request review"),
]

for urgency, task in tasks:
    heapq.heappush(task_desk, (urgency, task))
    print(f"  Pushed [{urgency}] {task}  →  Top: {task_desk[0][1]}")

print("\nCEO works through tasks (most urgent first):\n")
while task_desk:
    urgency, task = heapq.heappop(task_desk)
    print(f"  ✓ [{urgency}] {task}")


# ── Max-Heap: CEO Salary Review Desk ──────────────────────────

print("\n" + "=" * 50)
print("  MAX-HEAP — CEO Salary Review Desk")
print("=" * 50)

salary_review = []

employees = [
    ("Alice",   95),
    ("Bob",     80),
    ("Charlie", 70),
    ("Diana",   60),
    ("Eve",     50),
]

for name, salary in employees:
    heapq.heappush(salary_review, (-salary, name))

print("\nCEO reviews by salary (highest first):\n")
while salary_review:
    neg_salary, name = heapq.heappop(salary_review)
    print(f"  ✓ ₹{-neg_salary}k — {name}")


# ── heapify: Batch of Numbers ──────────────────────────────────

print("\n" + "=" * 50)
print("  HEAPIFY — Numerical Example")
print("=" * 50)

numbers = [64, 25, 12, 22, 11]
print(f"\nOriginal list : {numbers}")
heapq.heapify(numbers)
print(f"After heapify : {numbers}")
print(f"Minimum (root): {numbers[0]}")

print("\nExtracting in ascending order:")
temp = numbers[:]
result = []
while temp:
    result.append(heapq.heappop(temp))
print(" ", result)


# ── nsmallest / nlargest ───────────────────────────────────────

print("\n" + "=" * 50)
print("  NSMALLEST / NLARGEST")
print("=" * 50)

scores = [88, 45, 72, 95, 60, 33, 81]
print(f"\nScores: {scores}")
print(f"Top 3 highest : {heapq.nlargest(3, scores)}")
print(f"Top 3 lowest  : {heapq.nsmallest(3, scores)}")
```

## 15. Time and Space Complexity

| Operation | Time | Notes |
|-----------|------|-------|
| `heappush` | O(log n) | Heapify up — at most log n swaps |
| `heappop` | O(log n) | Heapify down — at most log n swaps |
| `heap[0]` (peek) | O(1) | Root is always index 0 |
| `heapify` | O(n) | Build heap from existing list |
| `nsmallest(k, ...)` | O(n log k) | Scans all, keeps k smallest |
| `nlargest(k, ...)` | O(n log k) | Scans all, keeps k largest |
| **Space** | O(n) | Heap stored as a flat list |

## 16. Common Mistakes

**Mistake 1 — Treating the heap list as a sorted list**

```python
heapq.heapify([5, 3, 1, 4, 2])
# Result: [1, 2, 1, 4, 3]  ← NOT fully sorted
# heap[0] is always the minimum, but heap[1] may not be the second smallest
# Only pop() guarantees sorted extraction — do not index directly beyond heap[0]
```

**Mistake 2 — Forgetting to negate for Max-Heap**

```python
# Wrong — still behaves as Min-Heap
heapq.heappush(max_heap, salary)

# Correct — negate on push, negate again on pop
heapq.heappush(max_heap, -salary)
actual_salary = -heapq.heappop(max_heap)
```

**Mistake 3 — Modifying the heap list directly**

```python
heap.append(value)      # Wrong — breaks heap property silently
heapq.heappush(heap, value)   # Correct — maintains heap property
```

**Mistake 4 — Using `heapify` after direct append**

```python
heap.append(new_value)
heapq.heapify(heap)     # Works but costs O(n) every time
                        # Use heappush instead — costs O(log n)
```

## 18. Summary

| Concept | Meaning in CEO Context |
|---------|----------------------|
| Min-Heap | Lowest urgency number always at the top — most critical task first |
| Max-Heap | Highest value always at the top — negate values in Python's `heapq` |
| Heap Property | Every parent ≤ children (Min) or ≥ children (Max) at every node |
| Complete Binary Tree | No gaps — guarantees height = O(log n) always |
| `heappush` | New task joins the desk — O(log n) |
| `heappop` | CEO completes the top task, next most urgent rises — O(log n) |
| `heap[0]` | Peek at the most urgent without removing — O(1) |
| `heapify` | Convert entire pending task list to heap at once — O(n) |
| `nsmallest(k)` | Top k most urgent tasks without extracting — O(n log k) |
| `nlargest(k)` | Top k least urgent tasks without extracting — O(n log k) |
| Max-Heap trick | Push `-value`, pop and negate back |

The Heap is not the most complex data structure — it is the most disciplined one. It sacrifices full sorted order to guarantee one thing perfectly: the most important element is always at the top, always reachable in O(1), always replaceable in O(log n). For every system that must always act on the highest priority — operating systems, GPS, hospitals, compilers — the Heap is the right tool.
