# Binary Search Tree, Insertion, Search, and Deletion in Python

---

## 1. Introduction

Imagine you walk into a **library with 10,000 books**, all arranged in alphabetical order on shelves.

You are looking for a book titled *"The Midnight Library"*.

You do not start from shelf 1 and check every single book. You walk to the middle of the library. The books there start with "M". You think -*"T comes after M"* - so you walk to the right half. Now you are in the "S–Z" section. You find "T" quickly. Done. You checked maybe 15 shelves out of 10,000.

That is **Binary Search Tree logic** working in the real world.

A **Binary Search Tree (BST)** is a Binary Tree with one extra rule: a contract every node must honour:

> **Everything in my left subtree is smaller than me. Everything in my right subtree is larger than me.**

This single rule transforms a random collection of nodes into a **self-organising, searchable structure** that makes finding any value extraordinarily fast.

---

## 2. Real-World Applications

**Phone Book / Contact Search**

Your phone's contact list is not a plain list. Internally it behaves like a BST, when you type "Ra", the app eliminates every name before "R" and after "Rb" in one shot. That's why search feels instant even with 5,000 contacts.

**Bank Transaction Lookup**

Every time you check if a transaction happened on a specific date, the bank's database engine uses a BST-based index called a **B-Tree**. It doesn't scan millions of rows, it navigates a tree.

**Auto-Complete in Search Bars**

When you type "py" in Google and it suggests "python tutorial", "python download", "pypi", it is walking a BST (specifically a Trie, which is a BST variant) to find every word that starts with "py".

**Gaming Leaderboards**

A game needs to constantly insert new scores, delete old ones, and find the rank of a player. A BST allows all three operations in O(log n), a plain sorted list would be too slow.

**The File System on Your Computer**

The `find` command on your computer and Windows Search both use tree structures to locate files without reading every single file on disk.

## 4. Key Terminology

| Term | Plain English Meaning |
|------|-----------------------|
| **BST Property** | Left < Node < Right, at every single node |
| **Insertion** | Adding a new value while preserving the BST property |
| **Search** | Finding whether a value exists in the tree |
| **Deletion** | Removing a value while keeping the tree valid |
| **Inorder Successor** | The smallest value in the right subtree, used during deletion |
| **Balanced BST** | A tree where no branch is much longer than another, keeps operations fast |
| **Degenerate Tree** | A BST that has become a straight line (like a linked list), worst case |

## 5. The Node Class (Same Foundation, New Rules)

```python
class Node:
    def __init__(self, data):
        self.data  = data    # The value stored
        self.left  = None    # Left child (always smaller)
        self.right = None    # Right child (always larger)

    def __repr__(self):
        return f"Node({self.data})"
```

The Node class is identical to a Binary Tree node. The intelligence is not in the node, it is in **how we insert, search, and delete**. The node is just a container.

## 6. Operation 1: Insertion

### The Idea

Think of inserting a new employee into a company hierarchy where every manager earns more than their left-side report and less than their right-side report.

You start at the CEO (root). You compare the new employee's salary to the CEO's:
- If lower → go left
- If higher → go right

You repeat this at every level until you find an empty slot. You place the new employee there. The hierarchy rule is never violated.

### The Algorithm

```
To insert value V:
  Start at the root.
  If V < current node  → move left
  If V > current node  → move right
  If the spot is empty → place V here
```
<img src="(https://miro.medium.com/v2/resize:fit:640/format:webp/1*CjTC-LnGtgUZ0FBmOVi3Dg.gif)" alt="BST Insertion Steps" width="500"/>
### Implementation

```python
class BST:
    def __init__(self):
        self.root = None    # An empty tree has no root

    def insert(self, data):
        if self.root is None:
            self.root = Node(data)    # First node becomes the root
        else:
            self._insert_recursive(self.root, data)

    def _insert_recursive(self, node, data):
        if data < node.data:
            if node.left is None:
                node.left = Node(data)        # Empty slot found, place here
            else:
                self._insert_recursive(node.left, data)   # Keep going left
        elif data > node.data:
            if node.right is None:
                node.right = Node(data)       # Empty slot found, place here
            else:
                self._insert_recursive(node.right, data)  # Keep going right
        # If data == node.data, we ignore duplicates (BSTs typically don't store them)
```

### Trace, Inserting 50, 30, 70, 20, 40

```
Insert 50:   Tree is empty → 50 becomes root
             [50]

Insert 30:   30 < 50 → go left → empty → place here
             [50]
            /
          [30]

Insert 70:   70 > 50 → go right → empty → place here
             [50]
            /    \
          [30]  [70]

Insert 20:   20 < 50 → go left → reach 30
             20 < 30 → go left → empty → place here
             [50]
            /    \
          [30]  [70]
          /
        [20]

Insert 40:   40 < 50 → go left → reach 30
             40 > 30 → go right → empty → place here
             [50]
            /    \
          [30]  [70]
          /  \
        [20] [40]
```

**Notice:** We never had to rearrange anything. Each new value found its correct position by simply following the rule at every step.

## 7. Operation 2, Search

### The Idea

You are playing **"Higher or Lower"**, the game where someone thinks of a number and you guess.

- You guess 50. They say "lower."
- You guess 25. They say "higher."
- You guess 37. They say "correct."

You just did a BST search. At every step you eliminate half the remaining possibilities. This is why BST search is O(log n), not O(n) like scanning a list.

### Implementation

```python
def search(self, data):
    return self._search_recursive(self.root, data)

def _search_recursive(self, node, data):
    if node is None:
        return False              # Reached a dead end, value not in tree

    if data == node.data:
        return True               # Found it!

    elif data < node.data:
        return self._search_recursive(node.left, data)   # Go left

    else:
        return self._search_recursive(node.right, data)  # Go right
```

### Trace, Searching for 40 in our tree

```
         [50]
        /    \
      [30]  [70]
      /  \
    [20] [40]

Step 1: At [50].  40 < 50  → go left
Step 2: At [30].  40 > 30  → go right
Step 3: At [40].  40 == 40 → FOUND ✅
```

**Only 3 comparisons** to find a value in a 5-node tree. In a tree with 1,000,000 nodes, you'd need at most **20 comparisons**. That is the power of log₂(1,000,000) ≈ 20.

## 8. Operation 3, Deletion

### The Idea

Deletion is the trickiest operation. When you remove a node, you must ensure every remaining node still follows the BST rule. Imagine removing a manager from a company, you must promote someone to fill the gap correctly, not just pull them out and leave the organisation chart broken.

There are **three cases** depending on who you are removing.

---

### Case 1, Deleting a Leaf Node (No Children)

**Real-world analogy:** Firing an intern. They have no reports, no responsibilities. You simply remove them. Nobody notices except HR.

```
Delete [20] from:          Result:
     [50]                     [50]
    /    \                   /    \
  [30]  [70]              [30]  [70]
  /  \                       \
[20] [40]                   [40]
```

Simply set the parent's pointer (`node.left` or `node.right`) to `None`.

---

### Case 2, Deleting a Node with One Child

**Real-world analogy:** A middle manager with only one direct report resigns. The direct report simply moves up and now reports to the departing manager's boss. The chain is preserved.

```
Delete [30] (has only left child [20]):

     [50]                     [50]
    /    \         →          /    \
  [30]  [70]               [20]  [70]
  /
[20]
```

Replace the deleted node with its only child. The BST property is maintained because that child was already on the correct side.

---

### Case 3, Deleting a Node with Two Children

**Real-world analogy:** The CEO resigns. They have a left VP and a right VP. You cannot just pick one VP to replace them randomly, you need the person who fits best in the middle. The right choice is the **smallest person from the right subtree** (the Inorder Successor). They are:
- Larger than everyone in the left subtree ✅
- Smaller than everyone else in the right subtree ✅

They are the perfect fit for the vacated position.

```
Delete [50] (has two children):

        [50]                       [60]
       /    \          →          /    \
     [30]  [70]                 [30]  [70]
     /  \  /  \                 /  \     \
   [20][40][60][80]           [20][40]  [80]

Inorder Successor of [50] = smallest in right subtree = [60]
Copy [60]'s value into [50]'s position, then delete [60] from the right subtree.
```

### Implementation

```python
def delete(self, data):
    self.root = self._delete_recursive(self.root, data)

def _delete_recursive(self, node, data):
    if node is None:
        return None                   # Value not found, nothing to delete

    if data < node.data:
        node.left = self._delete_recursive(node.left, data)   # Go left

    elif data > node.data:
        node.right = self._delete_recursive(node.right, data) # Go right

    else:
        # === Node to delete found ===

        # Case 1: Leaf node, no children
        if node.left is None and node.right is None:
            return None

        # Case 2a: Only right child
        elif node.left is None:
            return node.right

        # Case 2b: Only left child
        elif node.right is None:
            return node.left

        # Case 3: Two children, find inorder successor
        else:
            successor = self._find_min(node.right)         # Smallest in right subtree
            node.data = successor.data                     # Copy successor's value here
            node.right = self._delete_recursive(node.right, successor.data)  # Delete successor

    return node

def _find_min(self, node):
    while node.left is not None:   # Keep going left until you can't
        node = node.left
    return node
```

## 9. Inorder Traversal, The BST's Secret Weapon

For any BST, an Inorder traversal (Left → Root → Right) always produces values in **sorted ascending order**.

```python
def inorder(self, node=None, _first=True):
    if _first:
        node = self.root
    if node is None:
        return
    self.inorder(node.left, _first=False)
    print(node.data, end="  ")
    self.inorder(node.right, _first=False)
```

For our tree `[20, 30, 40, 50, 60, 70, 80]`:

```
Inorder output:  20  30  40  50  60  70  80
```

This is not a coincidence, it is a direct consequence of the BST property. This is how **database indexes** produce sorted query results efficiently.

## 10. Complete Program

```python
class Node:
    def __init__(self, data):
        self.data  = data
        self.left  = None
        self.right = None

    def __repr__(self):
        return f"Node({self.data})"


class BST:
    def __init__(self):
        self.root = None

    # ── Insertion ────────────────────────────────────────────
    def insert(self, data):
        if self.root is None:
            self.root = Node(data)
        else:
            self._insert_recursive(self.root, data)

    def _insert_recursive(self, node, data):
        if data < node.data:
            if node.left is None:
                node.left = Node(data)
            else:
                self._insert_recursive(node.left, data)
        elif data > node.data:
            if node.right is None:
                node.right = Node(data)
            else:
                self._insert_recursive(node.right, data)

    # ── Search ───────────────────────────────────────────────
    def search(self, data):
        return self._search_recursive(self.root, data)

    def _search_recursive(self, node, data):
        if node is None:
            return False
        if data == node.data:
            return True
        elif data < node.data:
            return self._search_recursive(node.left, data)
        else:
            return self._search_recursive(node.right, data)

    # ── Deletion ─────────────────────────────────────────────
    def delete(self, data):
        self.root = self._delete_recursive(self.root, data)

    def _delete_recursive(self, node, data):
        if node is None:
            return None
        if data < node.data:
            node.left = self._delete_recursive(node.left, data)
        elif data > node.data:
            node.right = self._delete_recursive(node.right, data)
        else:
            if node.left is None and node.right is None:
                return None
            elif node.left is None:
                return node.right
            elif node.right is None:
                return node.left
            else:
                successor  = self._find_min(node.right)
                node.data  = successor.data
                node.right = self._delete_recursive(node.right, successor.data)
        return node

    def _find_min(self, node):
        while node.left is not None:
            node = node.left
        return node

    # ── Inorder Traversal ────────────────────────────────────
    def inorder(self, node=None, _first=True):
        if _first:
            node = self.root
        if node is None:
            return
        self.inorder(node.left, _first=False)
        print(node.data, end="  ")
        self.inorder(node.right, _first=False)


# ── Driver Code ──────────────────────────────────────────────

bst = BST()
for val in [50, 30, 70, 20, 40, 60, 80]:
    bst.insert(val)

#          [50]
#         /    \
#       [30]  [70]
#       /  \  /  \
#     [20][40][60][80]

print("Inorder after insertion:")
bst.inorder()
print()

print("\nSearch 40:", bst.search(40))    # True
print("Search 99:", bst.search(99))    # False

# Delete leaf node
bst.delete(20)
print("\nInorder after deleting 20 (leaf):")
bst.inorder()
print()

# Delete node with one child
bst.delete(30)
print("\nInorder after deleting 30 (one child):")
bst.inorder()
print()

# Delete node with two children
bst.delete(50)
print("\nInorder after deleting 50 (two children):")
bst.inorder()
print()
```

**Output:**

```
Inorder after insertion:
20  30  40  50  60  70  80

Search 40: True
Search 99: False

Inorder after deleting 20 (leaf):
30  40  50  60  70  80

Inorder after deleting 30 (one child):
40  50  60  70  80

Inorder after deleting 50 (two children):
40  60  70  80
```

## 11. Time Complexity, Why BST Matters

| Operation | Average Case | Worst Case (Degenerate) |
|-----------|-------------|--------------------------|
| **Insertion** | O(log n) | O(n) |
| **Search** | O(log n) | O(n) |
| **Deletion** | O(log n) | O(n) |

**What is O(log n) in plain English?**

If you have 1,000,000 items:
- A plain list scan → up to **1,000,000 steps**
- A BST search → at most **20 steps**

That is the difference between waiting 10 seconds and waiting 0.00002 seconds.

**What is the Worst Case (Degenerate Tree)?**

If you insert already-sorted data `[10, 20, 30, 40, 50]` into a BST:

```
[10]
   \
  [20]
     \
    [30]
       \
      [40]
         \
        [50]
```

It becomes a straight line, effectively a linked list. Every operation now takes O(n). This is why real-world databases use **self-balancing BSTs** (AVL Trees, Red-Black Trees) that automatically restructure themselves to stay efficient.

```
Original Tree:
         [50]
        /    \
      [30]  [70]
      /  \  /  \
    [20][40][60][80]
```

| Case | Delete | What Happens | Result |
|------|--------|-------------|--------|
| **Leaf** | `20` | Set parent's pointer to None | `30`'s left = None |
| **One child** | `30` | Replace with only child `40` | `50`'s left = `40` |
| **Two children** | `50` | Replace with inorder successor `60` | Root becomes `60` |

## 13. Common Mistakes

**Mistake 1, Forgetting to return the node in deletion**

```python
# Wrong, the tree structure gets lost
def _delete_recursive(self, node, data):
    ...
    node.left = self._delete_recursive(node.left, data)
    # Missing: return node ← the tree above this point disconnects

# Correct, always return node at the end
def _delete_recursive(self, node, data):
    ...
    node.left = self._delete_recursive(node.left, data)
    return node    # This re-links the parent to the (possibly modified) subtree
```

**Mistake 2, Using the wrong successor**

For a two-child deletion, always use the **minimum of the RIGHT subtree** (inorder successor), not the maximum of the left subtree (inorder predecessor), both work mathematically, but the successor is the convention and slightly simpler to implement.

**Mistake 3, Inserting duplicate values**

A standard BST ignores duplicates (`data == node.data`). If your use case needs duplicates (e.g. leaderboards where two players can have the same score), you must explicitly decide: go left on equal, or go right on equal, and be consistent.

**Mistake 4, Assuming BST = Sorted input is fine**

Inserting `[1, 2, 3, 4, 5]` in order creates a degenerate tree. Always shuffle or use a self-balancing variant (AVL, Red-Black) for production use.

## 14. What Comes Next

```
Binary Search Tree (BST)
 │
 ├──► AVL Tree
 │      └── Self-balancing BST (1962). After every insert/delete,
 │          it rotates nodes to keep the tree balanced.
 │          Used in: memory allocators, kernel scheduler (older Linux)
 │
 ├──► Red-Black Tree
 │      └── Loosely balanced BST. Faster insertions than AVL.
 │          Used in: Java TreeMap, C++ std::map, Linux CFS scheduler,
 │          Python's sortedcontainers
 │
 ├──► B-Tree / B+ Tree
 │      └── BST generalised for disk storage (many children per node).
 │          Used in: every relational database index (MySQL InnoDB,
 │          PostgreSQL, SQLite), file systems (NTFS, ext4, APFS)
 │
 └──► Trie (Prefix Tree)
        └── BST specialised for strings.
            Used in: autocomplete, spell checkers, IP routing tables,
            search engine indexing
```

## 15. Summary

| Concept | Plain English |
|---------|--------------|
| **BST Property** | Left < Node < Right, honoured at every node |
| **Insertion** | Follow the rule at each node until you find an empty slot |
| **Search** | Eliminate half the tree at every step (like "Higher or Lower") |
| **Deletion, Leaf** | Simply remove it |
| **Deletion, One child** | Promote the child to take the deleted node's place |
| **Deletion, Two children** | Replace with inorder successor (smallest of right subtree) |
| **Inorder Traversal** | Always gives sorted output, BST's built-in sort |
| **O(log n)** | 1,000,000 items → 20 steps. The magic of halving |
| **Degenerate Tree** | Sorted insertions create a linked list, always bad |
| **`return node`** | Never forget this in recursive deletion, it re-links the tree |

The BST is not just a data structure, it is a philosophy. Every decision halves the problem. Every node is a question: *"Am I bigger or smaller?"* And from that single repeated question emerges one of the most efficient organising mechanisms ever designed.

Once you understand BST, you understand why every database, every file system, and every search bar feels instant.
