# Binary Search Tree — Searching Employee Names in Python

---

## 1. Introduction

The company has grown.

What started as a CEO with two VPs has now expanded to **hundreds of employees** — Directors, Managers, Team Leads, Engineers, Analysts. HR receives dozens of requests every day:

- *"Is Alice in the Engineering department?"*
- *"Does anyone named Zara work here?"*
- *"Find the employee named Bob — immediately."*

The naive approach: scan the entire employee list from top to bottom. With 500 employees, that could mean 500 comparisons in the worst case. Slow, inefficient, unacceptable.

But before jumping to the solution, let us be fair and try every data structure you already know on this exact problem — searching an employee name as fast as possible.

**Array / Python List** stores all employee names in one block: `["Charlie", "Alice", "Frank", "Bob", ...]`. To search for "Diana", you scan from index 0 upward — no shortcut exists. Worst case: you check every single name. Inserting a new employee in the right sorted position means shifting every element after it. 500 employees? Every hire shuffles half the list.

**Stack** only exposes the topmost element. To find "Diana", you would have to pop employees one by one until you hit her — and in doing so, you destroy the stack. You cannot search a stack without dismantling it.

**Queue** processes employees strictly front to back. You dequeue everyone ahead of Diana just to reach her. Like a Stack, searching means consuming — you cannot peek into the middle without breaking the structure.

**Singly Linked List** gives every employee a pointer to the next one. To find "Diana", you start at the head and follow pointers one by one: Charlie → Alice → Frank → Bob → Diana. No jumping, no skipping. Even if Diana is the second name alphabetically, you cannot jump directly to her — you must walk the chain from the beginning every single time.

**Doubly Linked List** adds a pointer backward as well — but it still offers no shortcut to a specific name. You can traverse forward or backward, but you still start from one end and walk. For 500 employees, "Zara" at the far end still costs 500 steps.

**The common failure in all four:** they are all **blind to order**. None of them can exploit the fact that names are alphabetical to skip irrelevant entries. They must check every element because their structure stores no information about *where* a value might be relative to any starting point.

This is exactly the gap the **Binary Search Tree** fills. A BST does not just store names — it arranges them so that at every single node, one comparison tells you which entire half of the remaining names to permanently ignore. The structure itself is the search strategy.

The smart approach: arrange employees in a **Binary Search Tree by name**. Now finding anyone takes at most **9 comparisons** — regardless of whether you are searching for Alice or Zara.

That is the power of a **Binary Search Tree (BST)**.

---

## 2. The One Rule That Makes BST Special

A Binary Search Tree is a Binary Tree with one strict rule enforced at **every single node**:

```
All names in LEFT subtree  <  Current node's name  <  All names in RIGHT subtree
```

Names are compared **alphabetically** — exactly like a dictionary. `Alice` comes before `Charlie`, so Alice goes to the left. `Zara` comes after `Charlie`, so Zara goes to the right.

Let us build the company's employee BST step by step. The employees join in this order:

```
Charlie → Alice → Frank → Bob → Diana → Eve → George
```

After all insertions, the BST looks like this:

```
                        [ Charlie ]              ← CEO level (root)
                       /           \
               [ Alice ]           [ Frank ]     ← VP level
                    \              /       \
                  [ Bob ]     [ Diana ]  [ George ]   ← Director level
                                   \
                                  [ Eve ]              ← Manager level
```

Verify the BST rule at every node:
- At `Charlie`: Alice, Bob are to the left (come before C). Frank, Diana, Eve, George are to the right (come after C). ✓
- At `Frank`: Diana, Eve are to the left (come before F). George is to the right (comes after F). ✓
- At `Alice`: Bob is to the right (comes after A). ✓

This ordering is what makes search lightning fast.

## 3. Key Terminology

| Term | Meaning in Employee Context |
|------|----------------------------|
| **Root** | The first employee inserted — becomes the reference point for all comparisons |
| **BST Property** | Left subtree names < Node name < Right subtree names, at every node |
| **Inorder Successor** | The next employee alphabetically — smallest name in the right subtree |
| **Balanced BST** | Tree height is O(log n) — all searches stay fast |
| **Skewed BST** | Employees inserted in alphabetical order — degrades to a straight line, O(n) |
| **Search Path** | The sequence of comparisons made while looking for an employee |

## 4. The Node and BST Class

Each node represents one employee. The `data` field holds the employee's name.

```python
class Node:
    def __init__(self, name):
        self.data  = name     # Employee name
        self.left  = None     # Points to employee whose name comes before
        self.right = None     # Points to employee whose name comes after

    def __repr__(self):
        return f"Node({self.data})"


class BST:
    def __init__(self):
        self.root = None      # Empty company — no employees yet
```

## 5. Insertion — Hiring a New Employee

### 5.1 The Logic

When a new employee joins, HR places them in the correct position in the org BST:

- Compare the new name with the current node
- If it comes **before** (alphabetically less) → go **left**
- If it comes **after** (alphabetically greater) → go **right**
- When an empty spot is found → **place the employee there**

Think of it like seating guests at a dinner table arranged alphabetically. You start from the head of the table (root) and keep moving left or right until you find the correct empty chair.

### 5.2 Code

```python
def insert(self, name):
    new_node = Node(name)

    if self.root is None:
        self.root = new_node       # First employee becomes the root
        return

    current = self.root
    while True:
        if name < current.data:
            if current.left is None:
                current.left = new_node    # Empty chair found on the left
                break
            current = current.left         # Keep moving left
        else:
            if current.right is None:
                current.right = new_node   # Empty chair found on the right
                break
            current = current.right        # Keep moving right
```

### 5.3 Building the Employee BST — Step by Step

```python
bst = BST()
employees = ["Charlie", "Alice", "Frank", "Bob", "Diana", "Eve", "George"]
for emp in employees:
    bst.insert(emp)
```

Watch the tree take shape as each employee is hired:

```
Insert Charlie  →  Charlie becomes root

Insert Alice    →  Alice < Charlie  →  Alice goes LEFT of Charlie
Insert Frank    →  Frank > Charlie  →  Frank goes RIGHT of Charlie

Insert Bob      →  Bob < Charlie  →  go left to Alice
                   Bob > Alice    →  Bob goes RIGHT of Alice

Insert Diana    →  Diana > Charlie  →  go right to Frank
                   Diana < Frank    →  Diana goes LEFT of Frank

Insert Eve      →  Eve > Charlie  →  go right to Frank
                   Eve < Frank    →  go left to Diana
                   Eve > Diana    →  Eve goes RIGHT of Diana

Insert George   →  George > Charlie  →  go right to Frank
                   George > Frank    →  George goes RIGHT of Frank

Final BST:
                        [ Charlie ]
                       /           \
               [ Alice ]           [ Frank ]
                    \              /       \
                  [ Bob ]     [ Diana ]  [ George ]
                                   \
                                  [ Eve ]
```

## 6. Search — Finding an Employee

### 6.1 The Logic

This is where the BST earns its reputation.

Imagine HR searching for `"Diana"` in a company of 500 employees using a plain list — they might check all 500 names. With a balanced BST of 500 employees, the maximum comparisons needed is just **9** (log₂ 500 ≈ 9).

At every node, one comparison eliminates an entire half of the remaining employees:

- If the name **matches** → employee **found**
- If the search name comes **before** → look only in the **left** subtree
- If the search name comes **after** → look only in the **right** subtree
- If you reach `None` → employee does **not exist** in the company

### 6.2 Code

```python
def search(self, name):
    current = self.root
    steps = 0                               # Count comparisons for learning

    while current is not None:
        steps += 1
        if name == current.data:
            print(f"  Found '{name}' in {steps} step(s). ✓")
            return True
        elif name < current.data:
            current = current.left          # Discard right half entirely
        else:
            current = current.right         # Discard left half entirely

    print(f"  '{name}' not found after {steps} step(s). ✗")
    return False
```

### 6.3 Trace — Searching for "Diana"

```
Start at Charlie  →  Diana > Charlie  →  go RIGHT  (Alice, Bob eliminated)
At Frank          →  Diana < Frank    →  go LEFT   (George eliminated)
At Diana          →  Diana == Diana   →  FOUND ✓

Total comparisons: 3
```

### 6.4 Trace — Searching for "Eve"

```
Start at Charlie  →  Eve > Charlie  →  go RIGHT
At Frank          →  Eve < Frank    →  go LEFT
At Diana          →  Eve > Diana    →  go RIGHT
At Eve            →  Eve == Eve     →  FOUND ✓

Total comparisons: 4
```

### 6.5 Trace — Searching for "Zara" (not in company)

```
Start at Charlie  →  Zara > Charlie  →  go RIGHT
At Frank          →  Zara > Frank    →  go RIGHT
At George         →  Zara > George   →  go RIGHT
None              →  NOT FOUND ✗

Total comparisons: 3
```

In all three cases, the BST never checked employees it did not need to. Alice, Bob, Diana (in the Zara search) were completely skipped. That is the BST at work.

## 7. Minimum and Maximum Employee Name

### 7.1 The Logic

Two queries HR gets very often:

- *"Who is the first employee alphabetically?"* → **Minimum** — always the **leftmost** node
- *"Who is the last employee alphabetically?"* → **Maximum** — always the **rightmost** node

No searching needed. Just walk to the edge.

```
Find Minimum:
Charlie → left → Alice → left? No left child → Alice is the minimum ✓

Find Maximum:
Charlie → right → Frank → right → George → right? No right child → George is the maximum ✓
```

### 7.2 Code

```python
def find_min(self):
    if self.root is None:
        return None
    current = self.root
    while current.left is not None:
        current = current.left             # Keep going left
    return current.data


def find_max(self):
    if self.root is None:
        return None
    current = self.root
    while current.right is not None:
        current = current.right            # Keep going right
    return current.data
```

## 8. Height of the Employee BST

### 8.1 The Logic

The **height** of the BST is the length of the longest reporting chain from the root down to the deepest employee.

In our company: `Charlie → Frank → Diana → Eve` is the longest path. That is 3 edges, so height = **3**.

Height directly determines the worst-case search time. A balanced company org BST keeps height low. A poorly built one (employees inserted alphabetically) collapses into a straight line — height equals number of employees.

```python
def height(self, node=None, _first_call=True):
    if _first_call:
        node = self.root
    if node is None:
        return -1                               # Empty — no employees
    left_h  = self.height(node.left,  _first_call=False)
    right_h = self.height(node.right, _first_call=False)
    return 1 + max(left_h, right_h)
```

**Trace on our BST:**

```
height(Bob)     = 1 + max(-1, -1) = 0   ← leaf
height(Eve)     = 1 + max(-1, -1) = 0   ← leaf
height(George)  = 1 + max(-1, -1) = 0   ← leaf
height(Alice)   = 1 + max(-1, 0)  = 1
height(Diana)   = 1 + max(-1, 0)  = 1
height(Frank)   = 1 + max(1,  0)  = 2
height(Charlie) = 1 + max(1,  2)  = 3   ← root
```

Height of our BST = **3**

## 9. Inorder Traversal — Employee Directory in Alphabetical Order

The most useful property of a BST: **Inorder traversal always outputs names in sorted alphabetical order.**

HR can generate the complete company directory — sorted — by simply doing an inorder traversal. No sorting algorithm needed. The BST structure itself is the sort.

```python
def inorder(self, node=None, _first_call=True):
    if _first_call:
        node = self.root
    if node is None:
        return
    self.inorder(node.left,  _first_call=False)
    print(node.data, end="  ")
    self.inorder(node.right, _first_call=False)
```

**Output for our employee BST:**

```
Alice  Bob  Charlie  Diana  Eve  Frank  George
```

Employees were inserted in the order `Charlie, Alice, Frank, Bob, Diana, Eve, George` — a completely random order. Yet Inorder traversal gives a perfect alphabetical directory. This is why BSTs are used in sorted dictionaries, maps, and sets in every major programming language.

## 10. Deletion — Employee Resignation

When an employee leaves the company, they must be removed from the BST. The BST property must remain intact after removal. There are three cases.

### 10.1 Case 1 — Removing a Leaf Employee (no reportees in BST)

Simply remove the node. No one else is affected.

```
Remove Bob (a leaf):

Before:                     After:
    [ Alice ]                   [ Alice ]
         \                          (right is now None)
       [ Bob ]
```

### 10.2 Case 2 — Removing an Employee with One Subtree

Replace the departing employee with their only subtree. Like a manager leaving — their one direct reportee steps up.

```
Remove Alice (has only right child Bob):

Before:                     After:
    [ Charlie ]                 [ Charlie ]
    /                           /
[ Alice ]                   [ Bob ]
     \
   [ Bob ]
```

### 10.3 Case 3 — Removing an Employee with Two Subtrees

The trickiest case. The departing employee has people on both sides. You cannot simply remove them — the BST property must be preserved for both subtrees.

**Solution:** Find the **inorder successor** — the employee whose name comes immediately after the departing one alphabetically. That employee steps into the vacated role. Then remove the successor from their original position.

*Why inorder successor?* They are the smallest name in the right subtree — greater than everyone in the left subtree, smaller than everyone else in the right subtree. Placing them in the vacated slot preserves the BST rule perfectly.

```
Remove Charlie (has both Alice subtree and Frank subtree):

Inorder successor of Charlie = Diana
(Diana is the smallest name in Charlie's right subtree)

Step 1: Replace Charlie's name with Diana
Step 2: Delete Diana from its original position

Before:                          After:
        [ Charlie ]                      [ Diana ]
       /           \                    /          \
   [ Alice ]     [ Frank ]         [ Alice ]     [ Frank ]
        \         /      \               \         /      \
       [Bob]  [Diana]  [George]        [Bob]    [Eve]   [George]
                  \
                 [Eve]
```

### 10.4 Code

```python
def delete(self, name):
    self.root = self._delete_recursive(self.root, name)

def _delete_recursive(self, node, name):
    if node is None:
        return None                        # Employee not found

    if name < node.data:
        node.left  = self._delete_recursive(node.left,  name)
    elif name > node.data:
        node.right = self._delete_recursive(node.right, name)
    else:
        # Employee to remove found

        # Case 1 and 2: zero or one subtree
        if node.left is None:
            return node.right
        if node.right is None:
            return node.left

        # Case 3: two subtrees
        # Find inorder successor (alphabetically next employee)
        successor = node.right
        while successor.left is not None:
            successor = successor.left

        node.data  = successor.data        # Successor steps into the role
        node.right = self._delete_recursive(node.right, successor.data)

    return node
```

## 11. The Danger — Skewed BST

If employees are inserted in alphabetical order, every new employee is greater than the previous one and goes to the right. The BST becomes a straight line — completely skewed:

```
Insert: Alice → Bob → Charlie → Diana → Eve → Frank → George

[ Alice ]
     \
   [ Bob ]
        \
      [ Charlie ]
             \
           [ Diana ]
                  \
                [ Eve ]
                      \
                    [ Frank ]
                           \
                         [ George ]
```

Searching for George now requires **7 comparisons** — visiting every node. The BST has become no better than a plain list.

This is why **AVL Trees** and **Red-Black Trees** were invented — they automatically re-balance after every insertion to ensure height stays at O(log n) regardless of insertion order.

## 12. Complete Program

```python
class Node:
    def __init__(self, name):
        self.data  = name
        self.left  = None
        self.right = None

    def __repr__(self):
        return f"Node({self.data})"


class BST:
    def __init__(self):
        self.root = None

    # ── Insertion ──────────────────────────────────────────────
    def insert(self, name):
        new_node = Node(name)
        if self.root is None:
            self.root = new_node
            return
        current = self.root
        while True:
            if name < current.data:
                if current.left is None:
                    current.left = new_node
                    break
                current = current.left
            else:
                if current.right is None:
                    current.right = new_node
                    break
                current = current.right

    # ── Search ─────────────────────────────────────────────────
    def search(self, name):
        current = self.root
        steps = 0
        while current is not None:
            steps += 1
            if name == current.data:
                print(f"  Found '{name}' in {steps} step(s). ✓")
                return True
            elif name < current.data:
                current = current.left
            else:
                current = current.right
        print(f"  '{name}' not found after {steps} step(s). ✗")
        return False

    # ── Minimum ────────────────────────────────────────────────
    def find_min(self):
        if self.root is None:
            return None
        current = self.root
        while current.left:
            current = current.left
        return current.data

    # ── Maximum ────────────────────────────────────────────────
    def find_max(self):
        if self.root is None:
            return None
        current = self.root
        while current.right:
            current = current.right
        return current.data

    # ── Height ─────────────────────────────────────────────────
    def height(self, node=None, _first_call=True):
        if _first_call:
            node = self.root
        if node is None:
            return -1
        left_h  = self.height(node.left,  _first_call=False)
        right_h = self.height(node.right, _first_call=False)
        return 1 + max(left_h, right_h)

    # ── Deletion ───────────────────────────────────────────────
    def delete(self, name):
        self.root = self._delete_recursive(self.root, name)

    def _delete_recursive(self, node, name):
        if node is None:
            return None
        if name < node.data:
            node.left  = self._delete_recursive(node.left,  name)
        elif name > node.data:
            node.right = self._delete_recursive(node.right, name)
        else:
            if node.left is None:
                return node.right
            if node.right is None:
                return node.left
            successor = node.right
            while successor.left:
                successor = successor.left
            node.data  = successor.data
            node.right = self._delete_recursive(node.right, successor.data)
        return node

    # ── Inorder: Alphabetical Directory ────────────────────────
    def inorder(self, node=None, _first_call=True):
        if _first_call:
            node = self.root
        if node is None:
            return
        self.inorder(node.left,  _first_call=False)
        print(node.data, end="  ")
        self.inorder(node.right, _first_call=False)


# ── Driver Code ────────────────────────────────────────────────

bst = BST()
employees = ["Charlie", "Alice", "Frank", "Bob", "Diana", "Eve", "George"]
for emp in employees:
    bst.insert(emp)

print("── Company Directory (Alphabetical) ──")
bst.inorder()
print("\n")

print("── Employee Search ──")
bst.search("Diana")
bst.search("Eve")
bst.search("Zara")
print()

print("── First Employee (Min) ──")
print(" ", bst.find_min())
print()

print("── Last Employee (Max) ──")
print(" ", bst.find_max())
print()

print("── BST Height ──")
print(" ", bst.height())
print()

print("── After Charlie Resigns ──")
bst.delete("Charlie")
bst.inorder()
print()
```

**Output:**

```
── Company Directory (Alphabetical) ──
Alice  Bob  Charlie  Diana  Eve  Frank  George

── Employee Search ──
  Found 'Diana' in 3 step(s). ✓
  Found 'Eve' in 4 step(s). ✓
  'Zara' not found after 3 step(s). ✗

── First Employee (Min) ──
  Alice

── Last Employee (Max) ──
  George

── BST Height ──
  3

── After Charlie Resigns ──
Alice  Bob  Diana  Eve  Frank  George
```

## 13. Time Complexity

| Operation | Balanced BST | Skewed BST (worst case) |
|-----------|-------------|-------------------------|
| Insert employee | O(log n) | O(n) |
| Search employee | O(log n) | O(n) |
| Delete employee | O(log n) | O(n) |
| First alphabetically | O(log n) | O(n) |
| Last alphabetically | O(log n) | O(n) |
| Generate directory (Inorder) | O(n) | O(n) |

For a company of 1,000 employees:
- Balanced BST: search completes in ≤ **10 comparisons**
- Skewed BST: search may need up to **1,000 comparisons**

## 14. Common Mistakes

**Mistake 1 — Case-sensitive comparisons giving wrong results**

```python
# "alice" and "Alice" are treated as different employees
# "alice" > "Charlie" in Python because lowercase letters have higher ASCII values
# Always normalise before inserting or searching:
name = name.strip().title()    # "alice smith" → "Alice Smith"
```

**Mistake 2 — Forgetting the inorder successor in deletion**

The most common error is replacing the deleted employee with an arbitrary child. The correct replacement is always the **minimum of the right subtree** (inorder successor). Choosing any other node breaks the BST property silently — searches will give wrong results with no error message.

**Mistake 3 — Inserting employees in sorted order and wondering why search is slow**

```python
# This creates a skewed BST — height = n, search = O(n)
for emp in ["Alice", "Bob", "Charlie", "Diana", "Eve"]:
    bst.insert(emp)
```

If your data arrives in sorted order, use a **self-balancing BST** (AVL Tree) or shuffle the data before insertion.

## 16. Summary

| Concept | Meaning in Employee Context |
|---------|----------------------------|
| BST Property | All left names < current name < all right names |
| Insertion | Walk left/right alphabetically, attach at first empty slot |
| Search | Halve remaining employees at every comparison |
| Minimum | Leftmost node — first name alphabetically |
| Maximum | Rightmost node — last name alphabetically |
| Height | Longest chain from CEO node to deepest employee |
| Inorder | Produces full alphabetical employee directory |
| Deletion Case 1 | Leaf — simply remove |
| Deletion Case 2 | One subtree — that subtree steps up |
| Deletion Case 3 | Two subtrees — inorder successor takes the role |
| Skewed BST | Sorted insertion order → degrades to O(n) |
| Balanced BST | Random insertion order → O(log n) |

The BST is the first structure where the **arrangement of data encodes its own order**. Every operation exploits that order. Searching 1,000 employees in 10 steps is not magic — it is the inevitable consequence of maintaining one rule at every node.
