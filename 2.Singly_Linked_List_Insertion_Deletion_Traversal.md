# Singly Linked List – Insertion, Deletion, Traversal

---

## The Setup — A Problem Worth Solving

Picture this.

You are the manager of a theatre. Every night, people line up for tickets. Sometimes someone walks in with a VIP pass and needs to be placed **at the front**. Sometimes a person in the middle of the queue decides to leave. Sometimes you just want to **count** how many people are waiting.

Now imagine you're doing all of this with a fixed row of chairs.

Someone joins at front? Everyone shifts one seat forward.
Someone leaves from the middle? Everyone behind them shifts one seat back.

That's exhausting. That's a Python list.

Now imagine instead — each person is holding a **token** that says *"the next person is standing over there."* People can stand anywhere in the room. When someone new joins at the front, they just get a token pointing to the old first person. When someone leaves, their neighbours simply exchange tokens. Nobody moves. Nobody shifts.

That is a **Singly Linked List**.

---

## What Exactly Is a Singly Linked List?

A Singly Linked List is a **chain of nodes** where:
- Each node holds **data**
- Each node holds a **pointer to the next node**
- The last node points to **None** (end of the line)
- You always know where the chain **starts** — this is called the **head**

```
head
 │
 ▼
┌────┬──┐   ┌────┬──┐   ┌────┬──┐   ┌────┬──────┐
│ 10 │ ───► │ 20 │ ───► │ 30 │ ───► │ 40 │ None │
└────┴──┘   └────┴──┘   └────┴──┘   └────┴──────┘
```

**Singly** means each node only knows about the **next** node — it does not know who came before it. It's a one-way street.

---

## Building the Foundation

Before we build the list, we need our Node (from the previous topic):

```python
class Node:
    def __init__(self, data):
        self.data = data
        self.next = None
```

Now the Linked List itself. At its core, a linked list just needs to remember **one thing** — where it starts:

```python
class SinglyLinkedList:
    def __init__(self):
        self.head = None   # The list is empty. No starting point yet.
```

Why only `head`? Because once you know the first node, you can reach every other node by following the chain. The head is your **entry point into the world**.

---

## Act 1 — Traversal (Walking the Chain)

Before inserting or deleting, you need to know how to **walk** through a linked list. Everything else depends on this.

Think of it like following a treasure map. Each clue leads to the next. You start at clue #1 and follow until there are no more clues.

```python
def traverse(self):
    current = self.head       # Start at the beginning

    while current is not None:         # Keep going until the chain ends
        print(current.data, end=" → ")
        current = current.next         # Move to the next node

    print("None")             # Mark the end
```

Let's trace this mentally with a list: `10 → 20 → 30 → None`

| Step | `current` | `current.data` | `current.next` |
|------|-----------|----------------|----------------|
| 1    | node(10)  | 10             | node(20)       |
| 2    | node(20)  | 20             | node(30)       |
| 3    | node(30)  | 30             | None           |
| 4    | None      | loop ends      | —              |

**Output:** `10 → 20 → 30 → None`

This is the heartbeat of a linked list. Every other operation — insertion, deletion, searching — uses this same idea of **walking the chain**.

---

## Act 2 — Insertion

There are **three places** you can insert a new node:
1. At the **beginning** (before the head)
2. At the **end** (after the last node)
3. At a **specific position** (in the middle)

Each one is a different scene in our story. Let's walk through all three.

---

### Scene 1 — Insert at the Beginning

New VIP arrives. They go straight to the front. Everyone else moves back.

But in a linked list, nobody *actually* moves. We just update two pointers.

**The logic:**
1. Create a new node
2. Make the new node's `next` point to the current head
3. Make the new node the new head

```python
def insert_at_beginning(self, data):
    new_node = Node(data)          # Create the new node
    new_node.next = self.head      # New node points to old head
    self.head = new_node           # New node IS the new head
```

**Before:** `head → 10 → 20 → 30 → None`

**After inserting 5:** `head → 5 → 10 → 20 → 30 → None`

Let's visualise what happened:

```
Step 1: Create new_node(5)
        new_node → [5 | None]

Step 2: new_node.next = self.head
        new_node → [5 | ──────────────► 10 → 20 → 30 → None]

Step 3: self.head = new_node
        head → [5 | ──► 10 → 20 → 30 → None]
```

**Time Complexity: O(1)** — No matter how long the list is, inserting at the front always takes the same number of steps. This is where linked lists absolutely **destroy** arrays (which are O(n) for this).

---

### Scene 2 — Insert at the End

A regular customer joins at the back of the queue. Perfectly polite.

**The logic:**
1. Create a new node
2. Walk to the **last** node (the one whose `next` is `None`)
3. Make that last node's `next` point to the new node

```python
def insert_at_end(self, data):
    new_node = Node(data)

    if self.head is None:          # If the list is empty
        self.head = new_node       # The new node is the only node
        return

    current = self.head
    while current.next is not None:    # Walk until the last node
        current = current.next

    current.next = new_node            # Attach new node at the end
```

**Why `while current.next is not None` and not `while current is not None`?**

This is a classic question. If you use `while current is not None`, by the time the loop ends, `current` will be `None` — and you can't do `None.next = new_node`. You need to **stop at the last node**, not go past it.

```
List: 10 → 20 → 30 → None

Walk:
  current = node(10) → current.next = node(20) → keep going
  current = node(20) → current.next = node(30) → keep going
  current = node(30) → current.next = None     → STOP HERE

current.next = new_node(40)

Result: 10 → 20 → 30 → 40 → None
```

**Time Complexity: O(n)** — You have to walk the entire list to find the end. This is a known limitation of singly linked lists. (Solved by keeping a `tail` pointer — but that's a design choice.)

---

### Scene 3 — Insert at a Specific Position

Someone with a semi-VIP pass. Not front, not back — somewhere in the middle.

Say we want to insert `99` at position `2` (0-indexed):

`10 → 20 → 30 → None`  becomes  `10 → 99 → 20 → 30 → None`

**The logic:**
1. Walk to the node **just before** the target position
2. Make new node's `next` point to that node's `next`
3. Make that node's `next` point to the new node

**Order matters critically.** If you do step 3 before step 2, you lose the rest of the chain. Forever.

```python
def insert_at_position(self, data, position):
    new_node = Node(data)

    if position == 0:                      # Inserting at the front
        new_node.next = self.head
        self.head = new_node
        return

    current = self.head
    for _ in range(position - 1):          # Walk to node BEFORE target position
        if current is None:
            print("Position out of range")
            return
        current = current.next

    new_node.next = current.next           # Step 2: point new node forward
    current.next = new_node               # Step 3: point previous node to new node
```

Let's see this visually for inserting `99` at position `1`:

```
Before:
head → [10 | ──► ] → [20 | ──► ] → [30 | None]

After walking to position 0 (node 10):
  current = node(10)

Step 2: new_node(99).next = current.next  →  new_node points to node(20)
Step 3: current.next = new_node           →  node(10) points to node(99)

After:
head → [10 | ──► ] → [99 | ──► ] → [20 | ──► ] → [30 | None]
```

**Time Complexity: O(n)** — Walking to position takes linear time.

## Act 3 — Deletion

Deletion is where things get dramatic. You're removing a node from the chain — and you must **not break the chain** in the process.

There are three cases:
1. Delete the **first** node
2. Delete the **last** node
3. Delete a node with a **specific value**

---

### Scene 1 — Delete the First Node

The VIP at the front leaves. The second person becomes the new first.

```python
def delete_at_beginning(self):
    if self.head is None:           # Nothing to delete
        print("List is empty")
        return

    self.head = self.head.next      # Head now points to the second node
```

The old first node is now **unreferenced**. Python's garbage collector cleans it up automatically.

```
Before: head → [10] → [20] → [30] → None
After:  head →        [20] → [30] → None
```

**Time Complexity: O(1)** — Instant.

---

### Scene 2 — Delete a Node by Value

This is the most common deletion. Find the node that holds a specific value and remove it.

**The trick:** You can't delete a node directly in a singly linked list. You need to find the node **before** it, and redirect that node's pointer to skip over the target.

```
Want to delete node(20):

Before:  [10 | ──►] → [20 | ──►] → [30 | None]

Find node(10) — the node BEFORE node(20)
Make node(10).next = node(20).next  →  node(10).next = node(30)

After:   [10 | ──────────────────►] → [30 | None]
          node(20) is now unreachable — garbage collected
```

```python
def delete_by_value(self, value):
    if self.head is None:
        print("List is empty")
        return

    # Special case: deleting the head node
    if self.head.data == value:
        self.head = self.head.next
        return

    current = self.head
    while current.next is not None:           # Walk the list
        if current.next.data == value:        # Found the node to delete
            current.next = current.next.next  # Skip over it
            return
        current = current.next

    print(f"Value {value} not found in list")
```

**Why do we check `current.next.data` instead of `current.data`?**

Because we need to be **one step ahead**. To delete a node, we need to hold the node *before* it. If we wait until `current.data == value`, we've already moved onto the node we want to delete — and we've lost our reference to the previous one. In a singly linked list, there is no going backwards.

**Time Complexity: O(n)** — In the worst case, the value is at the end.

---

### Scene 3 — Delete the Last Node

The last person in the queue leaves. The second-to-last person's token now says "None."

```python
def delete_at_end(self):
    if self.head is None:
        print("List is empty")
        return

    if self.head.next is None:     # Only one node in the list
        self.head = None
        return

    current = self.head
    while current.next.next is not None:   # Stop at second-to-last node
        current = current.next

    current.next = None            # Disconnect the last node
```

**Why `current.next.next is not None`?**

We want to stop at the **second-to-last** node. From there, we set its `next` to `None`, effectively cutting off the last node.

## Putting It All Together — The Complete Class

```python
class Node:
    def __init__(self, data):
        self.data = data
        self.next = None


class SinglyLinkedList:
    def __init__(self):
        self.head = None

    # ── Traversal ──────────────────────────────────────────
    def traverse(self):
        current = self.head
        while current is not None:
            print(current.data, end=" → ")
            current = current.next
        print("None")

    # ── Insertion ──────────────────────────────────────────
    def insert_at_beginning(self, data):
        new_node = Node(data)
        new_node.next = self.head
        self.head = new_node

    def insert_at_end(self, data):
        new_node = Node(data)
        if self.head is None:
            self.head = new_node
            return
        current = self.head
        while current.next is not None:
            current = current.next
        current.next = new_node

    def insert_at_position(self, data, position):
        new_node = Node(data)
        if position == 0:
            new_node.next = self.head
            self.head = new_node
            return
        current = self.head
        for _ in range(position - 1):
            if current is None:
                print("Position out of range")
                return
            current = current.next
        new_node.next = current.next
        current.next = new_node

    # ── Deletion ───────────────────────────────────────────
    def delete_at_beginning(self):
        if self.head is None:
            print("List is empty")
            return
        self.head = self.head.next

    def delete_at_end(self):
        if self.head is None:
            print("List is empty")
            return
        if self.head.next is None:
            self.head = None
            return
        current = self.head
        while current.next.next is not None:
            current = current.next
        current.next = None

    def delete_by_value(self, value):
        if self.head is None:
            print("List is empty")
            return
        if self.head.data == value:
            self.head = self.head.next
            return
        current = self.head
        while current.next is not None:
            if current.next.data == value:
                current.next = current.next.next
                return
            current = current.next
        print(f"Value {value} not found")
```

## Where Singly Linked Lists Live in the Real World

You've been using singly linked lists your entire life without knowing it.

**1. Your Browser's "Forward" Button (partially)**
When you navigate pages, browsers keep a chain of visited pages. Each page points to the next.

**2. Music Playlist (next track only)**
Spotify's queue — each song knows which song comes next. No going back in a singly linked structure.

**3. Undo History in Simple Editors**
Each action points to the action before it. Press undo, move to the previous state.

**4. Hash Table Collision Chains**
When two keys hash to the same bucket in Python's `dict`, they're stored as a linked list inside that bucket. Every dictionary lookup you've ever done touched a linked list.

**5. CPU Process Scheduling**
Operating systems maintain a queue of processes waiting to use the CPU. New processes join the end. Completed processes are removed from the front. That is a linked list in action.

## Time Complexity — The Full Picture

| Operation | Time Complexity | Why |
|---|---|---|
| Insert at beginning | **O(1)** | Just update head pointer |
| Insert at end | **O(n)** | Must walk to last node |
| Insert at position | **O(n)** | Must walk to that position |
| Delete at beginning | **O(1)** | Just update head pointer |
| Delete at end | **O(n)** | Must walk to second-to-last node |
| Delete by value | **O(n)** | Must search the list |
| Traversal | **O(n)** | Must visit every node |
| Access by index | **O(n)** | No direct jump like arrays |

**The golden rule of linked lists:**
- Beginning operations → **O(1)** — blazing fast
- End and middle operations → **O(n)** — pay the walking cost

This is why linked lists are ideal when you're **mostly inserting and deleting at the front** (like a stack), and less ideal when you need **random access** (use an array for that).

---

## The One Mistake That Breaks Everything

The most dangerous mistake in linked list deletion and insertion:

```python
# WRONG ORDER — you just lost the rest of your list
current.next = new_node          # node(10) now points to new_node
new_node.next = current.next     # current.next is NOW new_node — circular!
```

```python
# CORRECT ORDER — always point the new node forward FIRST
new_node.next = current.next     # new_node points to what comes next
current.next = new_node          # THEN redirect the previous node
```

This is the sequence that trips up almost every programmer the first time. Always ask: **"Am I about to lose a reference I still need?"** before updating any pointer.

## Summary — The Whole Movie in One Frame

```
A Singly Linked List is a chain of nodes.
Each node holds data and a pointer to the next node.
You always enter the chain from the HEAD.
You always know the end because it points to NONE.

INSERT at front  →  O(1)  →  update head
INSERT at end    →  O(n)  →  walk, then attach
INSERT at middle →  O(n)  →  walk, then redirect pointers (forward FIRST)

DELETE at front  →  O(1)  →  move head forward
DELETE at end    →  O(n)  →  walk to second-to-last, set .next = None
DELETE by value  →  O(n)  →  walk until found, skip over it

TRAVERSE         →  O(n)  →  follow .next until None
```

The singly linked list is not just a data structure. It is **the first proof** that you don't need memory to be arranged in a straight line to make it work for you. Once you understand this, every advanced data structure — stacks, queues, trees, graphs — starts to make sense at a deeper level.
