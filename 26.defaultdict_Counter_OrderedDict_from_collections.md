# Python `collections` — `defaultdict`, `Counter`, and `OrderedDict`

---

## 1. Introduction

Picture a school librarian tracking which books each student has borrowed.

A new student walks up: *"I'd like to borrow 'Wings of Fire'."* The librarian opens the borrowing register — but this student has never borrowed before. Their page doesn't exist yet.

A careless librarian panics: *"Error — no page found for this student!"*
A smart librarian calmly creates a fresh page, writes the student's name at the top, and records the book. No crash. No fuss. Default behaviour handled automatically.

Now imagine two more librarians:

The **Counting Librarian** keeps a tally of how many times each book has been borrowed — automatically. You never need to check *"does this book already have a count?"* She just counts.

The **Meticulous Librarian** records every borrowing in the exact order it happened — and when you ask for the list, she gives it back in that same order, no reshuffling.

```
defaultdict  →  "No page? I'll create one for you automatically."
Counter      →  "How many times? I'll track that for you."
OrderedDict  →  "What order did things happen? I'll preserve that exactly."
```

These three classes live in Python's `collections` module. They are not exotic tools — they are the `dict` you already know, but with one specific superpower added. Once you see what each one eliminates, you will reach for them instinctively.

---

## 2. Real-World Applications

All three are specialised Hash Maps. They share the O(1) lookup of `dict` but each solves a different recurring headache.

**`defaultdict` — Grouping and Aggregation**

Every analytics pipeline groups records by category: sales by region, logs by severity, students by grade. Without `defaultdict`, every grouping loop needs an `if key not in d` guard. `defaultdict` eliminates that guard entirely. Used in web servers, data warehouses, recommendation engines, and graph algorithms.

**`Counter` — Frequency Analysis**

Every search engine ranks results by term frequency. Every spam filter counts word occurrences. Every election system counts votes. Every NLP pipeline tokenises and counts. `Counter` turns a five-line frequency-counting loop into a single constructor call — and adds arithmetic, most-common queries, and set-like operations on top.

**`OrderedDict` — Sequence-Sensitive Mappings**

An LRU (Least Recently Used) cache must remember which key was accessed least recently — and evict it when full. `OrderedDict` has a `move_to_end()` method designed for exactly this. It also powers configuration systems where the order of settings matters, and HTTP headers where key order affects parsing.

## 3. Key Terminology

Before writing code, you must speak the language.

```
collections module
 │
 ├── defaultdict  ←  dict + automatic default value for missing keys
 │       │
 │       └── default_factory: the callable that creates the default
 │               int   → 0         (for counting)
 │               list  → []        (for grouping)
 │               set   → set()     (for unique grouping)
 │               str   → ""        (for string accumulation)
 │
 ├── Counter  ←  dict + built-in counting, arithmetic, and most_common()
 │       │
 │       └── Subclass of dict. Keys = elements. Values = counts (integers).
 │
 └── OrderedDict  ←  dict + guaranteed insertion-order + move_to_end()
         │
         └── In Python 3.7+, regular dict also preserves insertion order.
             OrderedDict still matters for move_to_end(), popitem(last=),
             and equality checks that consider order.
```

| Term | Meaning |
|------|---------|
| **`default_factory`** | The callable `defaultdict` calls to create a missing key's default value. |
| **`KeyError`** | The error a plain `dict` raises when you access a missing key. `defaultdict` and `Counter` never raise this for reads. |
| **Frequency / Count** | How many times an element appears. `Counter` stores this as the value. |
| **Most Common** | The element with the highest count. `Counter.most_common(n)` returns the top-n. |
| **`move_to_end`** | `OrderedDict` method: moves a key to the front or back of the order. |
| **`popitem(last=True)`** | `OrderedDict` method: removes and returns the last (or first) inserted item. |
| **LRU Cache** | Least Recently Used cache — evicts the item accessed least recently. Built on `OrderedDict`. |

## 4. `defaultdict` — The Dict That Creates Its Own Defaults

### 4.1 The Problem It Solves

Every time you group data with a plain `dict`, you write a guard:

```python
# Without defaultdict — the "check before you write" boilerplate
groups = {}
for student, subject in enrollments:
    if student not in groups:       # Guard — check every single time
        groups[student] = []        # Create the list manually
    groups[student].append(subject) # Now safe to append
```

This pattern — *check if key exists, create if not, then use* — appears hundreds of times in real codebases. `defaultdict` collapses it to one line:

```python
# With defaultdict — the guard disappears entirely
from collections import defaultdict

groups = defaultdict(list)
for student, subject in enrollments:
    groups[student].append(subject)   # Missing key? list() is called automatically.
```

### 4.2 How `defaultdict` Works

```
Regular dict:
d["missing_key"]  →  KeyError ✗

defaultdict(list):
d["missing_key"]  →  calls list() → stores [] → returns []  ✓
d["missing_key"]  →  now returns the same []  ✓
```

The `default_factory` is a **callable** (a function, a class, a lambda). When you access a key that doesn't exist, `defaultdict` calls `default_factory()` with no arguments, stores the result at that key, and returns it. The key is now in the dict — it was silently created.

```python
from collections import defaultdict

# default_factory = int → calls int() = 0
counter = defaultdict(int)
counter["apples"] += 1     # No guard needed — missing key gets 0 first
counter["apples"] += 1
counter["bananas"] += 1
print(dict(counter))       # {"apples": 2, "bananas": 1}

# default_factory = list → calls list() = []
buckets = defaultdict(list)
buckets["fruits"].append("mango")
buckets["fruits"].append("banana")
buckets["veggies"].append("carrot")
print(dict(buckets))
# {"fruits": ["mango", "banana"], "veggies": ["carrot"]}

# default_factory = set → calls set() = set()
unique_visitors = defaultdict(set)
unique_visitors["homepage"].add("Alice")
unique_visitors["homepage"].add("Alice")   # Duplicate — silently ignored
unique_visitors["homepage"].add("Bob")
print(dict(unique_visitors))
# {"homepage": {"Alice", "Bob"}}

# default_factory = lambda → any custom default
prices = defaultdict(lambda: 9.99)   # Every unknown item costs 9.99
prices["apple"] = 1.50
print(prices["apple"])    # 1.50
print(prices["durian"])   # 9.99 — missing key gets the lambda's return value
```

### 4.3 Critical Distinction — `[]` vs `.get()`

```python
d = defaultdict(list)

# This CREATES the key (calls list(), stores [])
x = d["new_key"]         # d now has "new_key": []

# This does NOT create the key (uses .get() which bypasses default_factory)
x = d.get("new_key2")    # Returns None — "new_key2" is NOT added to d
```

This distinction matters when you want to check existence without accidentally creating an entry.

### 4.4 Practical Patterns

**Graph as Adjacency List**

```python
edges = [("A", "B"), ("A", "C"), ("B", "D"), ("C", "D"), ("D", "E")]

graph = defaultdict(list)
for src, dst in edges:
    graph[src].append(dst)

print(dict(graph))
# {"A": ["B", "C"], "B": ["D"], "C": ["D"], "D": ["E"]}

# BFS on this graph — every node lookup is safe, even leaf nodes
from collections import deque

def bfs(graph, start):
    visited = set()
    queue   = deque([start])
    order   = []
    while queue:
        node = queue.popleft()
        if node not in visited:
            visited.add(node)
            order.append(node)
            queue.extend(graph[node])   # graph["E"] returns [] safely
    return order

print(bfs(graph, "A"))   # ["A", "B", "C", "D", "E"]
```

**Inverted Index (Search Engine Core)**

```python
documents = {
    "doc1": "python dict hashmap tutorial",
    "doc2": "python list tutorial beginner",
    "doc3": "hashmap collision chaining",
}

index = defaultdict(list)
for doc_id, text in documents.items():
    for word in text.split():
        index[word].append(doc_id)

print(dict(index))
# {"python": ["doc1", "doc2"], "dict": ["doc1"],
#  "hashmap": ["doc1", "doc3"], "tutorial": ["doc1", "doc2"], ...}

# Search: which docs contain "python" AND "hashmap"?
result = set(index["python"]) & set(index["hashmap"])
print(result)   # {"doc1"}
```

## 5. `Counter` — The Dict That Counts

### 5.1 The Problem It Solves

Counting element frequencies is one of the most common operations in programming. The plain `dict` pattern works — but it is verbose:

```python
# Without Counter — boilerplate every time
text = "banana"
freq = {}
for ch in text:
    freq[ch] = freq.get(ch, 0) + 1
print(freq)   # {"b": 1, "a": 3, "n": 2}
```

`Counter` collapses this to one constructor call — and adds powerful methods on top:

```python
from collections import Counter

freq = Counter("banana")
print(freq)   # Counter({"a": 3, "n": 2, "b": 1})
```

### 5.2 Creating a Counter

```python
from collections import Counter

# From a string — counts characters
Counter("mississippi")
# Counter({"s": 4, "i": 4, "p": 2, "m": 1})

# From a list — counts elements
Counter(["apple", "banana", "apple", "cherry", "banana", "apple"])
# Counter({"apple": 3, "banana": 2, "cherry": 1})

# From a dict — initialise with known counts
Counter({"red": 4, "blue": 2, "green": 1})

# From keyword arguments
Counter(cats=3, dogs=1, fish=2)
# Counter({"cats": 3, "fish": 2, "dogs": 1})

# From a generator
Counter(len(word) for word in ["hi", "hello", "hey", "world"])
# Counter({5: 2, 2: 1, 3: 1})
```

### 5.3 Core Operations

```python
from collections import Counter

votes = Counter(["Ravi", "Meena", "Ravi", "Arjun", "Meena", "Ravi", "Priya"])
print(votes)
# Counter({"Ravi": 3, "Meena": 2, "Arjun": 1, "Priya": 1})

# Access count — NEVER raises KeyError; returns 0 for missing keys
print(votes["Ravi"])      # 3
print(votes["Nobody"])    # 0 — not KeyError

# most_common(n) — top n elements by count
print(votes.most_common(2))
# [("Ravi", 3), ("Meena", 2)]

print(votes.most_common(1))    # Winner
# [("Ravi", 3)]

# Total count of all elements
print(votes.total())           # 7  (Python 3.10+)
print(sum(votes.values()))     # 7  (any version)

# elements() — expands back into an iterator of individual elements
print(list(votes.elements()))
# ["Ravi", "Ravi", "Ravi", "Meena", "Meena", "Arjun", "Priya"]

# Update — add more counts (does NOT reset, adds on top)
votes.update(["Meena", "Meena", "Priya"])
print(votes)
# Counter({"Ravi": 3, "Meena": 4, "Arjun": 1, "Priya": 2})

# Subtract — decrease counts (can go negative)
votes.subtract(["Ravi", "Ravi"])
print(votes["Ravi"])     # 1
```

### 5.4 Counter Arithmetic — The Killer Feature

Counters support `+`, `-`, `&`, `|` — just like sets, but on counts:

```python
from collections import Counter

shop_a = Counter({"apples": 5, "bananas": 3, "grapes": 2})
shop_b = Counter({"apples": 2, "bananas": 4, "mangoes": 6})

# Addition — combine inventories (sum counts)
combined = shop_a + shop_b
print(combined)
# Counter({"mangoes": 6, "apples": 7, "bananas": 7, "grapes": 2})

# Subtraction — only keeps positive results
diff = shop_a - shop_b
print(diff)
# Counter({"apples": 3, "grapes": 2})  ← bananas: 3-4 = -1, dropped

# Intersection — minimum count of each element
overlap = shop_a & shop_b
print(overlap)
# Counter({"apples": 2, "bananas": 3})

# Union — maximum count of each element
either = shop_a | shop_b
print(either)
# Counter({"mangoes": 6, "apples": 5, "bananas": 4, "grapes": 2})
```

### 5.5 Practical Patterns

**Top-N Most Frequent Words**

```python
from collections import Counter
import re

article = """
Python is a versatile language. Python is used in web development,
data science, automation, and artificial intelligence. Python is simple.
"""

words   = re.findall(r"\b\w+\b", article.lower())
freq    = Counter(words)

print(freq.most_common(5))
# [("python", 3), ("is", 3), ("a", 2), ("in", 1), ("web", 1)]
```

**Anagram Check**

```python
from collections import Counter

def is_anagram(s1, s2):
    return Counter(s1.lower()) == Counter(s2.lower())

print(is_anagram("listen", "silent"))    # True
print(is_anagram("hello", "world"))      # False
```

**Finding Missing Elements**

```python
from collections import Counter

required = Counter(["A", "B", "B", "C", "C", "C"])
have     = Counter(["A", "B", "C"])

missing = required - have
print(missing)   # Counter({"C": 2, "B": 1}) — need 2 more C, 1 more B
```

## 6. `OrderedDict` — The Dict That Remembers Order

### 6.1 The Problem It Solves

In Python 3.7+, regular `dict` preserves insertion order. So why does `OrderedDict` still exist?

Three reasons that a plain `dict` cannot match:

```
1. move_to_end(key, last=True)  — move any key to front or back in O(1)
2. popitem(last=True)           — remove and return last (or first) item
3. Order-aware equality         — OrderedDict(a=1, b=2) ≠ OrderedDict(b=2, a=1)
                                  Regular dict: {"a":1,"b":2} == {"b":2,"a":1}  ← True!
```

The most important use case is the **LRU Cache** — a cache that evicts the least-recently-used item when full. This requires moving a key to the end on access and popping from the front on eviction. `OrderedDict` makes both operations O(1).

### 6.2 Creating an OrderedDict

```python
from collections import OrderedDict

# From keyword arguments — order is preserved (Python 3.7+ always)
settings = OrderedDict(theme="dark", lang="en", font_size=14)

# From a list of pairs — order explicitly defined
config = OrderedDict([("host", "localhost"), ("port", 5432), ("debug", False)])

# Or build it step by step
od = OrderedDict()
od["first"]  = 1
od["second"] = 2
od["third"]  = 3
print(list(od.keys()))   # ["first", "second", "third"] — guaranteed
```

### 6.3 Core Operations

```python
from collections import OrderedDict

od = OrderedDict([("a", 1), ("b", 2), ("c", 3), ("d", 4)])

# move_to_end — move key to the LAST position
od.move_to_end("a")
print(list(od.keys()))   # ["b", "c", "d", "a"]

# move_to_end with last=False — move key to the FIRST position
od.move_to_end("a", last=False)
print(list(od.keys()))   # ["a", "b", "c", "d"]

# popitem(last=True) — remove and return LAST item (LIFO)
key, val = od.popitem(last=True)
print(key, val)            # d 4
print(list(od.keys()))     # ["a", "b", "c"]

# popitem(last=False) — remove and return FIRST item (FIFO)
key, val = od.popitem(last=False)
print(key, val)            # a 1
print(list(od.keys()))     # ["b", "c"]

# Order-sensitive equality
od1 = OrderedDict([("x", 1), ("y", 2)])
od2 = OrderedDict([("y", 2), ("x", 1)])
print(od1 == od2)          # False — same keys, same values, different order
print(dict(od1) == dict(od2))   # True — plain dicts don't care about order
```

### 6.4 Building an LRU Cache with `OrderedDict`

This is the canonical real-world use case — and the reason `OrderedDict` exists.

```
LRU Cache rule:
- Maximum capacity = N items
- On access: move that item to the MOST-RECENT end
- On insert (when full): evict the LEAST-RECENT item (the front)

OrderedDict makes both operations O(1):
  move_to_end(key)       → mark as recently used
  popitem(last=False)    → evict least recently used
```

```python
from collections import OrderedDict

class LRUCache:
    """
    Least Recently Used Cache.
    get() and put() both run in O(1).
    Evicts the least-recently-used item when capacity is exceeded.
    """

    def __init__(self, capacity: int):
        self._capacity = capacity
        self._cache    = OrderedDict()   # Maintains recency order

    def get(self, key):
        """Return value for key, or -1 if not found. Marks key as recently used."""
        if key not in self._cache:
            return -1
        self._cache.move_to_end(key)     # Most recently used → move to end
        return self._cache[key]

    def put(self, key, value):
        """Insert or update key-value pair. Evicts LRU item if over capacity."""
        if key in self._cache:
            self._cache.move_to_end(key) # Update recency
        self._cache[key] = value
        if len(self._cache) > self._capacity:
            self._cache.popitem(last=False)  # Evict least recently used (front)

    def __repr__(self):
        return f"LRUCache({dict(self._cache)})"


# Demo: Cache with capacity 3
cache = LRUCache(3)
cache.put("page_home",    "<html>Home</html>")
cache.put("page_about",   "<html>About</html>")
cache.put("page_contact", "<html>Contact</html>")
print(cache)
# LRUCache({"page_home": ..., "page_about": ..., "page_contact": ...})

cache.get("page_home")           # Access home — moves to most-recent end
cache.put("page_pricing", "<html>Pricing</html>")  # Cache full → evict LRU

print(cache.get("page_about"))   # -1 — page_about was evicted (least recently used)
print(cache.get("page_home"))    # "<html>Home</html>" — still in cache
```

## 8. Complete Program

```python
from collections import defaultdict, Counter, OrderedDict


# ─────────────────────────────────────────────────────────────────────────────
# SECTION A: defaultdict — School Library Borrowing System
# ─────────────────────────────────────────────────────────────────────────────

borrowings = [
    ("Arjun",  "Wings of Fire"),
    ("Meena",  "Python Crash Course"),
    ("Arjun",  "The Alchemist"),
    ("Priya",  "Wings of Fire"),
    ("Meena",  "Clean Code"),
    ("Arjun",  "Wings of Fire"),
    ("Priya",  "The Alchemist"),
]

# Group books per student — no guard needed
by_student = defaultdict(list)
for student, book in borrowings:
    by_student[student].append(book)

print("=== Library Borrowings (defaultdict) ===")
for student, books in by_student.items():
    print(f"  {student}: {books}")

# Count unique students per book — using set as default
students_per_book = defaultdict(set)
for student, book in borrowings:
    students_per_book[book].add(student)

print("\nUnique readers per book:")
for book, students in students_per_book.items():
    print(f"  {book!r}: {sorted(students)}")


# ─────────────────────────────────────────────────────────────────────────────
# SECTION B: Counter — Election Vote Counter
# ─────────────────────────────────────────────────────────────────────────────

ballot_box = [
    "Ravi", "Meena", "Ravi", "Priya", "Meena",
    "Ravi", "Arjun", "Meena", "Ravi", "Priya",
    "Arjun", "Ravi", "Meena", "Meena",
]

votes = Counter(ballot_box)

print("\n=== Election Results (Counter) ===")
print(f"  All votes  : {dict(votes)}")
print(f"  Winner     : {votes.most_common(1)[0][0]}  ({votes.most_common(1)[0][1]} votes)")
print(f"  Top 2      : {votes.most_common(2)}")
print(f"  Total cast : {sum(votes.values())}")

# Combine two polling booths
booth_2 = Counter({"Ravi": 3, "Meena": 5, "Arjun": 2})
combined = votes + booth_2
print(f"\nCombined (both booths):")
print(f"  {dict(combined)}")
print(f"  Final winner: {combined.most_common(1)[0][0]}")


# ─────────────────────────────────────────────────────────────────────────────
# SECTION C: OrderedDict — LRU Cache for a News Website
# ─────────────────────────────────────────────────────────────────────────────

class LRUCache:
    def __init__(self, capacity):
        self._capacity = capacity
        self._cache    = OrderedDict()

    def get(self, key):
        if key not in self._cache:
            return None
        self._cache.move_to_end(key)
        return self._cache[key]

    def put(self, key, value):
        if key in self._cache:
            self._cache.move_to_end(key)
        self._cache[key] = value
        if len(self._cache) > self._capacity:
            evicted = self._cache.popitem(last=False)
            print(f"  [EVICTED] {evicted[0]!r}")

    def snapshot(self):
        return list(self._cache.keys())


news_cache = LRUCache(capacity=3)

print("\n=== News Cache (OrderedDict LRU, cap=3) ===")
news_cache.put("sports",       "India wins T20!")
news_cache.put("technology",   "AI model released")
news_cache.put("finance",      "Sensex hits record")

print("Cache:", news_cache.snapshot())          # [sports, technology, finance]

news_cache.get("sports")                        # Access sports → moves to end
news_cache.put("politics", "Parliament session")  # Full → evict LRU

print("After politics added:", news_cache.snapshot())
# technology evicted (least recently used); sports was accessed so it survived
print("Technology still cached?", news_cache.get("technology") is not None)  # False


# ─────────────────────────────────────────────────────────────────────────────
# SECTION D: All Three Together — Log Analysis Pipeline
# ─────────────────────────────────────────────────────────────────────────────

server_logs = [
    ("ERROR",   "/api/login",    "user_101"),
    ("INFO",    "/api/home",     "user_202"),
    ("ERROR",   "/api/checkout", "user_303"),
    ("WARNING", "/api/login",    "user_101"),
    ("ERROR",   "/api/login",    "user_404"),
    ("INFO",    "/api/profile",  "user_202"),
    ("ERROR",   "/api/checkout", "user_101"),
    ("WARNING", "/api/home",     "user_303"),
]

# defaultdict: group log entries by severity
by_severity = defaultdict(list)
for level, endpoint, user in server_logs:
    by_severity[level].append((endpoint, user))

# Counter: count errors per endpoint
error_freq = Counter(
    endpoint for level, endpoint, user in server_logs if level == "ERROR"
)

# OrderedDict: record the first-seen timestamp of each user (insertion order = time order)
first_seen = OrderedDict()
for level, endpoint, user in server_logs:
    if user not in first_seen:
        first_seen[user] = endpoint   # First endpoint this user hit

print("\n=== Log Analysis Pipeline ===")
print("Errors by endpoint:", dict(error_freq))
print("Most problematic  :", error_freq.most_common(1)[0])
print("ERROR entries     :", by_severity["ERROR"])
print("First-seen users  :", dict(first_seen))
```

## 9. When to Use Which

| Situation | Use |
|-----------|-----|
| Grouping items by category (students → courses, words → documents) | `defaultdict(list)` |
| Collecting unique items per key (users → visited pages) | `defaultdict(set)` |
| Counting anything from scratch (votes, words, errors, events) | `Counter` |
| Top-N most frequent elements | `Counter.most_common(n)` |
| Combining frequency counts from multiple sources | `Counter` arithmetic `+` `\|` |
| Anagram / permutation detection | `Counter` equality |
| LRU cache implementation | `OrderedDict` |
| Removing items in insertion order (FIFO queue over dict) | `OrderedDict.popitem(last=False)` |
| Order-sensitive dict equality checks | `OrderedDict` |
| Everything else — basic key-value storage | plain `dict` |

## 10. Common Mistakes

**Mistake 1 — Accessing a `defaultdict` key you didn't intend to create**

```python
from collections import defaultdict

d = defaultdict(list)

# Checking membership like this CREATES the key
if d["user_999"]:         # Accesses "user_999" → creates [] → evaluates as False
    print("Found")
print("user_999" in d)   # True! The key was created by the check above

# Correct way to check without creating
if "user_999" in d:       # in-check does NOT trigger default_factory
    print("Found")
print("user_999" in d)   # Still False — key was not created
```

**Mistake 2 — Using `Counter` subtraction and expecting negatives**

```python
from collections import Counter

a = Counter({"x": 2, "y": 1})
b = Counter({"x": 5, "y": 3})

result = a - b
print(result)   # Counter() — empty! Negatives are dropped by -

# To keep negatives, use subtract() instead
a.subtract(b)
print(a)        # Counter({"x": -3, "y": -2}) — negatives preserved
```

**Mistake 3 — Calling `Counter.update()` when you mean to reset**

```python
from collections import Counter

c = Counter({"a": 3, "b": 2})
c.update({"a": 1})       # ADDS 1 to "a" — result: {"a": 4, "b": 2}

# To reset to a new count, reassign entirely
c = Counter({"a": 1})    # Fresh counter — {"a": 1}
```

**Mistake 4 — Treating `Counter` missing keys as errors**

```python
from collections import Counter

c = Counter("hello")

# This is safe — never raises KeyError
print(c["z"])   # 0 — "z" was never counted, returns 0

# But after this access, "z" is NOT added to the counter
print("z" in c) # False — Counter doesn't create missing keys on access (unlike defaultdict)
```

**Mistake 5 — Assuming regular `dict` and `OrderedDict` equality is the same**

```python
from collections import OrderedDict

d1 = {"x": 1, "y": 2}
d2 = {"y": 2, "x": 1}
print(d1 == d2)   # True — plain dicts ignore order

od1 = OrderedDict([("x", 1), ("y", 2)])
od2 = OrderedDict([("y", 2), ("x", 1)])
print(od1 == od2)   # False — OrderedDicts are order-sensitive

print(od1 == d1)    # True — OrderedDict == plain dict ignores order
```

**Mistake 6 — Forgetting to import from `collections`**

```python
# None of these are builtins — they require explicit import
from collections import defaultdict, Counter, OrderedDict

# Common mistake in interviews and exams:
d = defaultdict(list)   # NameError if import forgotten
```

## 11. Time and Space Complexity

All three are built on Python's `dict` internally. Their complexity mirrors `dict` — with the overhead of their added features.

| Operation | `defaultdict` | `Counter` | `OrderedDict` |
|-----------|--------------|-----------|---------------|
| `d[key]` / get | O(1) avg | O(1) avg (returns 0 if missing) | O(1) avg |
| `d[key] = v` / put | O(1) avg | O(1) avg | O(1) avg |
| `del d[key]` | O(1) avg | O(1) avg | O(1) avg |
| `key in d` | O(1) | O(1) | O(1) |
| `most_common(n)` | — | O(k log n) where k = unique elements | — |
| `elements()` | — | O(n) total elements | — |
| `Counter + Counter` | — | O(k) | — |
| `move_to_end(key)` | — | — | **O(1)** |
| `popitem(last=)` | — | — | **O(1)** |
| Iteration | O(n) | O(n) | O(n) |
| Space | O(n) | O(k) unique | O(n) + order overhead |

The real cost difference: `Counter.most_common(n)` uses `heapq.nlargest` internally — O(k log n), not O(k log k) like a full sort. For large counters with small `n`, this is significantly faster.

## 13. Summary

| Concept | Meaning |
|---------|---------|
| `defaultdict(factory)` | `dict` that calls `factory()` to create a default for missing keys |
| `defaultdict(int)` | Default = `0` — perfect for counting without `.get(k, 0)` |
| `defaultdict(list)` | Default = `[]` — perfect for grouping without `if k not in d` |
| `defaultdict(set)` | Default = `set()` — perfect for unique grouping |
| `d["missing"]` on `defaultdict` | Creates the key — use `"missing" in d` to check without creating |
| `Counter(iterable)` | Counts element frequencies in one call — subclass of `dict` |
| `c["missing"]` on `Counter` | Returns `0`, never `KeyError`, never creates the key |
| `c.most_common(n)` | Top-n elements by count — O(k log n) using `heapq` |
| `Counter + Counter` | Combine counts (sum); `-` drops negatives; `&` min; `\|` max |
| `c.subtract(other)` | Subtract counts, keeping negatives (unlike `-` operator) |
| `c.elements()` | Expands counter back into iterator of individual elements |
| `OrderedDict` | `dict` that preserves insertion order + `move_to_end` + `popitem(last=)` |
| `od.move_to_end(key)` | Move key to last (default) or first position — O(1) |
| `od.popitem(last=True)` | Remove and return last (LIFO) or first (FIFO) item — O(1) |
| `OrderedDict` equality | Order-sensitive: `OD(a=1,b=2) ≠ OD(b=2,a=1)` |
| LRU Cache pattern | `OrderedDict` + `move_to_end` on access + `popitem(last=False)` on eviction |
| Import | `from collections import defaultdict, Counter, OrderedDict` |

The `collections` module gives you three specialised swords where `dict` gives you one general-purpose knife. Each one eliminates a whole category of boilerplate — the `if key not in d` guard, the `freq.get(k, 0) + 1` dance, the manual order bookkeeping. Once you reach for the right one instinctively, your code gets shorter, faster, and easier to read.
