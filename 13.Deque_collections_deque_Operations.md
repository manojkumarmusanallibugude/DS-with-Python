# Deque — `collections.deque` Operations

---

## Before We Begin — What Problem Are We Even Solving?

Imagine you are managing a queue of customers at a bank.

A new VIP customer walks in. They get priority and must be added to the **front** of the line — not the back.

At the same time, your manager calls and says the last person who just joined the queue accidentally came to the wrong branch. They need to be removed from the **back** of the line — instantly.

Now think about the data structures you already know:

- A **regular queue** (`list` or linked list) lets you add at the back and remove from the front. That's it.
- A **stack** lets you add and remove only from the top.

Neither can do both: **add or remove from either end** in constant time.

You need something more powerful. Something that is a **queue and a stack simultaneously**.

That something is a **Deque** — pronounced *deck*, short for **Double-Ended Queue**.

---

## The Core Idea — What Is a Deque?

A **Deque** (Double-Ended Queue) is a data structure that allows you to **add and remove elements from both ends** — the front and the rear — efficiently.

```
Regular Queue:                    Deque:

  Only add here → [ ] [ ] [ ]    ← Add OR remove here
                        ↓         [ ] [ ] [ ]
               Only remove here    → Add OR remove here
```

The deque combines the strengths of both a stack and a queue, without the weaknesses of either:

```
                   FRONT                       REAR
                     │                           │
                     ▼                           ▼
                ┌────────────────────────────────────┐
appendleft() →  │  10  │  20  │  30  │  40  │  50  │  ← append()
  popleft()  ←  │                                    │  → pop()
                └────────────────────────────────────┘
```

Four operations. Two ends. All in **O(1)** time.

This is what makes the deque unique.

---

## Why Does This Matter? The Real-World Motivation

Let's be honest — you already know lists. Why learn deque?

| Operation | Python `list` | `collections.deque` |
|---|---|---|
| Add to **right** (append) | O(1) amortised | O(1) always |
| Add to **left** (prepend) | **O(n) — shifts all elements** | **O(1) always** |
| Remove from **right** | O(1) | O(1) |
| Remove from **left** | **O(n) — shifts all elements** | **O(1) always** |
| Random access by index | O(1) | O(n) |
| Fixed max size | Manual | Built-in with `maxlen` |

The critical difference: **`list` is catastrophically slow at its left end.**

When you do `list.insert(0, x)` or `list.pop(0)` on a list of 1,000,000 elements, Python physically moves all 1,000,000 elements one position in memory. Every. Single. Time.

**Numerical reality:**

```
list of 1,000,000 elements:
  list.insert(0, x)  → moves 1,000,000 elements → ~1 million operations
  deque.appendleft(x) → updates 2 pointers       → ~constant operations

  If you do this 1,000 times:
  list:  1,000,000,000 operations  ← unusable
  deque:         ~1,000 operations ← instant
```

Deque is the right tool whenever you need **O(1) operations on both ends**.

Real-world uses:
- **Sliding window algorithms** — add to right, remove from left as window moves
- **Browser history** — back (left end) and forward (right end) navigation
- **Undo/Redo systems** — bounded history with `maxlen`
- **Palindrome checking** — compare and remove from both ends simultaneously
- **BFS (Breadth-First Search)** — enqueue at right, dequeue from left
- **Work-stealing schedulers** — threads steal tasks from each other's deques

---

## Introducing `collections.deque` — Python's Built-In Double-Ended Queue

Python's `collections.deque` is implemented in **C** inside the Python interpreter. It is not a Python-level linked list — it is a highly optimised **doubly linked list of fixed-size memory blocks**.

You don't need to install anything. It's in the standard library.

```python
from collections import deque
```

That's it.

Here's the key insight:

> Unlike `heapq` which works on a plain list, `deque` is its **own object** — a first-class data structure with built-in methods for both ends.

```python
from collections import deque

dq = deque([10, 20, 30])

dq.append(40)        # Add to right  → deque([10, 20, 30, 40])
dq.appendleft(5)     # Add to left   → deque([5, 10, 20, 30, 40])
dq.pop()             # Remove right  → 40, deque([5, 10, 20, 30])
dq.popleft()         # Remove left   → 5,  deque([10, 20, 30])

print(dq)            # deque([10, 20, 30])
```

All four operations — O(1). No shifting. No reallocation.

---

## How `deque` Works Internally — The Block Structure

Understanding the internals helps you understand *why* deque is fast and *where* it is slow.

A `deque` is NOT a linked list of individual nodes. It is a **doubly linked list of fixed-size blocks**, where each block holds multiple elements.

```
Memory layout of deque([10, 20, 30, 40, 50, 60, 70]):

   left_ptr                                     right_ptr
      │                                               │
      ▼                                               ▼
  ┌───────────┐       ┌───────────┐       ┌───────────┐
  │ 10 │ 20  │ ◄───► │ 30 │ 40  │ ◄───► │ 50 │ 60  │
  └───────────┘       └───────────┘       └───────────┘
      ▲                                               ▲
   front index                                   rear index
   (within this block)                        (within this block)
```

Each block holds ~62 elements (implementation detail — varies by Python version).

**Why this is faster than a node-per-element linked list:**
- Fewer memory allocations (one block per 62 elements, not one per element)
- Better **cache locality** — elements in the same block sit side by side in RAM
- Pointer chasing only happens when crossing block boundaries

**Why random index access is O(n):**
- To find element at index `i`, Python must count through blocks from the nearest end
- No direct jump to a memory address like a list can do
- This is the **trade-off**: O(1) at both ends, but O(n) for the middle

## All Operations — Step by Step

### Creating a Deque

```python
from collections import deque

# Empty deque
dq1 = deque()
print(dq1)                  # deque([])

# From an iterable
dq2 = deque([1, 2, 3, 4, 5])
print(dq2)                  # deque([1, 2, 3, 4, 5])

# From a string
dq3 = deque("hello")
print(dq3)                  # deque(['h', 'e', 'l', 'l', 'o'])

# With a maximum size (bounded deque)
dq4 = deque([1, 2, 3], maxlen=5)
print(dq4)                  # deque([1, 2, 3], maxlen=5)
print(dq4.maxlen)           # 5
```

---

### Adding Elements — `append()` and `appendleft()`

```python
from collections import deque

dq = deque([20, 30, 40])

dq.append(50)           # Add to the RIGHT end — O(1)
print(dq)               # deque([20, 30, 40, 50])

dq.appendleft(10)       # Add to the LEFT end — O(1)
print(dq)               # deque([10, 20, 30, 40, 50])
```

**Trace — what happens in memory:**

```
Initial: [ 20 | 30 | 40 ]
          front       rear

After append(50):
         [ 20 | 30 | 40 | 50 ]
                          ▲
                    50 placed here — rear pointer advanced

After appendleft(10):
         [ 10 | 20 | 30 | 40 | 50 ]
           ▲
     10 placed here — front pointer moved back
```

No element was shifted. Two pointer updates. That's all.

---

### Adding Multiple Elements — `extend()` and `extendleft()`

```python
from collections import deque

dq = deque([3, 4, 5])

dq.extend([6, 7, 8])           # Add multiple to the RIGHT — O(k)
print(dq)                      # deque([3, 4, 5, 6, 7, 8])

dq.extendleft([2, 1, 0])       # Add multiple to the LEFT — O(k)
print(dq)                      # deque([0, 1, 2, 3, 4, 5, 6, 7, 8])
```

**⚠️ Important — `extendleft` reverses the order:**

```python
dq = deque([10, 20, 30])
dq.extendleft([1, 2, 3])
print(dq)    # deque([3, 2, 1, 10, 20, 30])
#                     ▲  ▲  ▲
#             NOT [1, 2, 3, 10, 20, 30] !
```

Why? Because `extendleft([1, 2, 3])` is equivalent to:
```python
dq.appendleft(1)   # deque([1, 10, 20, 30])
dq.appendleft(2)   # deque([2, 1, 10, 20, 30])
dq.appendleft(3)   # deque([3, 2, 1, 10, 20, 30])
```

Each `appendleft` pushes the new element **before** the previous one. The original order is reversed.

---

### Removing Elements — `pop()` and `popleft()`

```python
from collections import deque

dq = deque([10, 20, 30, 40, 50])

right = dq.pop()          # Remove from RIGHT — O(1)
print(right)              # 50
print(dq)                 # deque([10, 20, 30, 40])

left = dq.popleft()       # Remove from LEFT — O(1)
print(left)               # 10
print(dq)                 # deque([20, 30, 40])
```

**What happens if you pop from an empty deque:**

```python
dq = deque()
dq.pop()       # IndexError: pop from an empty deque
dq.popleft()   # IndexError: pop from an empty deque
```

Always check before popping:

```python
if dq:               # deque is falsy when empty
    val = dq.pop()
```

### Inspecting Without Removing — Peek Both Ends

`deque` has no built-in `peek()` method. Use index access:

```python
from collections import deque

dq = deque([10, 20, 30, 40, 50])

print(dq[0])     # 10  — peek left/front  — O(1) (special-cased)
print(dq[-1])    # 50  — peek right/rear  — O(1) (special-cased)
print(dq[2])     # 30  — middle element   — O(n) (traverses blocks)
```

The endpoints (`dq[0]` and `dq[-1]`) are O(1) because the deque tracks both ends directly. Middle elements require traversal — avoid indexing into the middle of a large deque in a loop.

---

### Rotating — `rotate()`

`rotate(n)` shifts all elements by n positions. It is one of the deque's most distinctive operations.

```python
from collections import deque

dq = deque([1, 2, 3, 4, 5])

dq.rotate(2)      # Rotate RIGHT by 2 positions
print(dq)         # deque([4, 5, 1, 2, 3])
#                          ▲  ▲
#                   4 and 5 moved from right to left

dq.rotate(-2)     # Rotate LEFT by 2 positions (undo the above)
print(dq)         # deque([1, 2, 3, 4, 5])
```

**How rotation works internally:**

```
Original:  [ 1 | 2 | 3 | 4 | 5 ]
                                ↑ right end

rotate(2) — move 2 elements from right to left:
  Step 1: pop 5 from right → appendleft(5) → [ 5 | 1 | 2 | 3 | 4 ]
  Step 2: pop 4 from right → appendleft(4) → [ 4 | 5 | 1 | 2 | 3 ]

Result: [ 4 | 5 | 1 | 2 | 3 ]

rotate(-2) — move 2 elements from left to right:
  Step 1: popleft 4 → append(4) → [ 5 | 1 | 2 | 3 | 4 ]
  Step 2: popleft 5 → append(5) → [ 1 | 2 | 3 | 4 | 5 ]
```

**Time complexity:** O(k) where k is the rotation amount. Since each step is O(1), rotating by k steps costs O(k).

### Other Useful Operations

```python
from collections import deque

dq = deque([10, 20, 30, 20, 40, 20])

# count() — how many times a value appears
print(dq.count(20))       # 3  — O(n)

# index() — find position of first occurrence
print(dq.index(30))       # 2  — O(n)

# remove() — remove first occurrence of a value
dq.remove(20)
print(dq)                 # deque([10, 30, 20, 40, 20])  — first 20 removed

# reverse() — reverse the deque in place
dq.reverse()
print(dq)                 # deque([20, 40, 20, 30, 10])  — O(n)

# clear() — remove all elements
dq.clear()
print(dq)                 # deque([])
print(len(dq))            # 0

# copy() — shallow copy
dq = deque([1, 2, 3])
dq2 = dq.copy()
dq2.append(4)
print(dq)                 # deque([1, 2, 3])   — original unchanged
print(dq2)                # deque([1, 2, 3, 4])
```

### The `maxlen` Parameter — Bounded Deque

`maxlen` is one of the most powerful and underused features of `deque`.

When you set `maxlen=n`, the deque can never hold more than n elements. When it is full and you add a new element:
- `append()` from the right **automatically drops the leftmost (oldest) element**
- `appendleft()` from the left **automatically drops the rightmost (newest) element**

```python
from collections import deque

# A sliding window of the last 3 values
window = deque(maxlen=3)

for value in [10, 20, 30, 40, 50]:
    window.append(value)
    print(f"Added {value}: {list(window)}")
```

**Output:**
```
Added 10: [10]
Added 20: [10, 20]
Added 30: [10, 20, 30]   ← window full
Added 40: [20, 30, 40]   ← 10 dropped automatically
Added 50: [30, 40, 50]   ← 20 dropped automatically
```

**No manual removal needed. No IndexError. No size checking.**

The `maxlen` is **immutable after creation** — you cannot change it later:

```python
dq = deque(maxlen=5)
print(dq.maxlen)    # 5
dq.maxlen = 10      # AttributeError: attribute 'maxlen' of 'deque' objects is not writable
```

## Time and Space Complexity — Complete Reference

| Operation | Time | Notes |
|---|---|---|
| `append(x)` | **O(1)** | Add to right |
| `appendleft(x)` | **O(1)** | Add to left |
| `pop()` | **O(1)** | Remove from right |
| `popleft()` | **O(1)** | Remove from left |
| `extend(iterable)` | O(k) | k = length of iterable |
| `extendleft(iterable)` | O(k) | Reverses order |
| `rotate(n)` | O(n) | n = rotation amount |
| `dq[0]` or `dq[-1]` | **O(1)** | Both ends special-cased |
| `dq[i]` (middle) | O(n) | Traverses block chain |
| `len(dq)` | **O(1)** | Maintained as a counter |
| `count(x)` | O(n) | Scans all elements |
| `index(x)` | O(n) | Scans until found |
| `remove(x)` | O(n) | Finds then removes |
| `reverse()` | O(n) | In-place |
| `clear()` | O(n) | Frees all blocks |
| Space | O(n) | n elements + block overhead |

**The golden rule of deque:** Use it for O(1) left/right operations. Avoid middle-index access in hot loops.

## Numerical Comparison — `list` vs `deque` at Scale

Let's make the performance difference concrete.

**Scenario:** You need to maintain a queue of 100,000 items and process 100,000 insertions at the left end.

```
list.insert(0, x) — shifts all existing elements:
  Insertion 1:       1 element shifted
  Insertion 2:       2 elements shifted
  Insertion 3:       3 elements shifted
  ...
  Insertion 100,000: 99,999 elements shifted

  Total shifts = 1 + 2 + 3 + ... + 99,999
               = 99,999 × 100,000 / 2
               = 4,999,950,000 operations  ← ~5 billion

deque.appendleft(x) — updates pointers:
  Each insertion: ~constant operations
  Total = 100,000 × constant ≈ 100,000 operations ← 50,000× faster
```

**Scenario:** Sliding window of size k=3 over a stream of 1,000,000 values.

```
With list (remove from left via pop(0)):
  Each pop(0) shifts remaining window elements
  1,000,000 × 3 shifts = 3,000,000 operations

With deque (popleft()):
  Each popleft() is O(1)
  1,000,000 × 1 = 1,000,000 operations
  → 3× faster for small k, 1000× faster for k=1000
```

## Practical Patterns

### Pattern 1 — Sliding Window Maximum

Given a list of numbers and a window size k, find the maximum value in every window as it slides across the list. This is a classic interview problem solved elegantly with a deque.

**Problem:** `nums = [3, 1, 5, 2, 7, 4, 6, 8]`, `k = 3`

```
Windows and their maximums:
  [3, 1, 5] → max = 5
  [1, 5, 2] → max = 5
  [5, 2, 7] → max = 7
  [2, 7, 4] → max = 7
  [7, 4, 6] → max = 7
  [4, 6, 8] → max = 8

Expected output: [5, 5, 7, 7, 7, 8]
```

**Brute-force approach:** For every window, scan k elements. Total: O(n × k).
For n=1,000,000, k=1,000: one **billion** operations.

**Deque approach:** O(n) regardless of k.

```python
from collections import deque

def sliding_window_max(nums, k):
    """
    Find the maximum in each sliding window of size k.
    Uses a deque of indices in decreasing order of their values.
    Time: O(n).  Space: O(k).
    """
    dq = deque()    # Stores indices; values at those indices are decreasing
    result = []

    for i, val in enumerate(nums):
        # Remove indices that have fallen outside the window
        while dq and dq[0] < i - k + 1:
            dq.popleft()

        # Remove indices whose values are smaller than current —
        # they can NEVER be the maximum while this element is in the window
        while dq and nums[dq[-1]] < val:
            dq.pop()

        dq.append(i)

        # Window is fully formed once i >= k-1
        if i >= k - 1:
            result.append(nums[dq[0]])    # Front always holds the index of max

    return result


nums = [3, 1, 5, 2, 7, 4, 6, 8]
k = 3
print(f"Numbers:  {nums}")
print(f"Window k: {k}")
print(f"Maximums: {sliding_window_max(nums, k)}")
```

**Output:**
```
Numbers:  [3, 1, 5, 2, 7, 4, 6, 8]
Window k: 3
Maximums: [5, 5, 7, 7, 7, 8]
```

**Trace for the first 4 steps:**

```
i=0, val=3:  dq=[], append 0    → dq=[0]       window not full
i=1, val=1:  1<3, just append 1 → dq=[0,1]     window not full
i=2, val=5:  5>1, pop 1; 5>3, pop 0; append 2 → dq=[2]    max=nums[2]=5
i=3, val=2:  2<5, append 3      → dq=[2,3]     max=nums[2]=5
i=4, val=7:  7>2, pop 3; 7>5, pop 2; append 4 → dq=[4]    max=nums[4]=7
```

Each element is pushed and popped at most once — total O(n).

### Pattern 2 — Palindrome Checker

A palindrome reads the same forward and backward. A deque lets you compare and remove from both ends simultaneously — no indexing, no slicing.

```python
from collections import deque

def is_palindrome(text):
    """
    Check if text is a palindrome ignoring spaces and case.
    Uses deque to compare from both ends simultaneously.
    """
    # Keep only letters and digits, convert to lowercase
    dq = deque(ch.lower() for ch in text if ch.isalnum())

    print(f"Checking: '{text}'")
    print(f"Cleaned:   {list(dq)}")

    while len(dq) > 1:
        left = dq.popleft()
        right = dq.pop()
        if left != right:
            print(f"  Mismatch: '{left}' ≠ '{right}' → NOT a palindrome\n")
            return False

    print(f"  All characters matched → IS a palindrome\n")
    return True


test_cases = [
    "racecar",
    "A man a plan a canal Panama",
    "hello",
    "Was it a car or a cat I saw",
    "Python",
    "Madam Im Adam",
]

for text in test_cases:
    is_palindrome(text)
```

**Output:**
```
Checking: 'racecar'
Cleaned:   ['r', 'a', 'c', 'e', 'c', 'a', 'r']
  All characters matched → IS a palindrome

Checking: 'A man a plan a canal Panama'
Cleaned:   ['a', 'm', 'a', 'n', 'a', 'p', 'l', 'a', 'n', 'a', 'c', 'a', 'n', 'a', 'l', 'p', 'a', 'n', 'a', 'm', 'a']
  All characters matched → IS a palindrome

Checking: 'hello'
Cleaned:   ['h', 'e', 'l', 'l', 'o']
  Mismatch: 'h' ≠ 'o' → NOT a palindrome

Checking: 'Was it a car or a cat I saw'
Cleaned:   ['w', 'a', 's', 'i', 't', 'a', 'c', 'a', 'r', 'o', 'r', 'a', 'c', 'a', 't', 'i', 's', 'a', 'w']
  All characters matched → IS a palindrome
```

### Pattern 3 — Browser History (Back and Forward)

A browser lets you go back to the previous page and forward to the next. This is a classic two-deque problem. When you visit a new page, the forward history is cleared.

```python
from collections import deque

class BrowserHistory:
    def __init__(self, homepage):
        self._back    = deque()           # Pages you can go back to
        self._forward = deque()           # Pages you can go forward to
        self._current = homepage
        print(f"  Opened browser at: {self._current}")

    def visit(self, url):
        """Visit a new page — clears forward history."""
        self._back.append(self._current)  # Save current to back stack
        self._forward.clear()             # New visit wipes forward history
        self._current = url
        print(f"  Visited: {self._current}  "
              f"[back:{len(self._back)} | fwd:{len(self._forward)}]")

    def back(self, steps=1):
        """Go back by `steps` pages."""
        for _ in range(steps):
            if not self._back:
                print("  ← Can't go back further")
                break
            self._forward.appendleft(self._current)
            self._current = self._back.pop()
        print(f"  ← Back to: {self._current}  "
              f"[back:{len(self._back)} | fwd:{len(self._forward)}]")

    def forward(self, steps=1):
        """Go forward by `steps` pages."""
        for _ in range(steps):
            if not self._forward:
                print("  → Can't go forward further")
                break
            self._back.append(self._current)
            self._current = self._forward.popleft()
        print(f"  → Forward to: {self._current}  "
              f"[back:{len(self._back)} | fwd:{len(self._forward)}]")

    def current(self):
        return self._current


print("=== Browser Session ===\n")
browser = BrowserHistory("google.com")
browser.visit("github.com")
browser.visit("stackoverflow.com")
browser.visit("python.org")

print()
browser.back()                      # python.org → stackoverflow.com
browser.back()                      # stackoverflow.com → github.com
browser.forward()                   # github.com → stackoverflow.com
browser.visit("docs.python.org")    # Visit new page — forward history cleared
browser.forward()                   # Nothing to go forward to
browser.back(2)                     # Go back 2 steps
```

**Output:**
```
=== Browser Session ===

  Opened browser at: google.com
  Visited: github.com         [back:1 | fwd:0]
  Visited: stackoverflow.com  [back:2 | fwd:0]
  Visited: python.org         [back:3 | fwd:0]

  ← Back to: stackoverflow.com  [back:2 | fwd:1]
  ← Back to: github.com         [back:1 | fwd:2]
  → Forward to: stackoverflow.com  [back:2 | fwd:1]
  Visited: docs.python.org     [back:3 | fwd:0]
  → Can't go forward further
  → Forward to: docs.python.org   [back:3 | fwd:0]
  ← Back to: github.com          [back:1 | fwd:2]
```

### Pattern 4 — Fixed-Size Activity Log with `maxlen`

A system keeps only the last N user actions. Older actions are automatically dropped as new ones arrive. With `maxlen`, this requires zero manual management.

```python
from collections import deque
from datetime import datetime

class ActivityLog:
    """Maintains a rolling log of the last `capacity` user actions."""

    def __init__(self, capacity=5):
        self._log = deque(maxlen=capacity)
        self._total_recorded = 0

    def log(self, user, action):
        timestamp = datetime.now().strftime("%H:%M:%S")
        entry = f"[{timestamp}] {user}: {action}"
        self._log.append(entry)
        self._total_recorded += 1

    def recent(self):
        return list(self._log)

    def stats(self):
        print(f"  Total actions recorded: {self._total_recorded}")
        print(f"  Actions in memory:      {len(self._log)} "
              f"(max {self._log.maxlen})")


log = ActivityLog(capacity=4)

actions = [
    ("Alice", "Login"),
    ("Bob",   "View dashboard"),
    ("Alice", "Edit profile"),
    ("Carol", "Upload file"),
    ("Bob",   "Logout"),          # ← Alice's Login will be dropped here
    ("Alice", "View reports"),
    ("Carol", "Download file"),
]

print("=== Logging Actions ===\n")
for user, action in actions:
    log.log(user, action)
    print(f"  Logged: {user} → {action}")

print()
print("=== Recent Activity (last 4) ===")
for entry in log.recent():
    print(f"  {entry}")

print()
log.stats()
```

**Output:**
```
=== Logging Actions ===

  Logged: Alice → Login
  Logged: Bob   → View dashboard
  Logged: Alice → Edit profile
  Logged: Carol → Upload file
  Logged: Bob   → Logout            ← Alice's Login dropped automatically
  Logged: Alice → View reports
  Logged: Carol → Download file

=== Recent Activity (last 4) ===
  [14:22:41] Bob:   Logout
  [14:22:41] Alice: View reports
  [14:22:41] Carol: Download file
  ... (4 most recent entries)

Total actions recorded: 7
Actions in memory:      4 (max 4)
```

7 events were logged. Only 4 live in memory. The deque manages the window automatically.

### Pattern 5 — Task Scheduler with Work Stealing

In multi-threaded systems, workers maintain their own task queues. When a worker finishes its tasks, it **steals** from the back of another worker's deque (so the victim worker loses its least-recently-added task rather than the one it is about to do next). This is called **work-stealing** and is used in Java's `ForkJoinPool`, Go's goroutine scheduler, and Python's `concurrent.futures`.

```python
from collections import deque
import random

class Worker:
    def __init__(self, name, tasks):
        self.name = name
        self.queue = deque(tasks)

    def work(self):
        """Process one task from the front."""
        if self.queue:
            task = self.queue.popleft()
            print(f"  {self.name} processed: {task}")
            return True
        return False

    def steal_from(self, other):
        """Steal one task from the BACK of another worker's queue."""
        if other.queue:
            stolen = other.queue.pop()    # Take from rear — O(1)
            self.queue.appendleft(stolen) # Add to our front — O(1)
            print(f"  {self.name} stole '{stolen}' from {other.name}")
            return True
        return False

    def has_work(self):
        return bool(self.queue)


# Create workers with uneven workloads
workers = [
    Worker("Worker-A", ["Task-1", "Task-2", "Task-3", "Task-4", "Task-5"]),
    Worker("Worker-B", ["Task-6"]),
    Worker("Worker-C", []),
]

print("=== Initial Workloads ===")
for w in workers:
    print(f"  {w.name}: {list(w.queue)}")

print("\n=== Processing ===")

# Worker-A processes two tasks
workers[0].work()
workers[0].work()

# Worker-B processes its only task and runs out
workers[1].work()

# Worker-C has nothing — steals from Worker-A (the busiest)
workers[2].steal_from(workers[0])
workers[2].work()

# Worker-B steals from Worker-A too
workers[1].steal_from(workers[0])
workers[1].work()

print("\n=== Final State ===")
for w in workers:
    print(f"  {w.name}: {list(w.queue)}")
```

**Output:**
```
=== Initial Workloads ===
  Worker-A: ['Task-1', 'Task-2', 'Task-3', 'Task-4', 'Task-5']
  Worker-B: ['Task-6']
  Worker-C: []

=== Processing ===
  Worker-A processed: Task-1
  Worker-A processed: Task-2
  Worker-B processed: Task-6
  Worker-C stole 'Task-5' from Worker-A
  Worker-C processed: Task-5
  Worker-B stole 'Task-4' from Worker-A
  Worker-B processed: Task-4

=== Final State ===
  Worker-A: ['Task-3']
  Worker-B: []
  Worker-C: []
```

Worker-A started with 5 tasks. The others stole from the rear — the task A was least likely to do next — leaving A with only its most imminent task. This is exactly how real work-stealing schedulers balance load.

### Pattern 6 — BFS with Deque (Revisited, Using Deque Directly)

Breadth-first search is the canonical use of a queue. When implemented with `deque`, `popleft()` gives O(1) dequeue — making BFS O(V + E) overall. A `list.pop(0)` would make it O(V² + E).

```python
from collections import deque

def bfs_shortest_path(graph, start, end):
    """
    Find the shortest path between start and end using BFS.
    Returns the path as a list of nodes, or None if no path exists.
    """
    if start == end:
        return [start]

    visited = {start}
    # Store (current_node, path_so_far)
    queue = deque([(start, [start])])

    while queue:
        node, path = queue.popleft()

        for neighbour in graph[node]:
            if neighbour == end:
                return path + [neighbour]
            if neighbour not in visited:
                visited.add(neighbour)
                queue.append((neighbour, path + [neighbour]))

    return None   # No path exists


# Social network: can Alice reach Frank through connections?
network = {
    "Alice":   ["Bob", "Carol"],
    "Bob":     ["Alice", "Dave", "Eve"],
    "Carol":   ["Alice", "Frank"],
    "Dave":    ["Bob"],
    "Eve":     ["Bob", "Frank"],
    "Frank":   ["Carol", "Eve"],
    "George":  [],              # Isolated node
}

queries = [
    ("Alice", "Frank"),
    ("Dave",  "Carol"),
    ("Alice", "George"),
]

print("=== Shortest Paths in Social Network ===\n")
for start, end in queries:
    path = bfs_shortest_path(network, start, end)
    if path:
        hops = len(path) - 1
        print(f"  {start} → {end}: {' → '.join(path)}  ({hops} hops)")
    else:
        print(f"  {start} → {end}: No connection found")
```

**Output:**
```
=== Shortest Paths in Social Network ===

  Alice → Frank: Alice → Carol → Frank  (2 hops)
  Dave  → Carol: Dave → Bob → Alice → Carol  (3 hops)
  Alice → George: No connection found
```

## `deque` vs `list` — When to Use Which

```
Use deque when:                          Use list when:
  ✓ You add/remove from BOTH ends          ✓ You need fast index access (list[i])
  ✓ You implement a queue or stack         ✓ You sort or slice frequently
  ✓ You need a bounded sliding window      ✓ You mostly append to the right
  ✓ BFS, palindrome check, rotate          ✓ Simple ordered collection
  ✓ Left-side operations in a loop         ✓ NumPy / math-heavy operations
```

**The one-liner rule:**

> If you ever write `list.pop(0)` or `list.insert(0, x)` in a loop — **replace it with a deque**.

## Common Mistakes Beginners Make

### Mistake 1 — Using `list.pop(0)` Instead of `deque.popleft()`

```python
# Wrong — O(n) per call — catastrophic in a loop
queue = [1, 2, 3, 4, 5]
while queue:
    item = queue.pop(0)    # Shifts ALL remaining elements every time
    process(item)

# Correct — O(1) per call
from collections import deque
queue = deque([1, 2, 3, 4, 5])
while queue:
    item = queue.popleft()    # Constant time always
    process(item)
```

For 10,000 items: `list.pop(0)` does ~50,000,000 shifts. `deque.popleft()` does ~10,000 operations.

---

### Mistake 2 — Forgetting `extendleft` Reverses Order

```python
from collections import deque

dq = deque([4, 5, 6])
dq.extendleft([1, 2, 3])

print(dq)    # deque([3, 2, 1, 4, 5, 6])
             # NOT  deque([1, 2, 3, 4, 5, 6]) !
```

If you want `[1, 2, 3, 4, 5, 6]`, either reverse the input or use `extend` from the right on a reversed existing deque:

```python
dq = deque([4, 5, 6])
dq.extendleft(reversed([1, 2, 3]))    # Reverse the input first
print(dq)    # deque([1, 2, 3, 4, 5, 6]) ✓
```

---

### Mistake 3 — Indexing Into the Middle of a Deque in a Hot Loop

```python
from collections import deque

dq = deque(range(100_000))

# Wrong — O(n) per access × n iterations = O(n²) total
total = 0
for i in range(len(dq)):
    total += dq[i]    # Each dq[i] traverses from the nearest end

# Correct — iterate directly
total = sum(dq)       # O(n) total — iterates block by block
```

Direct iteration over a deque is O(n). Random index access is O(n) per access. Never use `dq[i]` in a loop if you can iterate instead.

---

### Mistake 4 — Trying to Change `maxlen` After Creation

```python
from collections import deque

dq = deque(maxlen=5)
dq.extend([1, 2, 3, 4, 5])

dq.maxlen = 10    # AttributeError: attribute 'maxlen' is not writable
```

`maxlen` is fixed at creation. If you need a different size, create a new deque and copy the elements:

```python
new_dq = deque(dq, maxlen=10)    # Creates new deque from old one with new maxlen
```

---

### Mistake 5 — Treating a Bounded Deque Like a Fixed Buffer and Missing Silent Drops

```python
from collections import deque

log = deque(maxlen=3)
log.append("Event-1")
log.append("Event-2")
log.append("Event-3")
log.append("Event-4")    # "Event-1" is silently dropped — no warning, no error!

print(list(log))    # ['Event-2', 'Event-3', 'Event-4']
# "Event-1" is gone forever
```

The `maxlen` deque drops elements **silently**. If you need to know when an element was dropped, track `len(dq) == dq.maxlen` before appending:

```python
if len(log) == log.maxlen:
    print(f"  Warning: dropping oldest entry: {log[0]}")
log.append("Event-4")
```

---

### Mistake 6 — Popping from an Empty Deque

```python
from collections import deque

dq = deque()
dq.pop()        # IndexError: pop from an empty deque
dq.popleft()    # IndexError: pop from an empty deque
```

Always guard pops:

```python
# Option 1 — Check first
if dq:
    val = dq.pop()

# Option 2 — Handle the exception
try:
    val = dq.popleft()
except IndexError:
    val = None
```

### Mistake 7 — Confusing `rotate()` Direction

```python
from collections import deque

dq = deque([1, 2, 3, 4, 5])
dq.rotate(1)
print(dq)    # deque([5, 1, 2, 3, 4])  ← positive = rotate RIGHT (elements move right)

dq = deque([1, 2, 3, 4, 5])
dq.rotate(-1)
print(dq)    # deque([2, 3, 4, 5, 1])  ← negative = rotate LEFT (elements move left)
```

Memory device:
- **Positive n** → elements shift **right** → rightmost elements wrap to the left
- **Negative n** → elements shift **left** → leftmost elements wrap to the right

Think of it as the **viewpoint shifting**: `rotate(1)` is like turning a wheel clockwise — the top element comes from the right.

## The Complete `deque` Operations Reference

```python
from collections import deque

# Creation
dq = deque()                    # Empty deque
dq = deque(iterable)            # From any iterable
dq = deque(iterable, maxlen=n)  # Bounded — auto-drops on overflow

# Adding elements — O(1)
dq.append(x)                    # Add x to the RIGHT
dq.appendleft(x)                # Add x to the LEFT

# Removing elements — O(1)
dq.pop()                        # Remove and return rightmost; raises IndexError if empty
dq.popleft()                    # Remove and return leftmost;  raises IndexError if empty

# Adding multiple — O(k)
dq.extend(iterable)             # Add each item to the RIGHT in order
dq.extendleft(iterable)         # Add each item to the LEFT (result is REVERSED)

# Inspection — O(1) for ends, O(n) for middle
dq[0]                           # Peek left (front)
dq[-1]                          # Peek right (rear)
dq[i]                           # Access index i — avoid in hot loops
len(dq)                         # Number of elements — O(1)
dq.maxlen                       # Maximum size (None if unbounded)

# Searching — O(n)
dq.count(x)                     # Count occurrences of x
dq.index(x)                     # Index of first x; raises ValueError if absent

# Modifying — O(n)
dq.remove(x)                    # Remove first occurrence of x
dq.reverse()                    # Reverse in place
dq.rotate(n)                    # Rotate right by n (negative n = rotate left)

# Utility
dq.clear()                      # Remove all elements — O(n)
dq.copy()                       # Shallow copy — O(n)

# Iteration (always use this for full traversal — O(n))
for item in dq:
    process(item)
```

## What Comes After the Deque?

```
collections.deque
 │
 ├──► Queue implementation          (use deque: enqueue=append, dequeue=popleft)
 ├──► Stack implementation          (use deque: push=append, pop=pop)
 ├──► Sliding window algorithms     (maxlen or manual with popleft)
 ├──► BFS / level-order traversal   (deque as the queue — O(1) popleft)
 ├──► Palindrome checking           (popleft + pop from both ends)
 │
 ├──► Work-stealing schedulers      (steal from back, process from front)
 ├──► Browser history               (two deques: back and forward stacks)
 ├──► Undo/Redo with bounded depth  (maxlen caps history automatically)
 │
 └──► asyncio.Queue / threading     (thread-safe variants for concurrent code)
```

## Summary

| Concept | What It Means |
|---|---|
| Deque | Double-Ended Queue — add and remove from **both** ends |
| `append(x)` | Add to the right — O(1) |
| `appendleft(x)` | Add to the left — O(1) |
| `pop()` | Remove from the right — O(1) |
| `popleft()` | Remove from the left — O(1) |
| `extendleft` | Adds in reverse order — remember this |
| `rotate(n)` | Positive = right rotation, negative = left rotation |
| `maxlen` | Fixed capacity — auto-drops opposite end on overflow |
| `dq[i]` middle access | O(n) — traverse blocks from nearest end — avoid in loops |
| vs `list` | Use deque whenever left-end operations appear in a loop |
| vs `heapq` | deque has no priority — it's FIFO (or LIFO); heapq is priority-ordered |

The `deque` is not just a faster list. It is a fundamentally different contract: **constant time at both ends, in exchange for linear time in the middle**. Once you truly understand this trade-off, you will instinctively reach for `deque` every time you see a sliding window, a BFS, a history buffer, or any structure that grows and shrinks from both ends.

A list is a shelf. A deque is a conveyor belt — things flow in from one end, out from the other, and the belt never needs to stop to rearrange itself.
